# HIG: แถบและโครงหน้าต่างบน macOS

ใช้เมื่อ module ออกแบบ app บน Mac (หรือ desktop ที่ตั้งใจให้เหมือน Mac) อ้างเป็นเลขข้อ เช่น "HM7: ปุ่มบน toolbar ไม่มีใน menu bar"
Apple เรียกส่วนบนสุดของหน้าต่างว่า **frame** (title bar + toolbar อยู่รวมกัน) ส่วนเนื้อหาคือ **body** พื้นผิว Liquid Glass ใช้กับแถบและ sidebar ที่ลอยเหนือเนื้อหา ดู `hig-foundations.md`
ถ้าโปรเจกต์ไม่ใช่ app บน Mac (เช่น เว็บ, tablet) ให้ระบุว่า "ไม่เกี่ยวข้อง" ตามข้อ ไม่ใช่ "ผ่าน"

## โครงหน้าจอ Mac (บนลงล่าง)

| ส่วน | หน้าที่ | อยู่ที่ |
|---|---|---|
| Menu bar (ของระบบ) | คำสั่งทั้งหมดของ app, เรียนรู้ว่า app ทำอะไรได้ | ขอบบนจอ ไม่ใช่ในหน้าต่าง |
| Window frame: ปุ่มปิด/ย่อ/ขยาย + title | ย้าย/จัดการหน้าต่าง | ขอบบนหน้าต่าง |
| Toolbar | ชื่อ view, navigation (back/forward, แสดง/ซ่อน sidebar), actions, search | อยู่ใน frame ใต้หรือรวมกับ title bar |
| Sidebar | ไปยังส่วนหลักของ app | ซ้ายของ body (leading) |
| Content (split view: 1–3 pane) + inspector | เนื้อหาและรายละเอียด | กลาง/ขวา (trailing) |
| Bottom bar (ใช้น้อย) | ข้อมูลเล็ก ๆ ของเนื้อหา เช่น จำนวนรายการ | ขอบล่างหน้าต่าง |

## เกณฑ์ตรวจ

### Menu bar

| # | เกณฑ์ | ตัวอย่างที่ไม่ผ่าน |
|---|---|---|
| HM1 | เมนูเรียงตามมาตรฐาน: ชื่อ app → File → Edit → Format → View → (เมนูเฉพาะ app) → Window → Help แล้วแต่ละเมนูมีรายการตามแบบ (ดูตารางด้านล่าง) ไม่ใช้เมนูที่ไม่เกี่ยวข้อง แต่ต้องมี View และ Window เสมอแม้มีฟีเจอร์น้อย | ไม่มี Window menu ทั้งที่มีหน้าต่างเดียว, Settings ไปอยู่เมนู Edit |
| HM2 | แสดงรายการเมนูชุดเดิมเสมอ ถ้าใช้ไม่ได้ให้ทำให้จางลง ไม่ซ่อน ถ้าทุกรายการในเมนูใช้ไม่ได้ ตัวเมนูก็ยังเปิดดูได้ | รายการ Paste หายเมื่อไม่มีอะไรให้วาง |
| HM3 | คำสั่งเฉพาะ app ทุกตัวอยู่ในเมนูแม้จะมีปุ่มที่อื่นแล้ว (หาเจอง่าย มี shortcut ได้ ใช้กับ Full Keyboard Access ได้) | คำสั่งอยู่ในปุ่มลอยในหน้าอย่างเดียว |
| HM4 | ชื่อเมนูสั้น (คำเดียวดีที่สุด) ใช้ title-style capitalization ถ้าเกินหนึ่งคำ | ชื่อเมนูยาวเป็นประโยค |
| HM5 | ใช้ shortcut มาตรฐานของระบบตามหน้าที่เดิม (Command-C/V/X/Z/S/N/O/W/Q/P/F/A, Command-, = Settings, Command-. = ยกเลิก) ไม่เอาไปใช้ทำอย่างอื่น ตั้ง shortcut เองเฉพาะที่จำเป็น | Command-S ไปทำ "ส่งข้อมูล" |
| HM6 | รายการเมนู: ขึ้นต้นด้วยกริยา ใช้ ellipsis (…) เมื่อต้องรับข้อมูลเพิ่มก่อนทำ ไม่ใส่ a/an/the มีไอคอนทั้งกลุ่มหรือไม่มีเลย ใช้ไอคอนระบบสำหรับ Copy/Share/Delete จัดกลุ่มด้วยเส้นคั่น รายการที่ใช้บ่อยอยู่บน | "Save" ที่เปิด dialog ถามชื่อ แต่ไม่มี … |
| HM7 | รายการที่เปลี่ยนสถานะ (แสดง/ซ่อน) ใช้ชื่อที่ตรงสถานะปัจจุบัน (Show Toolbar ↔ Hide Toolbar) หรือใช้เครื่องหมายถูก submenu ใช้น้อย ลึกชั้นเดียว ไม่เกิน ~5 รายการ | ใช้ย่อหน้าแทน submenu |
| HM8 | รายการเมนูที่ซ่อนด้วย modifier (Option) ใช้เป็นทางลัดของงานขั้นสูงเท่านั้น ไม่ใช่ทางเดียวของงานนั้น | Minimize All เป็นทางเดียวที่ย่อทุกหน้าต่าง |

### เมนูมาตรฐาน (ใช้ตรวจ HM1)

| เมนู | รายการตามลำดับ |
|---|---|
| ชื่อ app (ตัวหนา) | About [ชื่อสั้น ≤16 ตัว ไม่ใส่เวอร์ชัน] (แยกกลุ่มเดี่ยว) → Settings… → รายการตั้งค่าเฉพาะ app → Services → Hide [app] → Hide Others → Show All → Quit [app] |
| File | New [ชนิดรายการ] → Open / Open Recent → Close (Close Tab) → Save → Duplicate (ดีกว่า Save As/Export) → Rename… → Move To… → Export As… → Revert To → Page Setup… → Print… (ถ้า app ไม่ใช้ไฟล์ จะเปลี่ยนชื่อหรือตัดทิ้งได้) |
| Edit | Undo/Redo (ระบุเป้า เช่น "Undo Typing") → Cut → Copy → Paste (+ Paste and Match Style) → Delete (ไม่ใช้ Erase/Clear) → Select All → Find → Spelling and Grammar → Substitutions → Transformations → Speech → Start Dictation → Emoji & Symbols |
| Format | Font · Text (ตัดทิ้งถ้า app ไม่มีข้อความจัดรูปแบบ) |
| View | Show/Hide Tab Bar → Show All Tabs → Show/Hide Toolbar → Customize Toolbar → Show/Hide Sidebar → Enter/Exit Full Screen |
| เมนูเฉพาะ app | อยู่ระหว่าง View กับ Window เรียงตามลำดับชั้นของ app และจากทั่วไปไปเฉพาะ |
| Window | Minimize → Zoom → Show Previous/Next Tab → Move Tab to New Window → Merge All Windows → Bring All to Front → รายชื่อหน้าต่างที่เปิด (เรียงตัวอักษร ไม่ใส่ panel) |
| Help | [ชื่อ app] Help → รายการเพิ่ม (ใส่น้อย คั่นด้วยเส้น) |

### Toolbar

| # | เกณฑ์ | ตัวอย่างที่ไม่ผ่าน |
|---|---|---|
| HM9 | ทุกปุ่มบน toolbar ต้องมีเป็นคำสั่งใน menu bar ด้วย (toolbar ถูกซ่อน/ปรับแต่งได้ จึงเป็นที่เดียวของคำสั่งไม่ได้) แต่ไม่ต้องเอาทุกคำสั่งในเมนูมาไว้ toolbar | ปุ่ม "ส่งออก" มีแต่บน toolbar |
| HM10 | เลือกรายการอย่างตั้งใจ ไม่แน่น ปุ่มต้องแยกออกและกดได้ทีละปุ่ม ให้ระบบจัดการ overflow เอง (ไม่ทำเมนู overflow เอง และไม่ออกแบบให้ล้นตั้งแต่ขนาดปกติ) ใช้เมนู More เมื่อจำเป็นจริง ใส่คำสั่งสำคัญน้อยไว้ในนั้น | ปุ่ม 12 ปุ่มจนหน้าต่างปกติก็ล้น |
| HM11 | 3 ตำแหน่ง: **leading** = ย้อน/แสดง-ซ่อน sidebar → ชื่อ view → เมนูเอกสาร (Duplicate, Rename, Move, Export); **center** = ปุ่มที่ใช้บ่อย (ปรับแต่งได้ ยุบเข้า overflow เมื่อหน้าต่างแคบ); **trailing** = ปุ่มสำคัญที่ต้องเห็นเสมอ, ปุ่มเปิด inspector, ช่อง search, เมนู More, และ action หลัก | ปุ่ม Done อยู่ตรงกลาง, ปุ่มสำคัญอยู่ในส่วนที่ยุบหายตอนหน้าต่างแคบ |
| HM12 | จัดกลุ่มตามหน้าที่และความถี่ ไม่เกิน ~3 กลุ่ม navigation และ Done/Close/Save แยกกลุ่มชัดเจน ปุ่มที่มีข้อความอยู่ติดปุ่มไอคอนต้องมีที่ว่างคั่น (ไม่ให้ดูเป็นปุ่มเดียว) | กลุ่ม 6 กลุ่มเรียงชิดกัน |
| HM13 | ปุ่มชัดความหมาย ใช้สัญลักษณ์ระบบ (SF Symbols) ไม่มีกรอบ เว้นแต่คำที่สัญลักษณ์สื่อไม่ได้ (เช่น Edit) ใช้ข้อความ ใช้ปุ่ม Back/Close มาตรฐาน ไม่ใช้ข้อความ "Back/Close" แทนสัญลักษณ์ | ปุ่มวงกลมมีเส้นขอบรอบ icon, ปุ่ม "Back" เป็นตัวหนังสือ |
| HM14 | action หลักของ view มีได้ 1 ปุ่ม ใช้สไตล์ prominent (เช่น Done/Submit) วางที่ trailing | สองปุ่ม prominent ในแถบเดียว |
| HM15 | ลดพื้นหลังและสีย้อมบน toolbar ให้สีของเนื้อหาเป็นตัวกำหนด ไม่ใช้สีใกล้เคียงกับพื้นหลังเนื้อหาในป้ายปุ่ม ถ้าเนื้อหาสีสด ใช้ toolbar โทนเดียวตามค่าปริยาย | toolbar ทาสีแบรนด์ทึบ |
| HM16 | title หน้าต่าง: บอกว่าอยู่ view ไหน สั้น (< 15 ตัวอักษร) ไม่ใช้ชื่อ app เป็น title เว้นว่างได้ถ้าซ้ำซ้อน | title คือชื่อ app |
| HM17 | ใช้ component มาตรฐานบน toolbar (มุมโค้งสอดคล้องกับมุมแถบ ถ้าทำเองต้องโค้งแบบเดียวกัน) ช่วยให้ซ่อน toolbar ได้ชั่วคราว (โหมดไม่รบกวน) และมีวิธีเรียกกลับที่ไว้ใจได้ | toolbar ซ่อนแล้วเรียกกลับไม่ได้ |

### Window และ bottom bar

| # | เกณฑ์ | ตัวอย่างที่ไม่ผ่าน |
|---|---|---|
| HM18 | ใช้กรอบหน้าต่าง/ปุ่มควบคุมของระบบ ไม่ทำกรอบเอง ถ้าเลียนแบบแล้วไม่ตรงทุกจุด app จะดู "พัง" | ปุ่มปิด/ย่อ/ขยายวาดเอง |
| HM19 | หน้าต่างปรับขนาดได้ลื่น (ย่อ ขยาย ย้าย เต็มจอ) เปิดหน้าต่างใหม่เมื่อจำเป็น (เช่น เขียนเมลใหม่ดูเมลเดิมไปพร้อมกัน) ไม่เปิดเป็นปริยาย แต่ให้เลือกเปิดใน window ใหม่ได้ ใช้คำว่า "window" ในข้อความผู้ใช้ | ทุกการคลิกเปิดหน้าต่างใหม่ |
| HM20 | แยกหน้าต่างหลัก (นำทาง+เนื้อหา) กับหน้าต่างเสริม (งานเดียว ไม่นำทางไปส่วนอื่น มีปุ่มปิด) และแสดงสถานะ main/key/inactive ต่างกัน (ใช้ component มาตรฐานจะทำให้เอง) | หน้าต่าง inactive ดูเหมือน active |
| HM21 | ห้ามวางข้อมูลหรือ action สำคัญที่ขอบล่างหน้าต่าง (bottom bar/status bar/ล่าง sidebar) เพราะผู้ใช้มักลากหน้าต่างจนขอบล่างอยู่นอกจอ ถ้าจะใช้ ให้ใส่ข้อมูลเล็กที่เกี่ยวกับเนื้อหาเท่านั้น (เช่น จำนวนรายการ) | ปุ่ม "บันทึก" อยู่ล่างสุดของหน้าต่าง |
| HM22 | เนื้อหาไม่ชนบริเวณกล้อง (notch) ที่ขอบบนหน้าต่าง | ปุ่มอยู่หลังกล้องตอนเต็มจอ |

### Sidebar, split view, panel, tab view, sheet

| # | เกณฑ์ | ตัวอย่างที่ไม่ผ่าน |
|---|---|---|
| HM23 | sidebar แสดงลำดับชั้นไม่เกิน 2 ระดับ ลึกกว่านั้นใช้ split view เพิ่มรายการกลาง ใช้ disclosure คุมความยาว ป้ายกลุ่มสั้น | sidebar ซ้อน 4 ชั้น |
| HM24 | ผู้ใช้ซ่อน/แสดง sidebar ได้ (ปุ่มใน toolbar หรือคำสั่ง Show/Hide Sidebar ในเมนู View) ไม่ซ่อนเป็นค่าปริยาย (ต้องค้นพบได้) พิจารณาซ่อนอัตโนมัติเมื่อหน้าต่างแคบ | ซ่อน sidebar เป็นค่าตั้งต้นโดยไม่มีปุ่มเรียก |
| HM25 | ไอคอน sidebar ใช้สี accent ที่ผู้ใช้ตั้งในระบบ ใช้สีคงที่เฉพาะที่ต้องเน้นความหมาย (ใช้น้อย) ไอคอนเป็น SF Symbols หรือ vector ไม่ใช่ bitmap | ไอคอน sidebar ทุกตัวคนละสีสด |
| HM26 | split view: ไฮไลต์รายการที่เลือกในแต่ละ pane ต่อเนื่องถึง detail ตั้งขนาด pane ต่ำสุด/สูงสุดให้ divider ไม่หาย ใช้ divider บาง (1 pt) มีหลายวิธีเรียก pane ที่ซ่อนกลับ | pane ย่อจนเห็น divider ไม่ออก |
| HM27 | panel (หน้าต่างเสริมลอย, inspector): ชื่อสั้นเป็นคำนามและมี title bar ใช้ตัวปรับง่าย ๆ (slider, stepper) ไม่ให้พิมพ์/เลือกหลายขั้น แสดงตามเมื่อ app active ซ่อนเมื่อ inactive ไม่อยู่ในรายชื่อเมนู Window ไม่มีปุ่มย่อ HUD ใช้เฉพาะแอปสื่อ | panel มีฟอร์มพิมพ์หลายช่อง |
| HM28 | tab view: ใช้กับพื้นที่เนื้อหาที่เกี่ยวข้องกัน แต่ละ pane ปิดตัวเอง ป้ายเป็นคำนาม title-style ไม่เกิน 6 แท็บ ไม่ใช้ pop-up button แทน | 9 แท็บในแถวเดียว |
| HM29 | sheet: ขนาดตั้งต้นพอดีเนื้อหา ผู้ใช้ยังสลับไปหน้าต่างอื่นของ app ได้ ถ้าต้องกรอกซ้ำ ๆ แล้วดูผล ใช้ panel แทน | sheet ที่ต้องเปิดปิดซ้ำทุกครั้งที่ลอง |
| HM30 | ปุ่มบน Mac: push button เป็นปุ่มมาตรฐาน (ใส่ … เมื่อเปิดหน้าต่าง/มุมมองอื่น) square button อยู่ใน view ไม่ใช่ใน toolbar/status bar และมีแต่สัญลักษณ์ ปุ่ม help วงกลม ? ตัวเดียวต่อหน้าต่าง อยู่ใน view ไม่ใช่ toolbar | ปุ่ม help 2 ปุ่มในหน้าต่างเดียว |

## หลักของ Mac ที่ใช้ตัดสินทั้งหน้าจอ (Designing for macOS)
- จอใหญ่ → แสดงเนื้อหามาก ซ้อนชั้นน้อย ใช้ modal น้อย แต่ความหนาแน่นยังอ่านสบาย
- ผู้ใช้ปรับหน้าต่างได้ (ย่อ ขยาย ซ่อน ย้าย เต็มจอ) และทำงานหลายแอปพร้อมกัน
- ใช้ได้หลายอุปกรณ์ป้อนข้อมูล (เมาส์/trackpad แม่น, คีย์บอร์ด) → รองรับ shortcut และการใช้คีย์บอร์ดล้วน
- รองรับการปรับแต่ง (toolbar, หน้าต่าง, สี/ฟอนต์)

## วิธีใช้
- **Feasibility:** เช็กว่า requirement ต้องการคำสั่งที่ไม่มีที่อยู่ในเมนูมาตรฐาน (ต้องเปิดเมนูเฉพาะ app) หรือต้องการ action ที่ซ่อนได้ (HM9, HM21) และ flow ที่ต้องเปิดหน้าต่างใหม่ (HM19)
- **Designer:** ระบุข้อ HM ที่ใช้ใน design ถ้าเบี่ยงจากข้อใด เขียนเหตุผล ทำ artboard ของ menu bar หรือรายการคำสั่งคู่กับ toolbar เพื่อให้ตรวจ HM9 ได้
- **Reviewer:** ให้ผล ผ่าน/ไม่ผ่าน/ไม่เกี่ยวข้อง รายข้อ HM1-HM30 ในหัวข้อ Review พร้อมจุดที่ต้องแก้
