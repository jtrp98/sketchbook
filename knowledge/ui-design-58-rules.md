# 58 กฎ UI ที่ใช้ได้จริง (UI1–UI58)

บทความจัด 58 ข้อเป็น 8 หมวด ("Elegance Formula"): Empathy · Layout · Essentialism · Guidance · Aesthetics · Novelty · Consistency · Engagement ตัวบทความเป็นหลักกว้าง ๆ แทบไม่มีตัวเลข ไฟล์นี้เติม**เกณฑ์ที่วัดได้**จากมาตรฐาน/งานวิจัยที่ค้นเพิ่ม ใช้ตรวจเป็นรายข้อ เช่น "UI29: ข้อความรอง contrast 3.8:1"
ใช้คู่กับ `usability-heuristics.md`, `hig*.md`, `universal-design.md`, `wcag-aa.md` ค่าหน้าตาของโปรเจกต์ใช้ตาม `projects/<ชื่อ>/brand.md` ข้อที่ขัดกัน brand ชนะเรื่องค่า ไฟล์นี้ชนะเรื่องเหตุผล/ข้อห้าม

## ระดับหลักฐาน (ใช้ตัดสินว่าข้อไหนตีตกได้)
- **A** มาตรฐานหรือผลวิจัยที่อ้างได้ (WCAG, NN/g, งานวิจัยทบทวนโดยผู้เชี่ยวชาญ) → ใช้เป็นเกณฑ์ผ่าน/ไม่ผ่านได้
- **B** แนวปฏิบัติที่ design system/แหล่งหลายแห่งตรงกัน → ใช้เป็นเกณฑ์ตรวจได้ แต่ถ้าเบี่ยงให้เขียนเหตุผลใน design
- **C** heuristic หรือความเห็นของผู้เขียน → เป็นแนวทางออกแบบ **ห้ามใช้เป็นเหตุตีตกระดับสูง**
- **ทีม** ข้อเสนอของทีมที่ตีความจากหลักฐานข้างต้น (ไม่ใช่มาตรฐานภายนอก) ต้องให้ผู้ใช้ยืนยันก่อนบังคับ

## Empathy (UI1–UI4)

| # | กฎ | เกณฑ์ตรวจ | ระดับ |
|---|---|---|---|
| UI1 | คำนึงถึงวัฒนธรรมและสังคม | ตรวจภาพ สัญลักษณ์ ภาษา ตัวอย่างว่าเหมาะกับบริบทผู้ใช้จริง (โรงเรียนไทย) ค้นไม่พบหลักฐานข้ามวัฒนธรรมเรื่องความหมายของสี จึง**ห้ามอ้างความหมายของสีเป็นเหตุผลออกแบบ** ให้ทดสอบกับผู้ใช้แทน และไม่ใช้สีอย่างเดียวสื่อความหมาย | C |
| UI2 | เข้าใจอุตสาหกรรมและบริบทการใช้ | ระบุใน design ว่าใช้ที่ไหน บนอุปกรณ์อะไร ระยะมอง มือถือ/เมาส์ เวลาต่อครั้ง | C |
| UI3 | ออกแบบตามกลุ่มประชากร | ระบุกลุ่ม/ช่วงอายุก่อนออกแบบ NN/g แยกงานวิจัยเด็ก 3–12 ปี และวัยรุ่นเป็นคนละชุด ไม่ออกแบบ "เด็ก" รวมกัน (แนวแบ่งยอดนิยม 3–5 / 6–8 / 9–12) ไม่พบค่า target size เฉพาะเด็กที่อ้างได้ → ใช้ขั้นต่ำของ platform แล้วเผื่อใหญ่ขึ้นและทดสอบกับเด็กจริง (งานวิจัยชี้ว่าเด็กแตะแม่นน้อยกว่าและแปรปรวนกว่าผู้ใหญ่ โดยเฉพาะเป้าเล็กราว ≤ 4 mm) | A (แนวทาง) / ค่าตัวเลข: ไม่มี |
| UI4 | ปรับตามความคุ้นเทคโนโลยี | ถ้ามีหลายกลุ่ม (นักเรียน/ครู) ตรวจแยกกลุ่ม: ภาษา ความลึกของ flow ทางลัด | C |

## Layout (UI5–UI10)

| # | กฎ | เกณฑ์ตรวจ | ระดับ |
|---|---|---|---|
| UI5 | ใช้พื้นที่ว่าง | ใช้ spacing scale ฐาน 4/8 (4, 8, 12, 16, 20, 24, 32, 48, …) ภายใน component ใช้ฐาน 4 ระหว่าง component ใช้ฐาน 8 · ระยะในกลุ่มเดียวกันน้อยกว่าระยะระหว่างกลุ่ม (ค่าตั้งต้นที่คนใช้: ประมาณ 1:2 ต้องทดสอบกับ layout จริง) · ถ้าระยะไม่พอแยกกลุ่ม ให้ใส่กรอบ/พื้นหลัง/เส้นแทน | B (ฐาน 4/8) · C (1:2) |
| UI6 | Golden ratio / rule of thirds | ใช้เป็นตัวช่วยเริ่มต้นได้ **ห้ามใช้ตีตก** งานทดลอง (91 คน) พบผลหนุนเฉพาะโครง wireframe ของมือถือ ไม่พบในเว็บ และมีผู้วิจารณ์ว่าสัดส่วนที่คนชอบเพี้ยนจาก φ ไม่พบการทดสอบ rule of thirds กับผลลัพธ์ผู้ใช้ | C |
| UI7 | ลำดับความสำคัญด้วยขนาด/สี/ระยะ | แต่ละหน้าอ่านลำดับได้ด้วย squint test (เบลอตาแล้วยังเห็นว่าอะไรเด่น ซึ่ง NN/g ใช้) type scale ใช้อัตราส่วนคงที่: 1.125 (แน่น), 1.2 (กะทัดรัด), 1.25 (ทั่วไป) ปัดเป็นผลคูณของ 4 | B |
| UI8 | ใช้ grid | กำหนดจำนวนคอลัมน์ ร่อง margin ต่อขนาดจอใน brand ของโปรเจกต์ ใช้ฐาน 8 ตาม UI5 ไม่มีค่าสากลที่อ้างได้ | B |
| UI9 | จุดโฟกัสชัดเจน | ทุกหน้าจอมีจุดเด่นหลักเดียวที่ผู้ใช้ควรเห็นก่อน ตรวจด้วย squint test | B |
| UI10 | จังหวะนำสายตา | ซ้ำรูปแบบ/ระยะสม่ำเสมอ · F-pattern (NN/g, eyetracking) เกิดกับหน้าที่ข้อความหนาแน่น และ NN/g ถือว่าเป็นผลลบ จึงออกแบบให้ไม่เกิด (หัวข้อ/ย่อหน้าขึ้นต้นด้วยคำสำคัญ) · **Z-pattern ไม่พบข้อมูล eyetracking จาก NN/g** มีแต่บล็อก อย่าอ้างเป็นเหตุผล | A (F) · C (Z) |

## Essentialism (UI11–UI16)

| # | กฎ | เกณฑ์ตรวจ | ระดับ |
|---|---|---|---|
| UI11 | ลดอย่างตั้งใจ | ทุกองค์ประกอบตอบได้ว่าช่วยงานใด ตัดที่ตอบไม่ได้ | C |
| UI12 | จัดระเบียบให้ดูน้อยลง | จัดกลุ่ม ใช้แท็บ/เมนู (แท็บบน Mac ไม่เกิน 6 ดู `hig-macos-bars.md` HM28) | B |
| UI13 | อย่าให้ผู้ใช้ต้องคิด | ใช้ pattern/ตำแหน่งที่คุ้น (ตรง H2, H4, H6) | B |
| UI14 | ออกแบบน้อยที่สุดเท่าที่ทำงานได้ | จำกัดสี ฟอนต์ กราฟิกตาม brand (ตรง H8) | B |
| UI15 | แบ่งงานใหญ่เป็นขั้น | ใช้ตัวบอกขั้น (step indicator) เมื่อ flow เป็นเส้นตรง ≥ 3 ขั้น (Carbon) หรือ ≥ 4 ขั้น (Visa) และไม่มีเงื่อนไขแตกสาย · ไม่ใช้เมื่อทำลำดับใดก็ได้ หรือขั้นหนักเบาต่างกันมาก (ให้ความคาดหวังผิด) · เริ่มจากรูปแบบ "ขั้นที่ X จาก Y" · ถ้าน้อยกว่านั้น ทดสอบก่อนว่าไม่ต้องมี | B |
| UI16 | เวลาที่ประหยัดรู้สึกเหมือนเรียบง่าย | เกณฑ์ตอบสนอง (NN/g): ≤ 0.1 วิ รู้สึกทันที ไม่ต้องมี feedback นอกจากผลลัพธ์ · ~1 วิ สังเกตได้แต่ความคิดไม่ขาด · ถึง 10 วิ คือเพดานความสนใจ งานเกิน 10 วิต้องมีแถบ % ที่เสร็จ **และ**ปุ่มยกเลิกชัดเจน · ตัวเลขเป็นแนวทาง ไม่ใช่เส้นตัดตายตัว ใช้ default ที่ฉลาด/autocomplete ลดการพิมพ์ | A |

## Guidance (UI17–UI22)

| # | กฎ | เกณฑ์ตรวจ | ระดับ |
|---|---|---|---|
| UI17 | onboarding ที่ดึงดูด | สั้น ผูกกับงานแรกที่ผู้ใช้ต้องทำ ข้ามได้ ไม่บังคับดูซ้ำ (ตัวเลขยอดนิยม 3–5 ทิป เป็นของผู้ขายเครื่องมือ ไม่ใช่งานวิจัย ใช้เป็นแนวเท่านั้น) | C |
| UI18 | flow ที่เป็นธรรมชาติ | ลำดับตามงานจริง/mental model ของผู้ใช้ (ตรง H2, H6) | B |
| UI19 | คำใบ้ตามบริบท | tooltip ใช้กับข้อมูลที่**ไม่จำเป็น**ต่อการทำงาน ข้อมูลสำคัญต้องเห็นเสมอโดยไม่ต้องโต้ตอบ · ปุ่มไอคอนทุกปุ่มมี tooltip · ไม่พูดซ้ำป้ายเดิม · ห้ามใช้แทน label/ข้อความ error · ข้อสังเกตของทีม: อุปกรณ์สัมผัสไม่มี hover ต้องมีวิธีเปิดอีกทาง | B |
| UI20 | เปิดเผยทีละชั้น | 2 ชั้นตามแนว Nielsen: หน้าแรกมีฟีเจอร์ที่ตอบงานส่วนใหญ่ ชั้นสองมีป้ายชัด · มือใหม่เรียนเร็ว/พลาดน้อย ผู้เชี่ยวชาญเสีย 1 คลิก · sidebar บน Mac ไม่เกิน 2 ระดับ (HM23) | A/B |
| UI21 | กระตุ้นให้เกิดการกระทำ | action หลักหนึ่งอย่างต่อ view เด่น เข้าถึงง่าย (ดู UI9) | B |
| UI22 | feedback ทุกการกระทำ | ทุกการกดมีผลตอบกลับภายใน 0.1 วิ (UI16) ถ้าเสียงเป็น feedback ต้องมีภาพคู่เสมอ (และสั่น ถ้า platform รองรับ) | A/B |

## Aesthetics (UI23–UI40)

### ตัวอักษร (UI23–UI28)

| # | กฎ | เกณฑ์ตรวจ | ระดับ |
|---|---|---|---|
| UI23 | ลำดับตัวอักษร | ใช้ type scale คงที่ (UI7) ไม่ใช้น้ำหนักบาง (Light/Thin) กับตัวเล็ก | B |
| UI24 | อ่านง่ายก่อน | ขนาดขั้นต่ำตาม platform/brand · **ภาษาไทย:** สระและวรรณยุกต์ซ้อนได้ถึง 2 ชั้นบนและ 1 ชั้นล่าง จึงต้องมี line-height สูงกว่าละติน ทดสอบพบตัดขอบที่ 1.1 และปลอดภัยเริ่มราว 1.6 (แหล่งไม่เป็นทางการ ต้องทดสอบกับไฟล์ฟอนต์จริงและข้อความไทยที่วรรณยุกต์สูงสุด) · ไทยไม่มีช่องว่างระหว่างคำ ต้องให้ระบบตัดคำแบบพจนานุกรม และห้ามตัดให้วรรณยุกต์/สระแยกจากตัวฐาน · ตัวมีหัว/ไม่มีหัว: งานวิจัยจุฬาฯ (Typotheque, ผู้ใหญ่) พบว่าความเร็วอ่านไม่ต่างกัน แต่ทุกวัยรับรู้ว่าแบบมีหัวอ่านง่ายกว่า และผู้อ่านอายุน้อยชอบแบบไม่มีหัวที่ขนาดเล็ก **ไม่พบงานวิจัยในเด็ก** จึงต้องทดสอบกับเด็กจริงถ้าเลือกฟอนต์ใหม่ | A/B (ตัวเลข 1.6 = C) |
| UI25 | สะท้อนอารมณ์แบรนด์ | ฟอนต์ตกแต่งใช้เฉพาะหัวข้อ เนื้อหาใช้ฟอนต์กลาง ๆ | C |
| UI26 | จับคู่ฟอนต์ | ถ้าใช้หลายตระกูล ต้องเข้ากันและแยกหน้าที่ (หัวข้อ/เนื้อหา) | C |
| UI27 | จำกัดชนิดและสไตล์ | กำหนดเพดานตระกูล/น้ำหนักใน brand (HIG: ลดชนิดฟอนต์ให้น้อยที่สุด) | B |
| UI28 | ระยะบรรทัด/ตัวอักษร | ย่อหน้าละติน: line-height 1.5–1.6 และยาวบรรทัด 50–75 ตัวอักษร (Baymard; Ruder แนะ 50–60) · **ต้องไม่พังเมื่อผู้ใช้ตั้งค่า WCAG 1.4.12:** line-height 1.5×, ย่อหน้า 2×, letter-spacing 0.12×, word-spacing 0.16× ของขนาดอักษร · ภาษาไทยนับตัวอักษรต่อบรรทัดเทียบเลขละตินไม่ได้ ใช้เป็นแนวคร่าว ๆ และดูที่การอ่านจริง · ข้อสังเกตของทีม (ยังไม่ยืนยัน): ไม่ใช้ letter-spacing ติดลบกับตัวไทยเพราะสระ/วรรณยุกต์อาจทับกัน ทดสอบก่อน | A/B |

### สี (UI29–UI34)

| # | กฎ | เกณฑ์ตรวจ | ระดับ |
|---|---|---|---|
| UI29 | contrast | WCAG 1.4.3 (AA): ข้อความปกติ ≥ 4.5:1, ข้อความใหญ่ (≥ 18 pt หรือ ≥ 14 pt ตัวหนา) ≥ 3:1 · WCAG 1.4.11 (AA): ส่วนประกอบ UI/กราฟิกที่จำเป็นต่อความเข้าใจ (ขอบช่องกรอก focus indicator) ≥ 3:1 กับสีข้างเคียง · ขนาดพื้นที่กดขั้นต่ำ WCAG 2.2 (2.5.8, AA) = 24×24 CSS px · ค่าที่ตรวจต้องคำนวณจากสีจริงใน design | A |
| UI30 | พาเล็ตสีสม่ำเสมอ | ใช้เฉพาะ token ใน brand สีหนึ่งสีสื่อความหมายเดียว (HF4) | B |
| UI31 | กฎ 60-30-10 | 60% พื้นกลาง ๆ, 30% สีรอง (ข้อความ/องค์ประกอบหลัก), 10% accent (ปุ่มหลัก/จุดสำคัญ) · เป็น heuristic ไม่ใช่ค่ามาตรฐาน ที่สำคัญคือ accent ต้องหายาก ไม่ใช่เลขตรง · เริ่มออกแบบเป็นขาวดำก่อนเพื่อให้ hierarchy มาก่อนสี · สีสถานะ (แดง/เขียว ฯลฯ) ไม่นับในสัดส่วน **ห้ามตีตกด้วยเลขนี้** | C |
| UI32 | จิตวิทยาและความหมายของสี | ไม่พบหลักฐานข้ามวัฒนธรรมจากการค้นหา → ห้ามอ้างอารมณ์ของสีเป็นเหตุผลออกแบบ ให้ทดสอบกับผู้ใช้เป้าหมาย | C (ไม่ยืนยัน) |
| UI33 | สีสถานะ | แดง/เขียวมีความหมายสถานะได้ แต่**ต้องมีข้อความและไอคอนคู่เสมอ** ผู้ชายราว 8% และผู้หญิงราว 0.5% บกพร่องการมองสีแดง-เขียว (ตัวเลขแหล่งทั่วไป ไม่ใช่งานวิจัยต้นฉบับ) · ให้สีสองสถานะต่างกันที่ความสว่างด้วย ไม่ใช่แค่เฉด | A/B |
| UI34 | สีนำการกระทำ | ใช้สี accent เฉพาะสิ่งที่กดได้/ควรกด ไม่ใช้สีเดียวกับข้อความที่กดไม่ได้ (HF4) | B |

### ภาพและการเคลื่อนไหว (UI35–UI40)

| # | กฎ | เกณฑ์ตรวจ | ระดับ |
|---|---|---|---|
| UI35 | เนื้อหามาก่อนการตกแต่ง | ลดกรอบ/เงา/พื้นหลังที่ไม่ช่วยงาน (ตรง HIG: ชั้นเนื้อหาเด่น) | C |

## Engagement (UI53–UI58) — **ระวังเป็นพิเศษเมื่อผู้ใช้เป็นเด็ก**

| # | กฎ | เกณฑ์ตรวจ | ระดับ |
|---|---|---|---|
| UI53 | gamification (แต้ม เหรียญ อันดับ) | งานวิจัย/ทบทวน (เช่น Frontiers 2024) ชี้ว่ารางวัลภายนอกอาจลดแรงจูงใจภายในและทำให้เรียนผิวเผิน ผลของอันดับสาธารณะ: หนุนคนที่เก่งอยู่แล้ว กดดันกลุ่มล่าง ยังมีมุมมองที่โต้แย้งทฤษฎีฐาน (SDT) จึงถือเป็นแนวโน้ม ไม่ใช่กฎตายตัว · **เกณฑ์ของทีม:** ผูกรางวัลกับเนื้อหาที่เรียน ไม่ใช่การกดบ่อย · สนับสนุนความรู้สึกเก่ง (competence) ให้ผู้เรียนเลือกเองได้ (autonomy) และได้ทำร่วมกับผู้อื่น (relatedness) · ไม่ใช้อันดับสาธารณะเปรียบเทียบเด็กคนอื่น ใช้เทียบกับตัวเองก่อนหน้า | A (ความเสี่ยง) / ทีม (เกณฑ์) |
| UI54 | personalization | ให้เลือกได้ในสิ่งที่ไม่กระทบงานหลัก ไม่ซ่อนฟังก์ชันที่ต้องใช้ ผู้ใช้เด็กตัวเลือกน้อยพอ (ลดภาระการตัดสินใจ) | C |
| UI55 | storytelling | ใช้เมื่อผูกกับบทเรียนและไม่ขัดงาน ข้ามได้ | C |
| UI56 | แสดงความก้าวหน้า | ตรง SDT เรื่อง competence แสดงเทียบกับความก้าวหน้าของตัวเอง ใช้กฎเดียวกับ UI15 | B |
| UI57 | รางวัลที่คาดเดาไม่ได้ (variable reward) | **ห้ามใช้กับผู้ใช้เด็ก** งานวิจัยและร่างกฎหมายต่างประเทศจัดตารางรางวัลแบบสุ่มเป็นกลไกดึงความสนใจ/แบบหลอก (dark pattern) และเด็กยังคุมตัวเองได้น้อย (ตัวเลข "80% ของแอปเด็กยอดนิยมมีกลไกชักจูง" เป็นข้อมูลมือสอง ต้องตรวจต้นฉบับก่อนอ้าง) · ใช้ได้เฉพาะรางวัลที่ทำนายได้ ผูกกับความสำเร็จจริงของงาน | A (ความเสี่ยง) / ทีม (ข้อห้าม) |
| UI58 | ฟีเจอร์สังคม (แชร์ แข่ง) | ความเสี่ยงเรื่องความเป็นส่วนตัวของเด็ก (ยังไม่ได้ค้นกฎหมายไทย ต้องตรวจก่อนออกแบบ) · เกณฑ์ของทีม: ต้องเลือกเปิดเอง (opt-in) ไม่แสดงชื่อ/รูปจริง ไม่แข่งอันดับสาธารณะ ครูควบคุมได้ | C / ทีม |

## วิธีใช้
- **Feasibility:** ตรวจว่า requirement ไม่เรียกหาข้อห้ามของผู้ใช้เด็ก (UI53 อันดับสาธารณะ, UI57, UI58) และมีค่าเกณฑ์เวลาตอบสนอง/ขนาดงานที่ใหญ่เกิน 10 วิ (UI16) รายงานเป็นช่องโหว่ ไม่แก้ requirement เอง
- **Designer:** ระบุข้อ UI ที่ใช้และข้อที่เบี่ยงพร้อมเหตุผลในหัวข้อ Design ใช้ค่าตัวเลขตามตาราง ถ้า brand กำหนดค่าเข้มกว่าให้ใช้ของ brand
- **Reviewer:** ให้ผล ผ่าน/ไม่ผ่าน/ไม่เกี่ยวข้อง รายหมวด และรายข้อที่ระดับ A/B เท่านั้นที่ตีตกเป็น "สูง/กลาง" ได้ ข้อระดับ C ให้เขียนเป็นข้อเสนอแนะ

## ระดับความรุนแรงเมื่อไม่ผ่าน
- **สูง:** UI57, UI58 (เมื่อผู้ใช้เป็นเด็ก), UI29 และ UI33 ที่ทำให้อ่าน/แยกสถานะไม่ได้, UI16 งานเกิน 10 วิไม่มี progress/ยกเลิก
- **กลาง:** UI15, UI19, UI20, UI24, UI28, UI38 (ไม่รองรับ reduced motion), UI53
- **ต่ำ:** ข้อระดับ C ที่เหลือ
