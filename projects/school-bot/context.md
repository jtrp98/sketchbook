# School Bot: บริบทร่วมของโปรเจกต์

ใช้ร่วมทุก module อ่านเมื่อต้องรู้ภาพรวม ผู้ใช้ ขอบเขต การตัดสินใจร่วม ข้อจำกัด ความเสี่ยง · รายละเอียดเฉพาะ module อยู่ใน `modules/<module>/` · **sketchbook เป็นแหล่งความจริงแล้ว** (โฟลเดอร์ระบบเก่าเก็บเป็นประวัติ ไม่ต้องเปิด) · แผนที่ ID เดิม → ไฟล์ใหม่: `archive/2026-10-21_legacy-map.md`

## ป้ายหลักฐาน (ใช้ทุกไฟล์ที่นำเข้ามา)

| ป้าย | ความหมาย | ใช้เป็นข้อยุติได้ไหม |
|---|---|---|
| Confirmed | ผู้ใช้ยืนยัน | ได้ ผูกพัน |
| Observed (EV-##) | เห็นจากหลักฐาน/frame (อ่านโค้ดหรือดูภาพ ไม่ได้รัน) | เป็นหลักฐาน ไม่ใช่การทดสอบ |
| Inferred | อนุมานจากหลักฐาน | ต้องตรวจก่อนใช้ |
| Unknown | ยังไม่ทราบ | ไม่ได้ ถามหรือออกแบบเผื่อ |
| Proposed | ข้อเสนอที่ยังไม่อนุมัติ | ใช้เป็นสมมติฐานออกแบบเท่านั้น |
| Delegated | มอบ role/ทีมตัดสินเอง | ตัดสินได้แต่ต้องบันทึกเหตุผล |

ลำดับความน่าเชื่อถือเมื่อขัดกัน: คำยืนยันล่าสุดของผู้ใช้ → ไฟล์ใน sketchbook ฉบับปัจจุบัน → หลักฐาน (EV) → โน้ตเก่าบน canvas → การอนุมาน
ห้ามยกระดับข้อกล่าวอ้าง: อ่านโค้ด/ดูภาพ ≠ ทดสอบแล้ว · ออกแบบแล้ว ≠ ผ่านการตรวจ · ผ่านการตรวจ ≠ ทดสอบกับผู้ใช้จริง

## ผลิตภัณฑ์

**School Bot Studio** (DEC-01): โปรแกรมติดตั้งบน Windows และ Mac สอน coding และหุ่นยนต์ให้นักเรียน **ป.1–6** (ทุกชั้นใช้ UI เดียวกัน) ของโรงเรียนที่เป็นลูกค้า **SchoolBright** · ปัญหาที่แก้: โปรแกรมเดิม (Zide คุม servo, Mixly ต่อบล็อก) ออกแบบสำหรับผู้ใช้ทั่วไป ซับซ้อนเกินไปสำหรับเด็กประถม

| ส่วนในโปรแกรม | คืออะไร | module |
|---|---|---|
| โครงแอป | installer · แถบหน้าต่าง · login · หน้าหลัก · ตั้งค่า/ภาษา · มาสคอต | `app-shell` |
| งานของฉัน | บันทึกงานบน cloud · export .ini · กู้คืนสำรอง · sync | `my-work` |
| Quiz Game (เมนู "บทเรียน") | แผนที่หน่วยและด่านแนว Duolingo ครอบคลุม AI พื้นฐาน บอร์ด โค้ด และการควบคุมแขนกล | `quiz` |
| Arm Lab | สอนท่าแขนกล 6 ข้อต่อ (S0–S5) แล้วเล่นเป็นลำดับ หุ่น Raspberry Pi ผ่าน USB · แขนบนจอไม่ขยับ · โหมดครู (ตั้งค่าขั้นสูงแบบ Zide) · รีดีไซน์จาก Zide | `arm-lab` |
| Block Lab | ต่อบล็อกสั่งบอร์ด **Arduino Uno** บอร์ดเดียว · ดูโค้ด Arduino C++ อ่านอย่างเดียว · ตัวจำลองบอร์ดต่อสายอิสระ · stage มาสคอต · แผงข้อความจากบอร์ด · ไม่มีภารกิจ · รีดีไซน์จาก Mixly | `block-lab` |
| เว็บครู (แยกต่างหาก ผ่านเบราว์เซอร์) | ครูดูความคืบหน้าและคะแนน Quiz รายเทอม/รายปี จัดตามห้อง · ตั้งค่า · แก้ปัญหาหุ่น | `teacher-web` |

แอปเป็นพื้นที่ให้นักเรียนใช้งานอย่างเดียว ยกเว้น **โหมดครูใน Arm Lab** (ครูโรงเรียนเดียวกัน login ด้วยบัญชีตัวเอง) · ครูจัดการอื่น ๆ ผ่านเว็บ (DEC-14)

## ขอบเขต MVP และสิ่งที่ไม่รวม

รวม: installer + แถบหน้าต่างของโปรแกรมเอง (ปิด ย่อ ซ่อน) · login (โรงเรียน → username → password) · หน้าหลัก (sidebar 4 เมนู, เรียนต่อ, งานล่าสุด, ความสำเร็จ) · Quiz · Arm Lab · Block Lab · การบันทึก cloud + export .ini + กู้คืนสำรอง · เว็บครู · มาสคอต 10 ท่า

**ไม่รวม (Confirmed):**
- จำลอง/แอนิเมชันแขนกลบนจอใน Arm Lab: แขนไม่ขยับไม่ว่ากรณีใด (CON-07)
- บอร์ดอื่นนอกจาก Arduino Uno ใน Block Lab (CON-02)
- UI แยกตามชั้น: ป.1–6 ใช้ UI เดียว · ไม่มีตัวช่วยเพิ่มสำหรับ ป.1–3 เช่น เสียงอ่าน/โหมดแยก (DEC-19 · ความเสี่ยงที่ยอมรับ RSK-04)
- ระบบหลังบ้านและหน้าจอของ SchoolBright เอง (ใช้ผ่านการเชื่อมต่อเท่านั้น)
- การจัดการของครูในแอปนักเรียน นอกจากการตั้งค่าขั้นสูงของแขน
- **Block Lab สั่งแขนกล (FR-21): เลื่อนไปรอบถัดไป** ไม่มีหมวดบล็อกแขนกลใน MVP (DEC-17, CR-02)
- ภารกิจ/โจทย์ใน Block Lab: MVP เป็นพื้นที่เล่นอิสระ บทเรียนอยู่ใน Quiz เท่านั้น (DEC-25)
- คะแนนจาก Arm Lab และ Block Lab: ไม่มี ไม่ส่งเข้า SchoolBright เว็บครูไม่แสดงงาน Lab (DEC-18)

## ลำดับความสำคัญด้าน UX (เรียงตามความสำคัญ)
1. **ปลอดภัยเมื่อสั่งหุ่น:** หยุดได้เสมอ เตือนก่อนขยับเสี่ยง เห็นสถานะชัดเจน (NFR-04)
2. **เด็ก ป.1–6 ใช้เองได้ด้วย UI เดียวกัน:** ภาษาง่าย ไอคอนคู่ข้อความ เป้าสัมผัสใหญ่ (NFR-02, DEC-19)
3. **ดูเหมือนเกมแต่คลีน:** contrast สูงแนว Duolingo ดูแลรักษาได้โดยไม่ต้องพึ่งนักวาด (NFR-01)
4. **สอดคล้องกันทั้ง 3 ส่วนและเว็บครู**

## เกณฑ์ตรวจเฉพาะโปรเจกต์ (highlighter ใช้เสริม knowledge/)

เกณฑ์ WCAG 2.2 AA ทั่วไป ใช้ `knowledge/` · ข้อด้านล่างคือที่ **เฉพาะ School Bot** หรือที่ระบบเก่าตรวจแล้วพบปัญหาจริง

**ผู้ใช้เด็กประถม (Proposed ให้ทีมยืนยัน)**
- เป้าสัมผัสหลักไม่เล็กกว่า 44×44 px · ไม่พึ่ง hover (แท็บเล็ตไม่มี hover) · ไอคอนสำคัญมีข้อความกำกับ
- ข้อความสั้น ภาษาง่าย หนึ่งเรื่องต่อหนึ่งประโยค ศัพท์เทคนิคมีคำอธิบายหรือไอคอน
- ผิดพลาดแล้วไม่โทษเด็ก มีทางแก้ เลิกทำได้ · ไม่มีแรงกดดันด้านเวลาโดยไม่จำเป็น · ไม่มีแอนิเมชันกะพริบ/วนซ้ำเป็นค่าเริ่มต้น (WCAG 2.3.1 กะพริบเกิน 3 ครั้ง/วินาทีไม่ได้)
- รางวัล/เกมมีเป้าหมายการเรียนรู้ ไม่ใช่กลไกดึงให้ใช้นาน · ข้อมูลส่วนบุคคลของเด็กแสดงเท่าที่จำเป็น ไม่ให้เพื่อนเห็นโดยไม่ตั้งใจ
- ข้อความ hint/toast ที่เด็ก ป.1 ต้องอ่าน อยู่อย่างน้อย ~5 วินาที หรือจนกว่าจะกดอย่างอื่น (AUD-F08)

**การลาก** (block programming, เรียงลำดับ, ต่อสายในตัวจำลอง): ต้องมีทางเลือกที่ไม่ต้องลาก เช่น แตะเลือกแล้วแตะวาง หรือเมนูย้าย (WCAG 2.5.7 AA)

**ความปลอดภัยเมื่อสั่ง hardware**
- ปุ่มหยุดทั้งหมดเห็นตลอด **ไม่ถูกบังด้วยสิ่งใด (รวม dialog/popover/tooltip/แถบหน้าต่าง)** และอยู่ห่างจากปุ่มสั่งให้ทำงาน · ชั้นสูงสุดคือ `z-stop`
- ก่อนการเคลื่อนไหวเสี่ยง (ไกล เร็ว วนไม่หยุด) มีเตือนหรือยืนยัน · สถานะเชื่อมต่อและ "กำลังขยับ" ชัดเจน · เมื่อหลุด ปุ่มสั่งถูกปิด · ค่าเกินขีดจำกัดถูกป้องกันหรือเตือน
- **ห้ามเขียนว่า "หุ่นหยุดแล้ว" / "บอร์ดหยุดแล้ว" จนกว่า firmware/dev ยืนยัน** (DEV-Q15, DEV-Q16)

**ความรุนแรงในรายงานเดิม (ระวัง "M" สองความหมาย):**
- ฝั่ง Auditor (review): **C** = ผู้ใช้ทำงานหลักไม่สำเร็จ / ขัด requirement / ไม่ผ่าน WCAG ระดับ A จุดสำคัญ / เสี่ยงความปลอดภัย (ตัวอย่าง "ปุ่มหยุดหาไม่เจอหรือกดไม่ติด") · **M = Major** ไม่ผ่าน AA, ทำผู้ใช้สับสน/ช้าลงชัดเจน, ไม่สอดคล้อง design system จุดที่เห็นชัด · **m** = ขัดเกลา (ระยะ ถ้อยคำ ความสม่ำเสมอ) · ผล: มี C = RETURN · มีแต่ M/m ที่ Designer แก้ได้ = PASS WITH FIXES
- ฝั่ง Architect (feasibility ARC-I##): C = Critical · **M = Material** (ถ้า Designer เดาแล้ว dev ต้องรื้อ หรือผู้ใช้ต้องปฏิเสธงาน) · m = Minor
- ใน sketchbook review ใช้ สูง / กลาง / ต่ำ (C→สูง, M→กลาง, m→ต่ำ) ตาม CLAUDE.md
- ข้อที่ตรวจในงานออกแบบไม่ได้ ส่งให้ dev ตรวจซ้ำ (ลำดับ focus, focus trap ใน dialog, screen reader/role=status, ขยายตัวอักษร 200% และ 3 ภาษา, `lang` ของ root ตามภาษา UI, ฝังฟอนต์ IBM Plex ไม่พึ่ง Google Fonts)

## ที่มาตั้งต้น (brief v1 ของผู้ใช้ ที่ฉบับปัจจุบันตัดทอน)
- SchoolBright คือ product บริหารจัดการโรงเรียน โรงเรียนลูกค้ามี account, มีคะแนนที่ต้องกรอก, มีวิชาที่ต้องเรียน · School Bot Studio เป็นของเสริมที่ส่งคะแนนกลับ
- login แรกเริ่มใช้ "ID นักเรียน" → เปลี่ยนเป็นโรงเรียน + username + password (CHG-02)
- frame เดิมเคยวางแผนไอคอนล้วนและเสียงอ่านสำหรับ ป.1–3 (โน้ตบน canvas) ผู้ใช้ตัดสินไม่ทำ (DEC-19) · ค่าเริ่มต้นเดิมของ OQ-14 คือ "ไอคอนกับข้อความทุกปุ่มหลัก + ภาษาง่าย" (ยังใช้เป็นแนวทาง)
- Block Lab สั่งแขนกล (FR-21): คำถามที่ยังไม่ตอบตอนเลื่อนรอบ: จะแปลงโค้ดสั่งแขนผ่าน Uno หรือส่งตรงไป Raspberry Pi · ลำดับเดิมคือ Should · ต้องกลับมาตอบเมื่อเปิดรอบถัดไป

## กฎ UX ที่ตัดสินแล้วระหว่างออกแบบรอบแรก (ใช้ร่วม)
- ห้ามสื่อความหมายด้วยสีอย่างเดียว: ทุกสถานะมีไอคอน + ข้อความ · ปุ่มที่ใช้ไม่ได้ใช้ `aria-disabled` + ข้อความบอกเหตุผล ไม่ใช่แค่หน้าตาจาง (D-03) · ปุ่มที่ดูใช้ได้แต่ไม่ทำงานเป็นข้อบกพร่อง (AUD-F07)
- ข้อความ error ทุกตัวบอกวิธีแก้ ภาษาเด็ก มี**รหัส error** กำกับ (ตัวอย่าง E-CLOUD, E-USB, E-NOREPLY, E-BUSY, T-EMPTY, T-AUTH, T-ROLE, T-SCHOOL, T-OFFLINE) · ครั้งที่ 2 เป็นเช็กลิสต์ + รหัส
- ทุก dialog เว้นแถบล่าง 76px เพื่อไม่บังปุ่มหยุด · ปุ่ม ⋯ ขนาด 44px เห็นตลอด (แท็บเล็ตไม่มี hover) · เลื่อนเฉพาะแผงรายการ ไม่เลื่อนทั้งหน้า (D-15)
- ลบงานใช้ toast + เลิกทำ ไม่มี pop-up ยืนยัน (FRM-03 ที่ผู้ใช้อนุมัติ) · สร้างงานใหม่ทำได้เฉพาะในหน้างานของแต่ละโปรแกรม ไม่มีปุ่มสร้างบนหน้าหลัก (CR-06/07)
- สถานะบันทึกขึ้นคลาวด์แสดงที่แถบหน้าต่างที่เดียว · ชิปอุปกรณ์บนแถบหน้าต่างแสดงเฉพาะใน lab (Block = Uno, Arm = ชื่อหุ่น)
- ข้อความตัวอย่างวิธีหยุดทางกายภาพใช้ "ถอดสายไฟ adapter ของหุ่น" (ตาราง SCREEN_INVENTORY เดิมเขียน "ปิดสวิตช์/ถอดไฟหุ่น" ต้องรวมเป็นถ้อยคำเดียว)
- ข้อความบล็อก Stage ตอนส่งลง Uno: "บล็อกตัวละครทำงานเฉพาะในจอ" (ไม่ใช่ error)
- นักเรียนลืมรหัส: "บอกครูให้ช่วยรีเซ็ต" (Proposed) · ครูลืมรหัส: ไปที่ SchoolBright

## บทเรียน Claude Design canvas จากระบบเก่า (RSK-08)
สาเหตุที่แก้หัวข้อเดียวกิน token สูง: canvas เก็บทุกเวอร์ชัน (หน้าแขนกลมี 76 ไฟล์) และไฟล์ frame ใหญ่ (MainV6A 540 KB) · แนวทางที่ใช้ได้ผล:
1. canvas ที่ใช้งานเก็บเฉพาะฉบับปัจจุบัน เวอร์ชันเก่าย้ายไป artifact `ARCHIVE — <ชื่อเดิม>` · เป้า ≤ ~15 frame หลักต่อ canvas
2. 1 หน้าจอ = 1 frame · สถานะต่าง ๆ ใช้ Tweaks/prop แทนการ duplicate frame · แยกชิ้นส่วนที่ใช้ร่วมเป็นไฟล์ย่อย (`dc-import`)
