# School Bot — Quiz Pattern Library (v0.2)

คู่มือรูปแบบ quiz ที่ใช้ซ้ำได้ สรุปจากโค้ดจริงใน `src/game/` (Unit 3, Unit 2 คาบ 1–2)
อ่านคู่กับ `learning-game-design-library.md` (ที่มาของ pattern จากใบงาน/แผนสอน)

---

## 1. โครงสร้างระบบ

```
types.ts          schema ของบทเรียน (Lesson → Segment[])
framework.tsx     Button, Card, Icon, ProgressTrack, FeedbackBar
mechanics.tsx     Explore, Compare, Match, Sort, Reflect, Hunt
mechanics-unit2   Pipeline, Predict, RoleSplit
DreamRobot.tsx    Robot builder (ไม่คิดคะแนน)
GameShell.tsx     หน้าเริ่ม → เล่น → สรุปผล, คำใบ้, retry, stats, โหมดสอบ
lesson-*.ts       เนื้อหาเท่านั้น (ไม่มี UI)
App.tsx           ตัวเลือกบทเรียน
```

**หลัก:** บทเรียนใหม่ = เขียนไฟล์ `lesson-*.ts` + เพิ่มใน `LESSONS` ของ `App.tsx`
สร้างกลไกใหม่เฉพาะเมื่อกลไกเดิมวัดจุดประสงค์นั้นไม่ได้

## 2. สิ่งที่ต้องคงเดิมทุก quiz (Interaction consistency)

| ส่วน | กติกา |
|---|---|
| Flow | หน้าเริ่ม (เป้าหมาย + โหมดฝึก/โหมดสอบ) → ภารกิจ 1..n → หน้าสรุปผล |
| Header ภารกิจ | ป้าย "ภารกิจ n" สีฟ้า + ชื่อ + คำสั่ง 1 ประโยค |
| School Bot Tips! | กล่องเส้นประสีส้ม, 1 ประโยค, ใช้แก้ความเข้าใจผิดหลักของภารกิจ |
| การเลือก | แตะการ์ดก่อน → แตะเป้าหมาย (ทุกกลไก) ไม่บังคับลากวาง |
| Feedback | แถบเดียวด้านบน: correct / incorrect / incomplete / hint / info |
| ถูก | สีเขียว + ✓ + **บอกเหตุผล** (ไม่ใช่แค่ "ถูก") |
| ผิด | สั่น + สีส้มแดง + คำใบ้ชี้ไปที่ลักษณะสำคัญ ไม่เฉลย ให้ลองใหม่ได้ |
| ไปต่อ | ปุ่ม "ข้อต่อไป / ไปต่อ" ขวาล่าง กดได้เมื่อทำข้อนั้นสำเร็จ |
| ตัวนับ | "ข้อที่ x / n" หรือ "คู่ที่ x / n" ซ้ายบนของพื้นที่โจทย์ |
| สี | ส้ม = AI/เน้น, ฟ้า = ข้อมูล/Robot/ระบบ, เขียว = ถูก/ผลลัพธ์, ส้มแดง = ผิด, เหลือง = คำใบ้ |
| สัญลักษณ์ | ใช้รูปร่าง + สีคู่กันเสมอ ไม่สื่อด้วยสีอย่างเดียว |
| ขนาดปุ่ม | สูงอย่างน้อย 44–56 px (เด็ก ป.1 ใช้นิ้ว) |

## 3. คลังกลไก (Mechanics)

| Mechanic | ชื่อเรียก | ทักษะที่วัด | การโต้ตอบ | คิดคะแนน | ใช้แล้วใน | ความเสี่ยงซ้ำ |
|---|---|---|---|---|---|---|
| `explore` | สำรวจ | เปิดเรื่อง เชื่อมชีวิตจริง | แตะการ์ดเปิดดู | ไม่ | U3 | ต่ำ |
| `compare` | เลือก 1 จาก 2 | แยกลักษณะสำคัญจากคู่ที่ต่างกันจุดเดียว | แตะ 1 การ์ด | ใช่ | U3, U2A, U2B | **สูง** — ใช้ ≤1 ภารกิจ/บท |
| `match` | จับคู่ | เชื่อมสถานการณ์กับประเภท/ความสามารถ | แตะการ์ด → แตะกล่อง (หรือลาก) | ใช่ | U3 | กลาง |
| `sort` | จำแนกลงกล่อง | จัดกลุ่ม 2–4 กลุ่ม (+ เหตุผล) | แตะการ์ด → แตะกล่อง → (เลือกเหตุผล) | ใช่ | U3, U2B | กลาง |
| `hunt` | หาในฉาก | สังเกตในบริบทจริง | แตะจุดในภาพฉาก | ใช่ | U3 | **สูง** — ใช้นาน ๆ ครั้ง |
| `pipeline` | เรียง/เติม/ซ่อมลำดับ | ลำดับขั้นตอน, หาจุดผิด | แตะการ์ดใส่ช่อง 1→3 | ใช่ | U2A | ต่ำ |
| `predict` | ทายผล (กล่อง AI / ตัวอย่าง) | ใช้กฎ หรือหาแบบแผนจากตัวอย่าง | แตะกลุ่มปลายทาง | ใช่ | U2A | ต่ำ |
| `roles` | แยกบทบาท | แยกหน้าที่ในระบบเดียว | เลือก A/B ทีละขั้น | ใช่ | U2B | ต่ำ |
| `reflect` | สะท้อนคิด | เชื่อมกับตัวเอง | เลือกได้หลายข้อ | ไม่ | U3 | ต่ำ |
| `robot` | สร้างผลงาน | ออกแบบสร้างสรรค์ | ประกอบชิ้นส่วน + วาด | ไม่ | U3 | ต่ำ |

### 3.1 รายละเอียดแต่ละกลไก

**compare** — `rounds[]: { a, b, aiSide, why, unsureHint, question? }`, `badge?`, `wrongText?`
- ใช้เมื่อ: ต้องการให้เห็น "ตัวแปรเดียวที่ต่าง" (เช่น พูด vs กดปุ่ม, มีตัว vs ไม่มีตัว)
- ระวัง: ให้ทั้ง 2 การ์ดมีผลลัพธ์คล้ายกัน ไม่งั้นเด็กเดาจากผลลัพธ์
- มีปุ่ม "ไม่แน่ใจ" → คำใบ้ (โหมดสอบ: ข้อความกลาง ๆ)

**sort** — `bins[]: { id, label, icon, color? }`, `items[]: { binId, why, wrongHint?, reasons?: [ถูก, ผิด] }`
- 2 กล่อง: AI / ไม่ใช่ AI · 4 กล่อง: Robot / AI / Both / Neither
- `reasons` = ขั้น "เพราะอะไร?" หลังวางถูก นับเป็น **bonus** แยก (ไม่รวม %)
- ต้องมี non-example ที่ดูน่าเชื่อเสมอ (เช่น พัดลม: ใช้ไฟฟ้าแต่ไม่ใช่ AI)

**pipeline** — `rounds[]` 3 แบบ ใช้ `steps: [data, ai, out]`
- `build`: แตะเรียงช่อง 1→3 (ง่าย)
- `fill`: มีช่องว่าง 1 ช่อง เลือกจาก `options` (กลาง) — ตัวลวงควรเป็น "ผลลัพธ์" หรือ "อุปกรณ์" เพื่อตรวจว่าแยกข้อมูลออกได้
- `fix`: แสดงลำดับผิด (`shown`) ให้แตะการ์ดที่ต้องมาก่อน (ยาก) — ถามแบบมีคำตอบเดียว
- ใช้ต่อได้กับ: Input → Process → Output, Sensor → คิด → Motor, ขั้นตอนอัลกอริทึม 3 ขั้น

**predict** — `rounds[]: { rule?, inputs?, groups[], probe, answer, why, wrongHint }`
- มี `rule` = โหมด **กล่อง AI**: แสดง ข้อมูล → กล่อง AI (โจทย์) → ผลลัพธ์?
- ไม่มี `rule` + มี `groups[].examples` = โหมด **เรียนรู้จากตัวอย่าง**
- ใช้ `ShapeCard { shape, color, size? }` (วงกลม/สี่เหลี่ยม/สามเหลี่ยม × ส้ม/ฟ้า/เขียว × ใหญ่/เล็ก)
- กฎสำคัญ: ทุกข้อต้องมี **ลักษณะชี้ขาดเพียง 1 อย่าง** ลักษณะอื่นต้องกระจายทั้งสองกลุ่ม

**roles** — `scenario`, `steps[]: { role: 'ai' | 'robot', why, wrongHint }`
- ทำทีละขั้นตามลำดับ (ขั้นถัดไปปลดล็อกเมื่อขั้นก่อนถูก)
- ใช้ต่อได้กับ: Sensor vs Motor, คน vs เครื่อง, ข้อมูล vs ผลลัพธ์

## 4. คะแนน, retry, โหมด

| | โหมดฝึก | โหมดสอบ (สำหรับครู) |
|---|---|---|
| คำใบ้ "ช่วยหน่อย" | มี (ไล่ระดับตาม `hints[]`) | ปิด |
| "ไม่แน่ใจ" | ให้คำใบ้ | ข้อความกลาง ๆ ไม่ใบ้ |
| ผิดแล้วลองใหม่ | ได้ | ได้ แต่นับเป็นคำตอบผิด |
| เริ่มภารกิจใหม่ | ได้ | ไม่มีปุ่ม |
| สรุปผล | ลองใหม่ x · คำใบ้ y ต่อภารกิจ | % = ถูก ÷ (ถูก + ผิด) ในกลไกที่คิดคะแนน + เหตุผลถูกครั้งแรก |
| เล่นซ้ำรายภารกิจ | ได้จากหน้าสรุป | ได้จากหน้าสรุป |

การนับ: 1 ข้อที่ทำสำเร็จ = `onCorrect` 1 ครั้ง · ทุกครั้งที่ตอบผิด = `onMistake` 1 ครั้ง
(`pipeline` แบบ build นับถูก 1 ครั้งเมื่อครบ 3 ช่อง)

## 5. สูตรออกแบบ 1 quiz (50 นาที)

**ขนาด:** 3–4 ภารกิจ · ~10 ข้อคะแนน · ~1–1.5 นาที/ข้อ · เวลาในแอป 15–16 นาที

**ลำดับความยาก:** ภารกิจแรกง่าย (compare) → กลางเป็นกลไกหลักของบท → ท้ายเป็นข้อที่ต้องให้เหตุผล/ใช้กับข้อมูลใหม่

**ตัวอย่างการแบ่งเวลา**

| ขั้น | นาที |
|---|---:|
| ทบทวน + ตั้งเป้าหมาย | 4–5 |
| ครูอธิบาย / กิจกรรมจริง | 8–15 |
| รอบฝึกในแอป (โหมดฝึก, สาธิตบนจอ) | 4 |
| Quiz โหมดสอบ | 15–16 |
| ทบทวนข้อที่ผิด (เล่นซ้ำรายภารกิจ) | 6 |
| สรุป / Think & Pair / exit ticket | 4–8 |
| **รวม** | **50** |

**การผสมกลไกในคู่บทเรียนติดกัน:** กลไกหลักห้ามซ้ำกัน · ใช้ `compare` ได้ไม่เกิน 1 ภารกิจต่อบท · หลีกเลี่ยงการใช้ `hunt` สองบทติดกัน

ตัวอย่างที่ทำแล้ว:
- U3 AI ใกล้ตัว: explore → compare → match → hunt → robot → reflect
- U2A กล่อง AI: compare → **pipeline** → predict (กล่อง AI) → predict (ตัวอย่าง)
- U2B Robot หรือ AI: compare → **sort 4 กล่อง + เหตุผล** → roles

## 6. Checklist ก่อนเขียนเนื้อหา

**ความถูกต้อง**
- [ ] ทุก segment มี `objective` ที่ยกมาจากแผนสอน (ระบุรหัสตัวชี้วัดถ้ามี)
- [ ] ข้อเท็จจริงและเฉลยมาจากแหล่งที่มา ถ้าคิดเองให้ใส่คอมเมนต์ `[R]` และให้ครูยืนยัน

**ความตรงของการวัด**
- [ ] มีคำตอบที่ถูกเพียงคำตอบเดียว
- [ ] ตัวลวงดูน่าเชื่อ (เป็นความเข้าใจผิดจริง ไม่ใช่ตัวเลือกไร้สาระ)
- [ ] ภาพหรือไอคอนไม่บอกใบ้คำตอบ (เช่น ไอคอน robot ต้องมีทั้งในข้อที่มีและไม่มี AI)
- [ ] ข้อความสั้น อ่านง่ายระดับ ป.1 (≤ 1 บรรทัดต่อการ์ด) ครูอ่านออกเสียงได้
- [ ] `why` อธิบายเหตุผล · `wrongHint` ชี้ไปที่ลักษณะสำคัญโดยไม่เฉลย

**ความครอบคลุม**
- [ ] จุดประสงค์สำคัญทุกข้อมีอย่างน้อย 1 ข้อคะแนน
- [ ] ไม่ถามซ้ำจุดง่ายจุดเดียวหลายข้อ

## 7. เพิ่มกลไกใหม่

1. เพิ่ม type ใน `types.ts` และใส่ใน union `Segment`
2. เขียน component รับ `MechanicProps<T>` ต้องเรียก `feedback`, `onCorrect`, `onMistake`, `onComplete` และ `onBonus` (ถ้ามีคะแนนเสริม)
3. ลงทะเบียนใน `MECHANICS` (และ `SCORED` ถ้าคิดคะแนน) ใน `GameShell.tsx`
4. ใช้ `Button` / `Icon` / ตัวแปรสีใน `index.css` เท่านั้น ห้ามตั้งค่าสีเอง
5. อัปเดตตารางในข้อ 3 ของไฟล์นี้

## 8. แนวคิดที่ยังไม่สร้าง (backlog)
- **รอบฝึกแยก**: 1–2 ข้อไม่คิดคะแนนก่อนเข้าโหมดสอบ (ตอนนี้ใช้โหมดฝึกทั้งเกมแทน)
- **เสียงพูด (ไมค์)**: กล่อง AI สั่งด้วยเสียง, "AI ฟังไม่ชัด!" — ห้ามใช้เป็นคะแนนหลัก, ต้องมีปุ่มแตะสำรอง, ไม่เก็บไฟล์เสียง
- **เสียงอ่านโจทย์** สำหรับเด็กที่ยังอ่านไม่คล่อง
- **บันทึกผลถาวร / รายงานครูรายคน** (ตอนนี้ไม่มี backend)
