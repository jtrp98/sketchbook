# Block Lab · Feasibility R18: แถบหมวดบล็อก (รวมตรวจ R1 หมวด + §ตารางหมวด)

## ฟังก์ชัน + กล่องเฟือง ⚙ (ruler 2026-10-28 รอบ 2 · หลัง OQ165/OQ170/OQ180/OQ181 · D1 §1.8 v326) · แทนข้อ 5 และส่วน §Function/hat ตัวที่ 3/X29 ด้านล่าง

**ผล: ทำได้มีเงื่อนไข · ไม่มี OQ ที่ block `approved`** (เปิด OQ182–OQ186 ทุกข้อมีค่า Proposed · OQ182 และ OQ185 ควรตอบก่อน handoff/dev) · อ่านเอกสาร + เทียบซอร์ส Mixly (`blocks.js` `generators.js`) เท่านั้น ไม่ได้ render · ไม่มีไฟล์ `variables.js` ของ Mixly → รายการชนิดจริงเทียบไม่ได้ (DEV-Q) · OQ170 (ก) hat หลายตัว/ชื่อห้ามซ้ำ ปิดแล้ว (X29 ปิด) · ใช้ WCAG 2.2 AA (ยังไม่มี components.md ของทีม)

**ข้อเท็จจริงจาก Mixly ที่ใช้ตัดสิน:** (ก) ซ่อนปาก (allow statements ออก) = เก็บ stack ไว้ `statementConnection_` แล้วคืนตอนติ๊กกลับ → ของเราตรง (ข) ชื่อค่าว่าง: validator ปฏิเสธ (คืนชื่อเดิม) ไม่ใช่ตั้ง "ค่า<n>" (ค) ช่องของ call จับด้วย `paramIds_` (id คงที่ ไม่ใช่ชื่อ) → สลับ/เปลี่ยนชื่อไม่ทำให้ค่าในช่องสลับตัว (ง) Mixly มี 2 hat (`defnoreturn`/`defreturn`) + `RETURN` input ล่าง hat + `ifreturn` ภายใน ของเรารวมเป็น dropdown ชนิดคืน (จ) เอาค่าที่รับออก = บล็อกในช่อง call หลุดไปลอยใน workspace (ไม่หาย) · ของเรา**ไม่มีบล็อกลอย** → จะหายถ้าไม่ออกแบบ (ดูข้อ 5)

## ขนาดแถบ (R12 · พื้นที่ 1440×856 · ราง 96 สูง 720 ตาม D1)
- รายการละ ~58px (เป้า 44px + ไอคอน + ชื่อ ≥16px · 3 ภาษา +40%) · หัวกลุ่มละ ~28px
- **ขณะไม่ได้เลือก stage:** 15 แถว + 3 หัวกลุ่ม ≈ 954px · **เลือก stage:** 16 แถว + 4 หัวกลุ่ม ≈ 1,040px · เทียบ 720px = เห็น ~69–75% · ลดเหลือ 44px เต็มไม่พอ (≈ 750–800px)
- **ที่ scroll 0 เห็นถึง ~Servo (บางส่วน Bus)** · Sound, Sensor, Display, Light อยู่ใต้รอยพับ · เด็กที่เริ่มด้วย Blink (Light) ต้องเลื่อนทุกครั้ง · ลำดับสลับไม่ได้ (ผู้ใช้ตัดสิน) → ทางลดผลที่อยู่ในกรอบ requirement: (ก) เลื่อนในแถบ + เก็บตำแหน่งเลื่อนระหว่างเปลี่ยนหมวด (ไม่รีเซ็ตเป็นบนสุด) (ข) หมวดที่เลือกอยู่เลื่อนเข้าจอเสมอ (R18 ระบุแล้ว) (ค) หัวกลุ่มยุบ/ขยายได้ (ข้อ "ข้อมูล" ว่าง 3 จาก 4 ยุบแล้วได้ที่ ~170px) — **ขัด requirement ปัจจุบันที่ให้หัวกลุ่มเป็น "ตัวคั่น"** ต้องให้ผู้ใช้ตัดสินถ้าอยากใช้ → OQ68 · (ง) ลด 5 หมวดว่างออกจากแถบ = ขัด OQ57 (ผู้ใช้ตัดสินแล้ว ไม่เสนอ)
- เงื่อนไขเมื่อเลื่อน (H1/H6/UD2 · R18 ระบุแล้ว): เห็นว่ายังมีต่อโดยไม่พึ่ง hover (ลูกศร/เฟดขอบ/แถบเลื่อนที่เห็นได้) · หมวดที่เลือกเลื่อนเข้าจอเสมอ · คีย์บอร์ดเลื่อนตาม focus (ลูกศรขึ้น-ลง, Home/End เสนอ เพราะไม่มี "ของโปรด" และไม่มีค้นหา) · reduced-motion ไม่เลื่อนแบบแอนิเมชัน · กดหมวดไม่ต้องลาก (ไม่ขัด 2.5.7) · ตัวอักษรไม่ชนกรอบ 3 ภาษา
- **ไม่มี "ของโปรด"** (OQ65): D1 และ feasibility/R1.md §หน้าจอ (SCR-16 "ตัวกรอง: ... ของโปรด") ยังพูดถึง → D1 ต้องเอาออกตอนแก้ · ไม่กระทบ logic อื่น
- กลุ่มเป็นตัวคั่น: ต้องเป็นโครงสร้างที่ screen reader อ่านเป็นกลุ่ม (role group + ชื่อกลุ่ม) ไม่ใช่ตัวหนังสือลอย · หัวกลุ่มไม่โฟกัสเป็นปุ่ม ไม่นับเป็นหมวด
- ไม่บันทึกหมวดที่เลือก/ตำแหน่งเลื่อนกับงาน (R18 ไม่ระบุ · my-work R10 ไม่รวม → ถือตามข้อเสนอ ruler: ไม่บันทึก) · เปิดงานใหม่/เปิดงานเดิม = เริ่มที่หมวดตั้งต้น (OQ68)

## ตัวละคร (หมวดโผล่เฉพาะเมื่อเลือก stage) · กลุ่ม "อื่น ๆ" หมวดเดียว (OQ66)
เรื่องดีของตำแหน่ง: ตัวละครอยู่ท้ายสุดของแถบ → หมวด/หัวกลุ่มที่โผล่หรือหายต่อท้าย ไม่ดีดตำแหน่งหมวดอื่น ๆ (ตอบข้อกังวลเดิมเรื่อง "ดีด") · ช่องโหว่ที่เหลือ:
- **หัวกลุ่ม "อื่น ๆ" ตอนไม่ได้เลือก stage:** R18 ให้มีหัวกลุ่มแม้เหลือหมวดเดียว แต่หมวดนั้นซ่อน → ถ้าหัวกลุ่มค้างจะเป็นหัวกลุ่มเปล่า (ขัดหลักไม่มีทางตัน/สับสน) · Proposed: หัวกลุ่มโผล่/หายพร้อมหมวด (4 กลุ่มเมื่อเลือก stage, 3 กลุ่มเมื่อไม่เลือก)
- **คลิก stage แล้วเกิดอะไรกับหมวดที่เลือก:** R1 บอกแค่ว่าหมวดแสดง ไม่บอกว่าสลับพาเลตไปตัวละครไหม · ถ้าไม่สลับ+แถบอยู่บนสุด หมวดใหม่อยู่ใต้รอยพับ ~1,000px เด็กไม่เห็นว่ามีอะไรเปลี่ยน (ใบ้ "คลิกเพื่อดูบล็อกตัวละคร" ของ OQ37 ไม่พอ) · Proposed: คลิก stage = เลือกตัวละครเป็นหมวดที่เลือก + เลื่อนเข้าจอ (แนว mBlock เลือก sprite) · ประกาศให้ screen reader ("แสดงหมวดตัวละคร")
- **กลับไปเลือกบอร์ดขณะเลือกตัวละครอยู่:** ต้องกลับไปหมวดที่เลือกก่อนหน้าที่ไม่ใช่ตัวละคร (ไม่ปล่อยพาเลตค้างบล็อกที่หมวดหายไปแล้ว) · โฟกัสคีย์บอร์ดที่อยู่บนหมวดที่หายต้องย้ายไปหมวดที่เลือกใหม่ ไม่ตกหาย
- **ทางเลือก stage ด้วยคีย์บอร์ด/ไม่ใช้เมาส์:** R1/R7 ระบุ "คลิก" เท่านั้น → ผู้ใช้คีย์บอร์ดเข้าหมวดตัวละครไม่ได้ (WCAG 2.1.1) · Proposed: stage มีปุ่มโฟกัสได้ (เช่น ปุ่มข้อความ "ตัวละคร" ใต้/บน stage) ที่ทำหน้าที่เดียวกับคลิก และบอกสถานะเลือกอยู่/ไม่ (aria-pressed) ไม่พึ่งสีอย่างเดียว
- บล็อกตัวละครที่อยู่ในพื้นที่ต่อบล็อกแล้วยังอยู่เมื่อหมวดซ่อน (R1 ระบุ · OQ37) · จึงต้องยังเห็นบล็อกเหล่านั้นอ่านได้ (ไม่ใช่ลายเทาปิดใช้ เพราะอยู่ใต้ setup/loop ได้ตามปกติ)
