# Block Lab · Feasibility R16: บล็อกอ้างอิงอุปกรณ์จาก dropdown ชื่อ

**ผล: ทำได้มีเงื่อนไข** (2026-10-22 · ruler) · ไม่มี OQ ที่ block การออกแบบ · เงื่อนไขหลัก: ตัวจำลองต้องมี netlist (หาขาจากสายจริง) · ผูกกับ R17 (`R17.md`)

## ข้อค้นพบหลัก
1. **netlist เป็นข้อบังคับ ไม่ใช่ตัวเลือก:** "ระบบหาขาจากสายที่ต่อจริง" ต้องไล่การเชื่อมต่อ ขา Uno → สาย → แถบรูของ breadboard → ขาอุปกรณ์ → (ผ่านตัวต้านทาน) → ปลายอีกด้าน · ไลบรารีจำลอง AVR ทั่วไปจำลอง MCU ไม่รวมวงจร (Assume · dev ยืนยัน) · เดิม OQ1 ตั้งเป็น "ระดับการคำนวณ (A/B)" ตอนนี้ขั้นต่ำคือ netlist + กฎนิ่ง (ไม่ต้องแก้สมการแอนะล็อก) → อัปเดต OQ1/OQ21
2. **บล็อกอ้างด้วย ID ของอุปกรณ์ ไม่ใช่ข้อความชื่อ** (เสนอ): ชื่อแก้ได้ (R4) ถ้าอ้างด้วยชื่อ การเปลี่ยนชื่อทำบล็อกพัง · ID ทำให้เลิกทำการลบ/เปลี่ยนชื่อผูกกลับเองได้ · ชื่ออัตโนมัติเป็น 3 ภาษา: เก็บ (ชนิด + ลำดับ + ธงอัตโนมัติ) แล้วแสดงตามภาษาปัจจุบัน ชื่อที่เด็กพิมพ์เองคงเดิม → OQ56
3. **dropdown กรองตามชนิดอุปกรณ์ของบล็อก:** "เปิด [LED]" แสดงเฉพาะ LED/ไฟ RGB ตามบล็อก · แต่ละตัวมีไอคอนชนิด (ไม่ใช้ชื่ออย่างเดียว ตาม R16) และสถานะ "ยังไม่ต่อสาย" (ไอคอน+ข้อความ) เพื่อให้เห็นก่อนกดรัน · ถ้าไม่มีอุปกรณ์ชนิดนั้น ข้อความบอกวิธีวาง (ตาม R16) และมีปุ่มไปแผงอุปกรณ์ (ไม่ต้องลาก OQ29)
4. **เลือกอัตโนมัติเมื่อมีตัวเดียว (ข้อเสนอ Designer):** เมื่อลากบล็อกเข้าและมีอุปกรณ์ชนิดนั้นตัวเดียว เลือกให้เลย ลดขั้นสำหรับ ป.3 · ไม่ใช่ข้อกำหนด
5. **LED บนบอร์ด (ขา 13):** เป็น "อุปกรณ์" ที่ไม่มีสายและมีเสมอ (OQ13 Proposed: มี) · ต้องตัดสินว่าอยู่ใน dropdown ด้วยไหม (Blink แรกไม่ต้องต่อสาย) และไม่ถูกลบ/แก้ขา → OQ54
6. **บล็อกขาสัญญาณใน R1 ขัดกับ R16:** ตาราง R1 ยังมี digitalWrite/digitalRead/analogRead/analogWrite แบบเลือกขา แต่ R16 ให้เลือกอุปกรณ์ → X10 → OQ54
7. **นิยาม "ขั้วสัญญาณ" ต่อชนิดอุปกรณ์** (ฐานของ R16/R17 · dev/Designer ยืนยัน):

| อุปกรณ์ | ขั้วสัญญาณที่ระบบหาขา Uno | ขั้วอื่นที่ต้องต่อ |
|---|---|---|
| LED | ขั้วบวก (ผ่านตัวต้านทานในอนุกรมได้) | ขั้วลบถึง GND |
| ปุ่มกด | ขาหนึ่ง | อีกขาถึง GND (ตัวสร้างโค้ดใส่ INPUT_PULLUP · OQ25) |
| potentiometer | ขากลาง (wiper) ต้องถึง A0–A5 | ปลายหนึ่ง 5V อีกปลาย GND |
| buzzer | ขั้วบวก | ขั้วลบ GND |
| servo | สายสัญญาณ | 5V และ GND |
| ไฟ RGB | 3 ช่อง (แดง เขียว น้ำเงิน) | ขากลาง (ชนิดเดียว OQ13) · ต่อไม่ครบบางช่อง ให้บอกรายช่อง |

8. **โค้ด C++ (R3) แสดงเลขขาที่หาได้:** เมื่อเด็กย้ายสาย เลขขาเปลี่ยนเอง (เป็นสิ่งดี แต่ควรเห็นว่าเปลี่ยน) · ยังหาขาไม่ได้ → บรรทัดคอมเมนต์ `// LED แดง 1: ยังไม่ได้ต่อสาย` ไม่ใส่เลขขา/pinMode/include ที่ไม่มีที่มา · การย้ายสายนับเป็น "แก้วงจร" ที่หยุดจำลอง (R10 · OQ8) และต้องชัดว่า "ย้ายสายระหว่างจำลอง" ไม่ทำให้ขาเปลี่ยนกลางโปรแกรม (หยุดแล้วเริ่มใหม่)
9. **ลำดับพึ่งพาข้อมูล:** ENT-17 ต้องเพิ่ม ID/ชื่อ/ธงชื่ออัตโนมัติของอุปกรณ์ และการอ้างของบล็อก → my-work R10 (ตอนนี้ระบุ "อุปกรณ์ ตำแหน่ง การหมุน ค่า สาย" ไม่ระบุชื่อ/ID) และรูปแบบ export (OQ5) · แจ้ง session หลัก

## พฤติกรรมเมื่ออุปกรณ์ที่บล็อกอ้างถูกลบ/ยังต่อไม่ครบ (OQ50) · ข้อเสนอ
**ลบอุปกรณ์:**
- บล็อก "กำพร้า": คง ID เดิม + ชื่อสุดท้าย + ไอคอนชนิด + ป้าย "ไม่พบอุปกรณ์" (ไอคอน+ข้อความ ใช้ภาษารูปลักษณ์เดียวกับบล็อก disabled ของ R2 (4) แต่ข้อความต่างกัน ไม่ปนกัน) ไม่ล้างค่า (ล้างทำให้เด็กเสียสิ่งที่ตั้งใจ และทำให้เลิกทำไม่ผูกกลับ)
- เลิกทำการลบ → บล็อกผูกกลับอัตโนมัติ (เพราะอ้าง ID) · วางอุปกรณ์ใหม่ชนิดเดียวกัน → **ไม่** ผูกให้เอง เด็กเลือกใหม่จาก dropdown (ข้อเสนอเสริม ไม่บังคับ: ทางลัด "ใช้ [LED แดง 2] แทน")
- ก่อนลบ: ถ้ามีบล็อกอ้างอุปกรณ์นั้น ให้บอกจำนวนบล็อกที่จะได้รับผลใน popover (H5 · ไม่ต้องมี confirm ถ้าเลิกทำได้) → Designer ตัดสิน
- นับเป็นข้อ (1) ของ R17 (ข้อเดียวต่ออุปกรณ์ ไม่ว่ากี่บล็อก)

**ระหว่างจำลองที่ผู้ใช้เลือกจำลองต่อ:**
- บล็อกคำสั่ง (เช่น "เปิด [LED]") กำพร้า = ไม่ทำอะไร โปรแกรมไปต่อ
- **บล็อกค่า/เงื่อนไขที่ฝังในบล็อกอื่น** (เช่น ใน "ถ้า [ปุ่ม ถูกกด]") กำพร้า = ค่า 0 / เท็จ (requirement ใช้คำว่า "ข้าม" ซึ่งกำกวมกับบล็อกที่ฝังอยู่ · ข้ามทั้งบล็อกแม่จะข้าม else ด้วย) · แจ้งในลิสต์ว่าใช้ค่านี้ · ป้ายอยู่บนบล็อกตลอดการจำลอง
- อุปกรณ์ที่ยัง "ต่อไม่ครบ" (ไม่กำพร้า): ไม่มีขาให้ขับ → ไม่ตอบสนอง (เหมือนสายหลวงบนบอร์ดจริง) · ปุ่ม/potentiometer ที่ไม่ได้ต่อ อ่านเป็นค่าคงที่ 0 ไม่สุ่ม (กันค่าสั่น/กะพริบ WCAG 2.3.1 และไม่งง) · เรื่องขาไม่รองรับหน้าที่ (ข้อ (3a)): ตัวจำลองทำเหมือนฮาร์ดแวร์ (เช่น analogWrite บนขาไม่ใช่ PWM = สูง/ต่ำ) เพื่อให้ตรงกับที่จะเกิดบนบอร์ดจริง ไม่ข้าม · ตัดสิน → ผู้ใช้ยืนยัน (OQ50)
- แผงโค้ด: บรรทัดคอมเมนต์ข้าม (ข้อ 8)

## H1/H5/H9
- H1: ป้ายบนบล็อก + สถานะ "ยังไม่ต่อสาย" ใน dropdown · H5: ลดโอกาสเลือกผิดชนิดด้วยการกรอง · H9: ทุกกรณีบอกสาเหตุ+วิธีแก้ (วางอุปกรณ์ / ต่อสาย / เลือกใหม่) ในลิสต์ R17
- UD4: ชื่อ + ไอคอน ไม่พึ่งสีของอุปกรณ์ (เช่น "LED แดง" ต้องมีไอคอน/ข้อความ ไม่ใช่สีแดงอย่างเดียว) · UD3: ชื่อยาวใน dropdown ที่ +40% (3 ภาษา) ต้องตัด/ขึ้นบรรทัดไม่ล้นบล็อก (R12 ความแน่น)
