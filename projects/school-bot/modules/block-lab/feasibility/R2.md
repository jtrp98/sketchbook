- สีขอบปัจจุบัน 16 สี (เข้มกว่าพื้น) ตัวขาวบนสีขอบ: **14 จาก 16 ผ่าน 4.5:1 (≈4.8–7.0)** · **ไม่ผ่าน 2:** เริ่มต้น #9C7A00 ≈4.0 · ไฟ #6E7F0B ≈4.47 (ฉิวเฉียด) → ถ้าใช้โทนขอบเป็นพื้นใหม่ ต้องปรับ 2 หมวดนี้ให้เข้มขึ้นอีก (ข้อเสนอเริ่มต้น เริ่มต้น ≈#8F6F00 ≈4.7 · ไฟ ≈#657500 ≈5.1 · ค่าจริงให้ Designer วัด) แล้วทำเส้นขอบให้เข้มกว่าพื้นใหม่อีกขั้น

- ผลข้างเคียงของ (ก): เฉดพื้นจะอยู่ช่วงมืดกลาง (L ≤ ~0.18) · เหลือง/เขียวมะนาวกลายเป็นน้ำตาลทอง/เขียวมะกอก (ลดความ "สดแบบ mBlock" ตาม R2 (2)) · กลุ่มที่ใกล้กัน: ตัวแปร #B03A1C / ตัวละคร #A4521C / ควบคุม #A8610A (สนิม-น้ำตาล) · คณิต #2F7A26 / แสดงผล #1F8050 / ตรรกะ #137A70 (เขียว-เขียวน้ำเงินเข้ม) → แยกหมวดด้วยสีอย่างเดียวไม่ได้ ต้องมีไอคอน+ชื่อกำกับ (UD4/R18 มีอยู่แล้ว · ต้องไม่ลดลง) · ผู้ใช้ควรเห็นภาพจริงก่อนยืนยัน (OQ111)
- **ขอบเขต "ตัวอักษรบนบล็อกเป็นสีขาว" ต้องนิยาม (ขาดใน R2 (11)):** บล็อกลายเทา/ไม่ได้ต่อ (พื้น #F4F6F8 · ตัวขาว = 1.1:1 ซ้ำ BUG-14), ข้อความในช่องค่าแคปซูลขาว (ตัวเข้ม ตามภาพอ้างอิง), ชิปคำกำกับ hat ขาวโปร่ง, ข้อความ "ช่องนี้ยังว่าง" ต้องคงตัวเข้ม → ข้อเสนอ: ขาวเฉพาะข้อความบนพื้นสีหมวดของบล็อกที่ใช้งานอยู่ · สถานะอื่นยังใช้ text-primary ผ่าน 4.5:1 (OQ111)
- ช่อง dropdown พื้นเข้มกึ่งโปร่ง rgba(0,0,0,.22) บนพื้นใหม่ ตัวขาวผ่านแน่ (พื้นเข้มขึ้นกว่าเดิม) · ตัวขาว 16px/400 บนพื้นเข้มอ่านบางกว่ากรมท่าบนพื้นสว่าง → แนะนำน้ำหนัก 500–600 (OQ75 อนุญาตให้ปรับน้ำหนักเมื่อ contrast ต้องการ ต้องรายงาน)
- ผลดี: ขอบเขตบล็อกกับพื้นขาว/ลายจุด เกิน 3:1 ชัดขึ้น (WCAG 1.4.11) · ค่าสีรวมอยู่ที่ component เดียว (13) แก้จุดเดียว
- OQ108 ยังเปิด (ไม่มีไฟล์ภาพ Tinkercad จึงวัดสี/ความหนาขอบ/padding จริงไม่ได้ · ค่าตัวขาวที่ผู้ใช้ "ใช้ได้" ในภาพอาจเป็นเฉดกลางที่ไม่ถึง 4.5:1 → ถ้าผู้ใช้ต้องการเฉดตามภาพเป๊ะ = ผู้ใช้ตัดสินยอมข้อยกเว้นตามเงื่อนไข OQ38 ไม่ใช่ Designer ลดเอง)

**(12) แผงรายการบล็อก พื้นทึบ 80–90% ซ่อนด้วยคลิก canvas · ทำได้มีเงื่อนไข**
- **contrast:** ข้อความของบล็อกอยู่บนบล็อกทึบ ไม่ขึ้นกับความโปร่งของแผง · ข้อความของแผงเอง (ชื่อหมวด, ข้อความหมวดว่าง/ไม่มีอุปกรณ์, หัวรายการ) อยู่บนแผง + ของที่ซ้อนหลังแผง · ลายจุดอย่างเดียว (ขาว + จุด #DCE3EC) ที่โปร่ง 10–20% ทำให้พื้นแผง ≈ #F8FAFC–#FDFEFE ไม่กระทบ (text-secondary #5A6377 ≈ 5.8–6.0:1, text-primary สูงกว่า) · **จุดเสี่ยง:** ถ้าแผงลอยทับบล็อกที่วางไว้ (พื้นเข้มใหม่) ที่โปร่ง 20% พื้นเฉลี่ยใต้ตัวอักษรเข้มขึ้น คำนวณมือกรณี #2F7A26 ใต้แผงขาว 80%: text-secondary ≈ 4.5:1 (ฉิวเฉียด) → ข้อความในแผงใช้ text-primary หรือใช้ 90% ขึ้นไปหรือมีพื้นทึบหลังข้อความ
- **แผง "ลอยทับ" หรือ "ดัน" พื้นที่ต่อบล็อก ไม่ระบุ:** "เห็นลายจุดด้านหลัง" แปลว่าลอยทับ canvas เต็มความกว้าง · ผลที่ต้องกำหนด: บล็อกที่วางใต้แผงมองเห็นจาง ๆ แต่คลิกไม่ได้ (ชนแผง) จนกว่าแผงซ่อน · ปล่อยบล็อกลงบนแผง = พื้นที่ลบ (R2 รอบ 4) ต้องบอกว่ายังเป็นเช่นนั้น · ตำแหน่งที่บีบให้อยู่ในพื้นที่ที่เห็น (รอบ 4) ต้องนับพื้นที่ใต้แผงเป็นพื้นที่วางได้หรือไม่
- **a11y คีย์บอร์ด/เด็กไม่รู้ว่าซ่อนได้ (H6 การจำ, UD2, WCAG 2.1.1, 3.2.x):**
  1. คลิกพื้นที่ว่างเป็นท่าทางที่มองไม่เห็น (ไม่มี affordance) และเป็นท่าทางเมาส์/นิ้วเท่านั้น → ต้องมีตัวควบคุมจริงที่มองเห็นและโฟกัสได้ (ปุ่มหุบ/ขยายที่ขอบแผง หรือกดหมวดที่เลือกอยู่ซ้ำ) + `aria-expanded`/`aria-controls` บนปุ่มหมวด และ Esc ปิดแผงเมื่อโฟกัสอยู่ในแผง
  2. ซ่อนแล้วแผงต้องออกจากลำดับ tab/อ่านออกเสียงจริง (`inert`/`hidden`) ไม่ใช่แค่จางหรือเลื่อนออกนอกจอ · ย้ายโฟกัสกลับปุ่มหมวดเมื่อซ่อนขณะโฟกัสอยู่ในแผง · ประกาศสถานะ (ซ่อน/แสดง) ให้ screen reader
  3. เด็กที่ไม่รู้ว่าซ่อนได้ ไม่เสียหาย: แผงเปิดแล้วคงใช้งานได้เต็มที่ (ค่าเริ่มต้นเมื่อเปิดงาน = แสดง เสนอ) · เด็กที่ซ่อนโดยบังเอิญ ต้องเปิดคืนง่าย: กดปุ่มหมวดใดก็ได้ในแถบหมวดแล้วแผงกลับมาที่หมวดนั้น (ลักษณะ mBlock) + ปุ่มที่เห็นได้ · ห้ามต้องไปค้นหาในเมนู
  4. **ชนกับท่าทางอื่นบน canvas:** (ก) ลากพื้นหลังเพื่อเลื่อน (OQ95) · ล้อ/ซูม → ต้องไม่นับเป็นคลิกซ่อน (เกณฑ์ระยะเลื่อน ≥ ~4px) (ข) ทางเลือกไม่ต้องลาก "แตะบล็อกในรายการแล้วแตะ canvas เพื่อวาง" (OQ29/WCAG 2.5.7) · ถ้าแตะ canvas ซ่อนแผงทันที ทางเลือกนี้พัง → ถ้ามีบล็อกที่กำลังเลือกค้าง แตะ canvas = วาง ไม่ซ่อน (ค) แตะบล็อกที่วางแล้ว/dropdown/ปุ่มในบล็อกไม่ซ่อน · ซ่อนเฉพาะแตะพื้นว่าง (ง) "กดบล็อกในรายการ = เพิ่มให้" (ทางเลือก OQ91/92) ต้องไม่ซ่อนแผง เพื่อเพิ่มต่อเนื่อง
  5. ไม่มีเหตุการณ์เวลา/hover จึงใช้บนจอสัมผัสได้ · เคารพ reduced-motion (แอนิเมชันหุบ/ขยาย)
- ผลต่อรอบ 5 ที่ผู้ใช้เคยตัดสิน: OQ93 (รายการ 340 · ดันพื้นที่) และ OQ102 (แผงขวา 680 ดันพื้นที่ต่อบล็อก) ใช้ "ดัน" · (12) ใช้ "ลอยทับ" → สองแผงมีพฤติกรรมต่างกัน (H4 สม่ำเสมอ) ต้องนิยามว่าซ้อนกันอย่างไรเมื่อเปิดทั้งสอง (รายการ 340 + แผงขวา 680 บน 1328 เหลือพื้นที่ต่อบล็อกที่มองเห็นเพียง ≈ 300)
- OQ112 บันทึกรายละเอียดที่ผู้ใช้ต้องตัดสิน/ยืนยัน

**(13) บล็อกใน list กับบน canvas เป็น component เดียว · ทำได้มีเงื่อนไข (เป็นงานออกแบบ/dev ไม่ขัด logic)**
- ทำได้ถ้า component รับ prop สถานะ (อยู่ในรายการ / วางแล้ว / กำลังลาก / ในช่อง / disabled-loose / กำพร้า) แล้ววาดรูปทรง สี ความสูง 34 (OQ97) และตัวอักษรชุดเดียว · ผลดี: เกณฑ์ contrast/OQ97 แก้ที่เดียว ไม่เพี้ยนระหว่าง 2 ที่ (ปัญหาของรอบ 5)
- เงื่อนไข: (1) ช่องซ้อน/ปากครอบ C ที่ยืดตามเนื้อหาต้องเป็น slot/children ของ component (ยังไม่ได้ render ตรวจใน C1) (2) นิยาม "เหมือนกัน" = รูปทรง สี ตัวอักษร padding ตรงกัน · ต่างได้เฉพาะสถานะ (เช่น ฮาโลตอนลาก) (3) **ผลต่อบอร์ด A:** OQ107 ให้อัปเดต component ที่ A ใช้ แต่ที่ผ่านมา A และชิ้นส่วนเดิมถูกกัน ไม่แตะ (A2 ทำสำเนา) → ต้องตัดสินว่าแก้ component ร่วมหรือทำชิ้นส่วนใหม่ให้ A2 (ถ้าแก้ร่วม A เปลี่ยนตาม: บล็อกใน A จะสีเข้ม/ตัวขาวด้วย) (4) ตัวคำนวณขนาด/เกาะ/โค้ด C++ ใน `BlocksPaneA2` ต้องอ่านขนาดจาก component (หรือค่าคงที่ร่วม) ไม่ใช้ค่าที่ซ้ำสองที่ (OQ103) · ผู้ใช้/session หลักตัดสินข้อ (3) → OQ116

## ผลตรวจ ruler (2026-10-21)
กติการูปทรงและต่อบล็อกชัด ทำได้ ช่องโหว่:
- **setup/loop อย่างละ 1 บล็อก ไม่ระบุกลไก:** วางไว้ให้ในงานใหม่ (ลบไม่ได้) หรือผู้ใช้ลากเอง (แผงปิดใช้หลังมี 1 ต้องบอกเหตุผลด้วย `aria-disabled` ไม่ใช่แค่จาง) · ถ้าลบได้/ไม่มี loop → โค้ด Arduino ต้องมีทั้งสองฟังก์ชัน ต้องกำหนดสถานะ · ถ้าวางไว้ให้ ST-10 "ว่าง = ลากบล็อกแรก" ต้องเปลี่ยนเป็น "ลากบล็อกเข้าใต้ วนทำซ้ำ" (Proposed: วางไว้ให้ ลบไม่ได้) → OQ26
- **บล็อกลายเทา (ST-27)** ถูกข้ามตอนจำลอง/ส่ง/ดูโค้ด ต้องบอกเหตุผลเป็นข้อความ ไม่ใช่แค่ลายเทา (H1, H5) · ต้องอ่านได้ (BUG-14)
- **โปรแกรมไม่สมบูรณ์** (ช่องว่าง เช่น "ถ้า [ ]", ชนิดไม่ตรง) ไม่มีสถานะรองรับตอนเริ่มจำลอง/ส่ง (H5, H9) → OQ26
- **"หยุดโปรแกรม" ไม่มีคู่ตรงใน Arduino C++** (ต้องแปลงเป็นลูปค้าง/exit) · ต้องนิยามผลบนตัวจำลองและ stage (จบแล้ว อุปกรณ์ค้างสถานะสุดท้ายหรือดับ) → OQ26
- **ไม่มีทางเลือกที่ไม่ต้องลาก** สำหรับต่อบล็อก (WCAG 2.5.7) · พื้นที่ต่อบล็อกต้องซูม/เลื่อนได้ (BUG-18) → OQ29
- **เลิกทำ 60 ขั้น:** ขอบเขตกับวงจร/แท็บอื่น (Ctrl+Z ทำอะไร) → OQ32
