# Block Lab · Feasibility R18: แถบหมวดบล็อก (รวมตรวจ R1 หมวด + §ตารางหมวด)

## ผลตรวจ ruler (2026-10-28 · ส่วน "แทนที่ 2026-10-28" · OQ156–OQ166)

**ผล: ทำได้มีเงื่อนไข · block `approved`: OQ170 (ฟังก์ชัน), OQ171 (เซนเซอร์ที่จำลองไม่ได้)** · อ่านจากเอกสารเท่านั้น ไม่ได้ render · ยังไม่มี `components.md` ของทีม: ใช้ WCAG 2.2 AA ทั่วไป · ผลด้านล่างของไฟล์ (16 หมวด) ใช้ได้เฉพาะกฎหมวดว่าง/การเลื่อนแถบ/สี ที่ไม่ขัดของใหม่

**ทำได้:** 15 หมวด 3 กลุ่ม (5+3+7) + ตัวละครพิเศษ = 18–19 แถว (รวมหัวกลุ่ม) ใกล้ของเดิม (16 + 4 หัว) กฎการเลื่อนแถบ R18 เดิมใช้ต่อได้ · Display/Serial/คณิต/ควบคุม มีบล็อกครบ · Serial = หมวดสื่อสารเดิม + 2 บล็อกรับข้อความ (OQ153) ไม่ขัด R8

**ข้อขัดในเอกสาร (X28 · session หลักแก้ข้อความ ไม่ต้องถามผู้ใช้):**
- R1: "16 หมวด" และ "หมวด สื่อสาร แสดงตลอด" · R8: "หมวด สื่อสาร มีบล็อกรับข้อความ" → Serial · R18 ข้อความเดิมทั้งก้อน (รายชื่อ 16 · Light/Sound/Bus · "List, Function, Text, Bus, Display ว่าง" · "ไม่มี hat ตัวที่ 3" · 4 กลุ่ม/กลุ่ม "อื่น ๆ" · หมวดอุปกรณ์ Servo/Sound/Sensor/Light) ขัดกับส่วนแทนที่ → ย้ายไป archive แทนการเขียน "ใช้เฉพาะที่ไม่ขัด" · บรรทัดใต้หัวตาราง "ตารางเดิม 16 หมวด" ok แต่ DEC-20 "→ 16 หมวด" ต้องแก้ · OQ157 (RGB/buzzer → Display) ถูก OQ164 ทับบางส่วน: ตาราง Display ถูกแล้ว แต่ควรหมายเหตุใน OQ157
- **Function ไม่ว่างแล้ว → hat ตัวที่ 3 กลับมา** ขัด R2 "hat 2 แบบ อย่างละ 1" (X29 → OQ170)

**ความเสี่ยงต่อ ป.3 (R12):**
1. **หมวดว่าง 6 จาก 15 (40%)** · กลุ่ม School Bot ว่าง 4 จาก 7 · ที่หนักสุด: **"Servo / Motor" ว่างทั้งที่ servo มีจริง (อยู่ Sensor)** และ **"Remote Control" ว่างทั้งที่ IR remote อยู่ Sensor** → เด็กหาตามชื่อหมวดแล้วเจอว่าง (H2 จับคู่โลกจริง · H4 ความสม่ำเสมอ) · Sensor มีตัวส่งออก (servo, fan, relay, buzzer, OLED, RGB) ขณะ Display มีแค่ LED → ชื่อหมวดไม่ตรงความหมาย → OQ169
2. **Sensor ≈ 35 บล็อก** รายการยาวมากในแผง 340 ต้องเลื่อนหลายหน้า · ไอคอนครบทุกตัว (OQ162) ช่วยได้ · ควรมีหัวย่อยในรายการ (รับค่า / ส่งออก) ไม่เปลี่ยนหมวด → OQ169
3. ชื่อหมวดอังกฤษ (Arm Control, Sensor, Display, Serial, Remote Control) กับเด็ก ป.3 → ยังเปิดที่ OQ62
4. **เซนเซอร์ที่ตัวจำลองไม่มี (OQ163) ใช้ไม่ได้จริงในโหมดบล็อก:** R16 dropdown แสดงเฉพาะอุปกรณ์ที่วางในตัวจำลอง + ไม่มีบล็อกเลขขา (OQ54) → เลือกอุปกรณ์/หาขาไม่ได้ · R17 (1) "ใช้อุปกรณ์ที่ยังไม่ได้วาง" จะขึ้นทุกครั้งและ **ปิดกั้นส่งลงบอร์ด** → ขัด OQ163 "ส่งลงบอร์ดทำงานปกติ" (X30 → OQ171 · block) · ค่า 0 ตอนจำลองอาจทำให้เงื่อนไขทำงานผิด (เช่น ระยะ < 10 เป็นจริงตลอด) ต้องเห็นป้ายบนบล็อก + ใน Output/รายการ R17 แบบข้อมูล ไม่ใช่ error · บางตัวต้องใช้ไลบรารี/หลายขา (OLED I2C, ultrasonic 2 ขา, DHT) → DEV-Q
5. **ฟังก์ชันแบบ Blockly mutator** (กล่องย่อยลาก "with" · allow statements · ชนิด C++): สำหรับ ป.3 เป็นงานซ้อนชั้น (ลากในป๊อปอัปลอย) + ศัพท์ C++ (int/float/void/String) + "with" ภาษาอังกฤษ · ลากในกล่องย่อยต้องมีทางเลือกไม่ลาก (WCAG 2.5.7) · ชนิด String ขณะหมวด ข้อความ ว่าง → ไม่มีบล็อกสร้างค่า String · รายงานความเสี่ยง ไม่ตัดสินแทน → OQ170
6. บล็อกค่าสี (R2 · OQ166): ช่อง R G B ต้อง validate 0–255 (H5) · ชุดสีพื้นฐานต้องมีชื่อสี (ไม่สื่อด้วยสีอย่างเดียว · 1.4.1) → OQ172

**ผล: ทำได้มีเงื่อนไข** (2026-10-22 · ruler · ตรวจซ้ำหลังผู้ใช้ตัดสิน OQ54, OQ57, OQ59, OQ60, OQ61, OQ65 และ session หลักแก้ requirements.md) · **ไม่มี OQ ที่ block `approved` และไม่มี OQ ที่ block การออกแบบ D1** · รายชื่อ/ลำดับ/กลุ่ม/ตารางหมวดใน requirements.md ตรงกันเอง (16 หมวด · 4 กลุ่ม 5+4+6+1) และไม่ขัด R2/R16/R17/R4 ยกเว้น 1 ข้อ (LED บนบอร์ด → X17) · ช่องโหว่ใหม่ 3 ข้อ (OQ66–OQ68) มีค่า Proposed ใช้ออกแบบเผื่อได้ · ทั้งหมดเป็นการอ่านเอกสาร ยังไม่ได้ทดสอบกับ mBlock จริงหรือ canvas · ไม่มี `components.md` ของทีม: ใช้ WCAG 2.2 AA ทั่วไป

ผลรอบก่อน (17 หมวด) ที่เลิกใช้แล้ว (Function/hat ตัวที่ 3, SRAM, รวม Serial/สื่อสาร, ตาราง R1 10 หมวดไม่ตรง, ข้อเสนอจับคู่) ถูกปิดโดยคำตอบผู้ใช้ · เก็บเฉพาะ §List/Function/Text ไว้เป็นจุดเริ่มถ้าเพิ่มบล็อกภายหลัง (OQ57)

## เงื่อนไข (สรุป)
1. แถบ **ต้องเลื่อน** · 16 รายการ + หัวกลุ่ม ≈ 950–1,040px เทียบ 720px · ที่ scroll 0 หมวด Sound/Sensor/Display/Light (อุปกรณ์ที่ใช้บ่อยสุดของ Block Lab) อยู่ใต้รอยพับ → §ขนาดแถบ, OQ68
2. วงจรชีวิตหมวด "ตัวละคร" (โผล่/หาย/หมวดที่เลือก/หัวกลุ่ม "อื่น ๆ"/คีย์บอร์ด) ยังไม่นิยาม → §ตัวละคร, OQ66
3. กฎหมวดว่าง 5 จาก 16 (ข้อมูลว่าง 3 จาก 4) เป็นกฎกลางตาม R18 แล้ว · เหลือถ้อยคำ/เครื่องหมายก่อนกด (OQ58)
4. LED บนบอร์ดขา 13: R16 "dropdown แสดงเฉพาะอุปกรณ์ที่วางแล้ว" ขัดกับ OQ54(ข) ที่ผู้ใช้ตอบ → X17, OQ67 (แก้ข้อความ requirement 1–2 ประโยค ไม่ต้องถามผู้ใช้)
5. ชื่อหมวดอังกฤษ (X15 · OQ62) และสีสด 16 เฉด (OQ64/OQ38) ยังเปิด · ไม่ block approved

## ขนาดแถบ (R12 · พื้นที่ 1440×856 · ราง 96 สูง 720 ตาม D1)
- รายการละ ~58px (เป้า 44px + ไอคอน + ชื่อ ≥16px · 3 ภาษา +40%) · หัวกลุ่มละ ~28px
- **ขณะไม่ได้เลือก stage:** 15 แถว + 3 หัวกลุ่ม ≈ 954px · **เลือก stage:** 16 แถว + 4 หัวกลุ่ม ≈ 1,040px · เทียบ 720px = เห็น ~69–75% · ลดเหลือ 44px เต็มไม่พอ (≈ 750–800px)
- **ที่ scroll 0 เห็นถึง ~Servo (บางส่วน Bus)** · Sound, Sensor, Display, Light อยู่ใต้รอยพับ · เด็กที่เริ่มด้วย Blink (Light) ต้องเลื่อนทุกครั้ง · ลำดับสลับไม่ได้ (ผู้ใช้ตัดสิน) → ทางลดผลที่อยู่ในกรอบ requirement: (ก) เลื่อนในแถบ + เก็บตำแหน่งเลื่อนระหว่างเปลี่ยนหมวด (ไม่รีเซ็ตเป็นบนสุด) (ข) หมวดที่เลือกอยู่เลื่อนเข้าจอเสมอ (R18 ระบุแล้ว) (ค) หัวกลุ่มยุบ/ขยายได้ (ข้อ "ข้อมูล" ว่าง 3 จาก 4 ยุบแล้วได้ที่ ~170px) — **ขัด requirement ปัจจุบันที่ให้หัวกลุ่มเป็น "ตัวคั่น"** ต้องให้ผู้ใช้ตัดสินถ้าอยากใช้ → OQ68 · (ง) ลด 5 หมวดว่างออกจากแถบ = ขัด OQ57 (ผู้ใช้ตัดสินแล้ว ไม่เสนอ)
- เงื่อนไขเมื่อเลื่อน (H1/H6/UD2 · R18 ระบุแล้ว): เห็นว่ายังมีต่อโดยไม่พึ่ง hover (ลูกศร/เฟดขอบ/แถบเลื่อนที่เห็นได้) · หมวดที่เลือกเลื่อนเข้าจอเสมอ · คีย์บอร์ดเลื่อนตาม focus (ลูกศรขึ้น-ลง, Home/End เสนอ เพราะไม่มี "ของโปรด" และไม่มีค้นหา) · reduced-motion ไม่เลื่อนแบบแอนิเมชัน · กดหมวดไม่ต้องลาก (ไม่ขัด 2.5.7) · ตัวอักษรไม่ชนกรอบ 3 ภาษา
- **ไม่มี "ของโปรด"** (OQ65): D1 และ feasibility/R1.md §หน้าจอ (SCR-16 "ตัวกรอง: ... ของโปรด") ยังพูดถึง → D1 ต้องเอาออกตอนแก้ · ไม่กระทบ logic อื่น
- กลุ่มเป็นตัวคั่น: ต้องเป็นโครงสร้างที่ screen reader อ่านเป็นกลุ่ม (role group + ชื่อกลุ่ม) ไม่ใช่ตัวหนังสือลอย · หัวกลุ่มไม่โฟกัสเป็นปุ่ม ไม่นับเป็นหมวด
- ไม่บันทึกหมวดที่เลือก/ตำแหน่งเลื่อนกับงาน (R18 ไม่ระบุ · my-work R10 ไม่รวม → ถือตามข้อเสนอ ruler: ไม่บันทึก) · เปิดงานใหม่/เปิดงานเดิม = เริ่มที่หมวดตั้งต้น (OQ68)

## ตัวละคร (หมวดโผล่เฉพาะเมื่อเลือก stage) · กลุ่ม "อื่น ๆ" หมวดเดียว (OQ66)
เรื่องดีของตำแหน่ง: ตัวละครอยู่ท้ายสุดของแถบ → หมวด/หัวกลุ่มที่โผล่หรือหายต่อท้าย ไม่ดีดตำแหน่งหมวดอื่น ๆ (ตอบข้อกังวลเดิมเรื่อง "ดีด") · ช่องโหว่ที่เหลือ:
- **หัวกลุ่ม "อื่น ๆ" ตอนไม่ได้เลือก stage:** R18 ให้มีหัวกลุ่มแม้เหลือหมวดเดียว แต่หมวดนั้นซ่อน → ถ้าหัวกลุ่มค้างจะเป็นหัวกลุ่มเปล่า (ขัดหลักไม่มีทางตัน/สับสน) · Proposed: หัวกลุ่มโผล่/หายพร้อมหมวด (4 กลุ่มเมื่อเลือก stage, 3 กลุ่มเมื่อไม่เลือก)
- **คลิก stage แล้วเกิดอะไรกับหมวดที่เลือก:** R1 บอกแค่ว่าหมวดแสดง ไม่บอกว่าสลับพาเลตไปตัวละครไหม · ถ้าไม่สลับ+แถบอยู่บนสุด หมวดใหม่อยู่ใต้รอยพับ ~1,000px เด็กไม่เห็นว่ามีอะไรเปลี่ยน (ใบ้ "คลิกเพื่อดูบล็อกตัวละคร" ของ OQ37 ไม่พอ) · Proposed: คลิก stage = เลือกตัวละครเป็นหมวดที่เลือก + เลื่อนเข้าจอ (แนว mBlock เลือก sprite) · ประกาศให้ screen reader ("แสดงหมวดตัวละคร")
- **กลับไปเลือกบอร์ดขณะเลือกตัวละครอยู่:** ต้องกลับไปหมวดที่เลือกก่อนหน้าที่ไม่ใช่ตัวละคร (ไม่ปล่อยพาเลตค้างบล็อกที่หมวดหายไปแล้ว) · โฟกัสคีย์บอร์ดที่อยู่บนหมวดที่หายต้องย้ายไปหมวดที่เลือกใหม่ ไม่ตกหาย
- **ทางเลือก stage ด้วยคีย์บอร์ด/ไม่ใช้เมาส์:** R1/R7 ระบุ "คลิก" เท่านั้น → ผู้ใช้คีย์บอร์ดเข้าหมวดตัวละครไม่ได้ (WCAG 2.1.1) · Proposed: stage มีปุ่มโฟกัสได้ (เช่น ปุ่มข้อความ "ตัวละคร" ใต้/บน stage) ที่ทำหน้าที่เดียวกับคลิก และบอกสถานะเลือกอยู่/ไม่ (aria-pressed) ไม่พึ่งสีอย่างเดียว
- บล็อกตัวละครที่อยู่ในพื้นที่ต่อบล็อกแล้วยังอยู่เมื่อหมวดซ่อน (R1 ระบุ · OQ37) · จึงต้องยังเห็นบล็อกเหล่านั้นอ่านได้ (ไม่ใช่ลายเทาปิดใช้ เพราะอยู่ใต้ setup/loop ได้ตามปกติ)

## หมวดว่าง (Text, List, Function, Bus, Display) · H1/H5/H9
- ว่างมี 2 ชนิดที่ต้องไม่ปนกัน: (1) ไม่มีบล็อกใน MVP (5 หมวดนี้) (2) หมวดอุปกรณ์ที่มีบล็อกแต่ยังไม่ได้วางอุปกรณ์ (Servo/Sound/Sensor/Light · R16 ข้อความบอกวิธีวางอุปกรณ์) ห้ามใช้ข้อความ "ยังไม่มีบล็อก" ร่วมกัน · และชนิด (3) หมวด "เริ่มต้น" ที่บล็อกวางไว้แล้ว (OQ68)
- กฎกลาง (R18 ระบุแล้ว): กดได้ · โฟกัสคีย์บอร์ดได้ (ห้าม `disabled`/`aria-disabled` ที่ข้ามโฟกัส) · ไอคอน + ข้อความ · ตัวอักษร ≥ 4.5:1 ไม่จาง · ไม่สัญญาเวลา/ฟีเจอร์ · ไม่ใช่ error · ชี้ทางไปต่อ (เช่น ปุ่ม/ลิงก์ไปหมวดที่มีบล็อก ไม่ใช่ข้อความเฉย ๆ)
- OQ58 ที่เหลือ: ถ้อยคำ 3 ภาษาในพื้นที่ ~184px ต้องไม่ล้น (R12) · ทำเครื่องหมายว่างบนแถบก่อนกดไหม (แลกกับความแน่น · เด็กกดหมวดว่างได้ 5 ครั้งต่อรอบสำรวจ ถ้าไม่มีเครื่องหมาย) → Designer เสนอ · เครื่องหมายต้องไม่ใช้ความจางอย่างเดียว (R18)
- ไม่กระทบ R17/R16/ตัวจำลอง/โค้ด C++ · ไม่มีสถานะ error

## List / Function / Text (เก็บไว้เป็นจุดเริ่มถ้าเพิ่มบล็อกภายหลัง · ตอนนี้ว่างใน MVP ตาม OQ57)
เปลี่ยน requirement ใหม่ + ตรวจ feasibility ใหม่ก่อน (ปัจจุบันไม่ใช้):
- **List:** อาร์เรย์ขนาดคงที่ ชนิด int (OQ25) · เพดาน (เช่น ≤ 20) เพราะ SRAM 2KB · ตำแหน่งนอกช่วงต้องกัน (clamp/ข้ามพร้อมข้อความ) · เลขเริ่ม 1 ใน Scratch vs 0 ใน C++ ต้องแปลงและหมายเหตุในแผงโค้ด
- **Function:** MVP ไม่มีพารามิเตอร์/ค่าคืน · hat ตัวที่ 3 (แก้ R2/X14) · กัน recursion · ประกาศก่อนใช้ใน C++ · บล็อก Stage/อุปกรณ์ในฟังก์ชันที่ไม่ถูกเรียกไม่เตือน R17
- **Text:** char array ไม่ใช้ `String` · จำกัดความยาว (ไทย 3 ไบต์/ตัว) · my-work/export (OQ5) ต้องบันทึกนิยามฟังก์ชัน/รายการ

## สี (R2/OQ38/OQ64 · DSG-13)
- R18 "อิง mBlock" แต่ไม่มีค่าสีอ้างอิงในไฟล์ใด (D1 มี 10 สีพาสเทลชั่วคราว) → Designer ถามผู้ใช้ขอภาพ/ค่าอ้างอิง (OQ64) · ruler ไม่ยืนยันค่าสี mBlock จริง
