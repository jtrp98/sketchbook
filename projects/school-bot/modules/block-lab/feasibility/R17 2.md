# Block Lab · Feasibility R17: ตรวจก่อนรันและเตือนเป็นรายการ

**ตรวจเพิ่ม 2026-10-26 (OQ105 · ตัวกระตุ้น "เริ่มจำลอง" ย้ายไปปุ่มในแผง stage): ทำได้มีเงื่อนไข · ไม่ขัดกับ R17** · ลำดับตรวจไม่เปลี่ยน (กดเริ่ม → ตรวจ → ป๊อปอัป → "เข้าใจแล้ว" → จำลองต่อ) · เงื่อนไข: (1) ตรวจต้องไม่ผูกกับแผง (ชั้นข้อมูล · ส่งลงบอร์ดโดยไม่เคยเปิดแผงต้องตรวจได้) (2) ป๊อปอัปเป็น modal ระดับจอ ไม่ใช่ในแผง (3) กดรายการเกี่ยวกับอุปกรณ์/ขาตอนแผงซ่อน → เปิดแผงก่อนไฮไลต์ (ใช้ "ไปที่ตัวจำลอง" ของ OQ102 ที่มีอยู่แล้ว) (4) ทางเริ่มที่สองจากแถบแจ้ง "หยุดเพราะแก้ไข" ต้องผ่านการตรวจ R17 ด้วย ถ้ายังมี (OQ113) · รายละเอียด `R10.md` §ผลตรวจ ruler 2026-10-26

**ผล: ทำได้มีเงื่อนไข** (2026-10-22 · ruler) · ไม่มี OQ ที่ block การออกแบบ · เงื่อนไขหลัก: ตัวจำลองต้องมี netlist (กราฟการเชื่อมต่อ) + ตารางกฎตรวจชุดเดียว (ดู §OQ51) · ทั้งหมดเป็นการอ่านเอกสาร ยังไม่ได้ทดสอบกับ dev

## ข้อค้นพบหลัก
1. **ข้อ (3) เดิมเปลี่ยนความหมายเมื่อมี R16:** "บล็อกสั่งขา 9 แต่สายต่อขา 10" หายไป เพราะบล็อกอ้างอุปกรณ์แล้วระบบหาขาจากสายเอง · ที่ยังเหลือคือ "ขาที่หาได้ ใช้กับหน้าที่ของบล็อกไม่ได้" (§OQ49) · ถ้า R1 ยังมีบล็อกขาแบบใส่เลขขา ข้อนี้ยังมีความหมายเดิมด้วย → ขัดกันเอง X10 → OQ54
2. **ทุกข้อในลิสต์ปิดกั้นการส่ง ไม่มีทางข้าม:** ผลตรวจที่ผิด (false positive) ทำให้เด็กส่งไม่ได้ตลอด (ทางตัน H9) → ลิสต์ต้องมีเฉพาะข้อที่ "แน่ใจ" และต้องมีกติกาเมื่อระบบตรวจพลาด (X12 → OQ55)
3. **ช่องอุปกรณ์ว่างขัด OQ26:** R17 ให้เตือนแล้วจำลองต่อ (ข้ามบล็อก) แต่ OQ26 (Proposed) ให้ช่องว่างไม่เริ่มจำลอง → ช่อง "เลือกอุปกรณ์" ที่ว่างใช้ R17 · ช่องอื่น (ตัวเลข ฯลฯ) ยังตาม OQ26 (X11)
4. **ป๊อปอัปแบบ modal กับ "กดรายการแล้วพาไปจุดที่ผิด":** ถ้าป๊อปอัปบังบล็อก/ตัวจำลอง ต้องย่อหรือปิดเมื่อกดรายการ แล้วต้องมีที่ให้กลับมาดูลิสต์ (chip "ปัญหา N ข้อ" ใกล้ปุ่มเริ่ม/ส่ง) · ใช้แบบเดียวกับ "ดูวงจร" ของ ST-46 (OQ30)
5. **ตอนจำลองต่อหลังเตือน:** ลิสต์หายพร้อมป๊อปอัป เด็กไม่เห็นว่าบล็อกไหนถูกข้าม (H1) → บล็อกที่ถูกข้ามต้องมีป้ายติดตัวบล็อกตลอดการจำลอง (ไอคอน + ข้อความ ไม่ใช้สีอย่างเดียว)
6. **ตรวจเฉพาะบล็อกที่ทำงานจริง (Proposed):** ไม่ตรวจบล็อกที่ไม่ได้ต่อใต้ setup/loop (ลายเทา R2) บล็อกที่ disabled และบล็อก Stage · บล็อกใต้ if/ลูปที่ไม่เคยถูกรันยังตรวจ (ตรวจแบบนิ่ง)
7. **นับข้อตามต้นเหตุ ไม่ตามจำนวนบล็อก:** LED เดียวที่ถูกลบแล้วมี 5 บล็อกอ้าง = 1 ข้อ ("ใช้ใน 5 บล็อก" กดแล้วไปบล็อกแรก/วนไปตัวถัดไป) · ต้นเหตุเดียวขึ้นข้อเดียว ลำดับเหตุที่แสดง (1) > (2) > (3) > (4) (ข้อ (4) แยกเสมอ)
8. **เด็กตั้งใจจำลองต่อ ถูกเตือนซ้ำทุกครั้งที่เริ่ม:** R17 ให้ตรวจใหม่ทุกครั้ง ไม่มี "ไม่ต้องเตือนอีก" (ต่างจาก ST-46) → รำคาญสำหรับ ป.3 ที่ยังต่อวงจรไม่เสร็จ (ผูก OQ55)
9. **ลำดับเมื่อกดส่งลงบอร์ด (ข้อเสนอ):** R17 ตรวจ (ไม่ต้องมีบอร์ด) → ตรวจการเชื่อม ST-30 → ST-46 เตือนต่อสายจริง → compile → ส่ง · R17 ก่อนเพราะแก้ได้ในจอ ไม่ต้องหาบอร์ด · compile error (OQ26) แยกจาก R17 (R17 = ตรวจความหมายของวงจร/อุปกรณ์ ไม่ใช่ไวยากรณ์)
10. **ท่ามาสคอต:** ท่าเดียวจากตาราง `../../../brand.md` §8 · ท่า #3 "คิด (?)" ผูกกับ "ตอบผิด" ใน Quiz เสี่ยงอ่านเป็นการลงโทษ · ท่า #6 "หลอดไฟ" (คำใบ้/สาเหตุ) หรือ #4 "แว่นขยาย" เหมาะกว่า (ข้อเสนอ → OQ53) · ขนาด ≤ ~150px · ข้อความกำกับท่าเสมอ
11. **แสดงความเป็นไปได้ของรหัส/ข้อความ (H9):** แต่ละข้อมีสาเหตุ+วิธีแก้ · รหัสข้อผิดพลาดตามกฎ context.md (ชื่อชั่วคราว E-CHK-xx) · ข้อความ 3 ภาษา +40% · ลิสต์ยาวต้องเลื่อนในแผง ไม่ล้นป๊อปอัป (จำนวนข้อสูงสุด → OQ53)
12. **ป๊อปอัปเป็น alertdialog:** โฟกัสเข้าปุ่มแรก · Esc ปิดได้ · ไม่หายเอง (ตาม R17) · รายการเป็นปุ่ม ≥ 44px · ไม่กะพริบ · อ่านจำนวนข้อให้ screen reader ก่อนลิสต์

## นิยามที่เสนอสำหรับ 4 กรณี (OQ49)
ฐาน: ตาราง "ขั้วสัญญาณ" ต่อชนิดอุปกรณ์ใน `R16.md` (LED, ปุ่ม, potentiometer, buzzer, servo, ไฟ RGB)

| ข้อ | นิยามที่เสนอ | หมายเหตุ/ช่องโหว่ |
|---|---|---|
| (1) ยังไม่ได้วาง | บล็อกที่ทำงานจริงอ้างอุปกรณ์ที่ไม่มีในวงจร (ถูกลบ) **หรือ** ช่องเลือกอุปกรณ์ยังว่าง | ตัดสินใจ: ช่องว่าง = ข้อ (1) ไม่ใช่ OQ26 |
| (2) ต่อสายไม่ครบ | อุปกรณ์ที่ **ถูกบล็อกที่ทำงานจริงอ้าง** มีขั้วจำเป็นอย่างน้อย 1 ขั้วไม่ถึง Uno (ขาสัญญาณ, 5V, GND ตามชนิด) | อุปกรณ์ที่วางไว้แต่ไม่มีบล็อกอ้างและต่อครึ่งเดียว ไม่แจ้ง (เด็กกำลังต่อ) ยกเว้นเข้าข้อ (4) · ต้องให้ผู้ใช้ยืนยันขอบเขตนี้ |
| (3) บล็อกกับขาไม่ตรง | ขาที่หาได้จากสายใช้กับบล็อกนั้นไม่ได้ ใน 4 กรณี: **3a** ขาไม่รองรับหน้าที่ (analogWrite ต้อง PWM 3/5/6/9/10/11 · analogRead ต้อง A0–A5) · **3b** ขั้วสัญญาณเดียวต่อถึงขา Uno มากกว่า 1 ขา (ไม่รู้ว่าขาไหน) · **3c** อุปกรณ์ต่างชนิดหรือต่างหน้าที่ (ออก/เข้า) ใช้ขา Uno ขาเดียวกัน · **3d** ขา 0/1 (ชน Serial/การอัปโหลด) ที่ใช้กับอุปกรณ์ | แก้ข้อสมมติเดิมของ OQ49: **servo ไม่ต้องต่อขา PWM** บน Uno (ไลบรารี Servo ใช้ขาดิจิทัลใดก็ได้) · ข้อมูลทั่วไป ต้องให้ dev ยืนยัน |
| (4) วงจรอันตราย | ดู §OQ51 | |

ช่องโหว่ที่ requirement ยังไม่ครอบ:
- **อุปกรณ์ชนิดเดียวกัน 2 ตัวต่อขาเดียวกัน (ขนาน):** ไม่ใช่ความผิดเสมอ · เสนอ: ไม่ใส่ในลิสต์ (ไม่ปิดกั้นส่ง) · ผู้ใช้ตัดสิน (OQ49)
- **ขั้วกลับ (LED, buzzer, servo):** LED กลับขั้วไม่เสียแต่ไม่ติดโดยไม่มีสัญญาณ (H1) servo กลับขั้วเสียได้ · ไม่ตรงกับ 4 ข้อ → เสนอเป็นข้อ (2) "ต่อไม่ถูกขั้ว" หรือ (4) ตามชนิด · ผู้ใช้ตัดสิน
- **tone() ชน PWM ขา 3/11 · Servo ชน PWM ขา 9/10:** edge ระดับ dev ไม่ใส่ใน MVP (บันทึกเป็นข้อสังเกต)
- **เส้นแบ่งข้อ (2) กับ (3):** ขั้วหนึ่งต่อ Uno และอีกขั้วไม่ต่อ = (2) ไม่ใช่ (3)

## ขอบเขตการตรวจวงจรอันตรายก่อนรัน (OQ51)
ตรวจก่อนรันได้ด้วย **การวิเคราะห์วงจรแบบนิ่งบน netlist + ตารางกฎ** ไม่ต้องจำลองไฟแบบแอนะล็อกเต็ม (ไม่ต้อง SPICE) · ใช้ตัวอย่างระดับ B (ปกติ/เกิน) ของ OQ1 ก็พอ

| ตรวจได้ (แน่นอน → ใส่ลิสต์) | ตรวจไม่ได้/ไม่แน่ (ไม่ใส่ลิสต์ · ปล่อยให้ R5 ตอนรัน) |
|---|---|
| ลัดวงจร 5V–GND (หรือ 3.3V–GND) ทางสายตรง/ผ่าน breadboard โดยไม่มีอุปกรณ์ | กระแสรวมทุกขาเกินงบ (ขึ้นกับโปรแกรม/จังหวะเวลา) |
| LED ในเส้นทางอนุกรมจากแหล่งจ่ายถึง GND ที่ไม่มีตัวต้านทาน | ค่ากระแสจริงที่ขึ้นกับ duty/PWM/เวลาของโปรแกรม |
| ตัวต้านทานค่าต่ำเกินเกณฑ์สำหรับ LED (คำนวณกฎโอห์มแบบเส้นเดียว · เกณฑ์ต้องกำหนด) | วงจรขนาน-อนุกรมผสมที่ไม่ใช่รูปแบบที่รู้จัก (ตัวจำลองบอก "ไม่แน่ใจ" ไม่ใช่ปลอดภัย) |
| ขาที่โปรแกรมตั้งเป็นเอาต์พุต (จากบล็อก) ต่อ GND/5V/ขาเอาต์พุตอื่นโดยตรง | สถานะที่ขึ้นกับปุ่มกด (ยกเว้นปุ่มคร่อม 5V–GND ตรง ตรวจเป็น "ลัดวงจรเมื่อกด" ได้) |
| servo/buzzer/LED ต่อขั้วไฟกลับ หรือขาสัญญาณ servo ต่อ 5V | สายและชิ้นส่วนจริงบนบอร์ด (DEC-27) · ค่าจริงของตัวต้านทานจริง · ไฟ USB จ่ายพอไหม |

เงื่อนไขและข้อควรระวัง:
- **ผลตรวจเดียวกับตอนรัน:** ตารางกฎ (ชนิดความเสียหาย → รหัส E-SIM / ข้อความ) ต้องเป็นชุดเดียวกับที่ R5 ใช้ตอนรัน ไม่เช่นนั้นเกิด "ตรวจผ่านแต่ตอนรันเสีย" หรือ "ตรวจเตือนแต่ตอนรันไม่เสีย" (H4 ความสม่ำเสมอ)
- **ตรวจผ่าน ≠ ปลอดภัยบนบอร์ดจริง:** ข้อความ ST-33/ST-46 ห้ามสื่อว่าวงจรผ่านการตรวจแล้วปลอดภัย (ตรวจเฉพาะวงจรในจอ)
- R5 ยังคงไว้เป็นตาข่ายสุดท้าย (ไม่เปลี่ยน ตามที่ R17 ระบุ)
- **ถ้า dev ทำ netlist ไม่ได้:** ข้อ (2), (3) และ R16 ทำไม่ได้ทั้งชุด (ไม่ใช่แค่ข้อ (4)) · ทางถอย: ข้อ (4) เหลือ 2 กรณีที่ออกแบบเผื่อใน D2 อยู่แล้ว (LED ไม่มีตัวต้านทาน, ลัดวงจร) · ต้องตอบก่อนส่ง dev → อัปเดต OQ1/OQ21
- **เวลา:** การตรวจนิ่งควรเสร็จทันที ไม่มีสถานะรอ · ถ้าวงจรใหญ่ช้า (dev ยืนยัน) ต้องมี loading (H1)
