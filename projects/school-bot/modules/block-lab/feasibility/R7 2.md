# Block Lab · Feasibility R7: Stage และมาสคอต

**ผล: ทำได้มีเงื่อนไข** (2026-10-21 · ruler) · ส่วนอื่นนอกจาก §ผลตรวจ ruler เป็นข้อมูลอ้างอิงจาก Architect ระบบเก่า (DEL-08 + CHG-08)

## ผลตรวจ ruler (2026-10-21)
UI ทำได้ (ได้ไฟล์มาสคอตแล้ว) ช่องโหว่ที่สำคัญคือ logic ของ stage:
- **stage ไม่ถูกแปลงเป็นโค้ด แต่ต้องทำงานพร้อมตัวจำลองที่รันโค้ด AVR:** ต้องมีทางส่งเหตุการณ์ stage ตามลำดับ/เวลาเดียวกับโปรแกรม · และ **บล็อก Stage ต้องไม่บล็อกเวลาโปรแกรม** (เช่น "พูด 2 วินาที" ที่หน่วงโปรแกรม) มิฉะนั้นจำลองกับบอร์ดจริงจะไม่ตรงกันเงียบ ๆ เมื่อส่งลงบอร์ดที่ข้าม Stage → OQ27 (dev)
- **ท่าอัตโนมัติ "วิ่ง" ตอนเคลื่อนที่ ชนกับบล็อก "เปลี่ยนท่า"** ใครชนะ · **stage รีเซ็ตตำแหน่ง/ท่าเมื่อเริ่มจำลองหรือไม่** → ผนวกใน OQ14
- **บล็อกพูด:** ไทยไม่เว้นวรรค ต้องมีกฎตัดบรรทัด · จีน/อังกฤษ · เด็กพิมพ์ข้อความเองด้วยคีย์บอร์ด → OQ14
- **แท็บ stage:** ต้องเห็นว่าจำลองหยุดเพราะเสีย/แก้ (ตัวบอกที่ SCR-16 ไม่ใช่เฉพาะ SCR-17) → OQ28
- **กะพริบ:** ท่า/พื้นหลัง stage ที่สลับถี่ตามโปรแกรมเด็ก → OQ34
- ภาพที่มีความหมายมี alt · ข้อความกำกับท่าเสมอ (AC-19) · สีส้มมาสคอตกับสีส้ม "กดแล้วหุ่นขยับ" (ปุ่มส่งลงบอร์ด) ต้องตัดสินตอนออกแบบ

## หน้าจอ
**SCR-18 Block Lab: stage (แท็บ)** · ผู้ใช้: นักเรียน · วัตถุประสงค์: ดูมาสคอตขยับตามโปรแกรม · FR-19, FR-32, AC-12, AC-18, AC-19
- ข้อมูลที่แสดง: ENT-27 มาสคอต (10 ท่า), ข้อความที่ตัวละครพูด, ตำแหน่ง
- การกระทำ: เริ่ม หยุด (ร่วมกับ SCR-17) · รีเซ็ตตำแหน่งตัวละคร
- สถานะ: ST-28 · **พร้อมออกแบบ: Yes** · รันพร้อมตัวจำลอง: กดเริ่มครั้งเดียว ทั้งตัวจำลองและ stage ทำงานพร้อมกัน แท็บแค่สลับมุมมอง (ผู้ใช้ 2026-10-21)
- มาสคอต: ไม่มีหน้าจอใหม่ · ห้ามใช้มาสคอตเป็นสื่อเดียวของความหมาย (AC-19) · ไม่ใช้บนเว็บครู

## มาสคอตบน stage (ตารางเต็มใน `../../brand.md` §8 · Proposed · Delegated → Designer)
ท่าเริ่มต้น/สวัสดี = โบกมือ · ดีใจ = ดีใจชูกำปั้น · สงสัย = คิด (?) · ค้นหา = แว่นขยาย · รัก = กอดหัวใจ · คิดออก = หลอดไฟ (ใช้กับสาเหตุอุปกรณ์เสีย ST-29 ได้) · ขณะตัวละครเคลื่อนที่ = วิ่ง · อ่าน = ถือแท็บเล็ต · เย่! = กระโดด + ดาว · เยี่ยม = ยกนิ้วโป้ง · บล็อก "เปลี่ยนท่า" เลือกจาก 10 ท่านี้เท่านั้น (DEC-30)
