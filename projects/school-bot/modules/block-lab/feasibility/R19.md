## ผลตรวจ ruler (2026-10-27)

**ทำได้**
- segmented tab 2 ตัวในส่วนหัว (ไอคอน + ข้อความ · role=tablist · ลูกศรซ้าย/ขวา) เป็น component มาตรฐาน · ค่าเริ่มต้นงานใหม่ = บล็อก มีค่าตั้งต้นชัด (H1) · ชื่อ 3 ภาษาสั้น (บล็อก/โค้ด · Blocks/Code · 积木/代码) ไม่ใช่ตัวทำให้ล้น
- ไม่ขัด app-shell R2: ส่วนหัวร่วมมีช่อง "เว้นว่าง" ระหว่างโลโก้กับ "เปลี่ยน" ซึ่ง R19 ใช้ช่องนี้ (Arm Lab ยังว่าง) · ควรให้ app-shell R2 ระบุว่าช่องนี้ "lab ใส่ตัวควบคุมของตัวเองได้" (แจ้ง session หลัก · ไม่ block)

**เงื่อนไข (ต้องอยู่ใน design/handoff)**
1. **เปิดใช้แบบกดยืนยัน (manual activation) ไม่ใช่สลับทันทีเมื่อกดลูกศร:** การสลับโหมดมีผลข้างเคียง (แปลงโค้ด · เปิด dialog เตือนเมื่อกลับจากโค้ดที่แก้แล้ว · หยุดจำลอง) ตาม ARIA APG ลูกศรย้ายโฟกัส · Enter/Space สลับ · กันการเปิด dialog ซ้อนจากการกดลูกศรผ่าน (H5, UD5)
2. **สถานะระหว่างทำงาน (H1/H5):** กำลังจำลอง → สลับโหมด = หยุดจำลองก่อน (นับเป็น "แก้" ตาม R10) และแจ้งในแถบเดิม "หยุดเพราะแก้ไข" · **กำลังแปลงโค้ด/ส่งลงบอร์ด → tab ปิดใช้แบบ `aria-disabled` + tooltip บอกเหตุผล** (ห้ามสลับเนื้อหาที่กำลังส่ง) · dialog/popover ของส่วนหัวเปิดอยู่ ■ หยุดทั้งหมดยังกดได้ (app-shell R5)
3. **ความกว้างที่ 1440 (OQ150):** ช่องว่างที่ผู้ใช้วัด ≈ 167px กับ tab ≈ 178px (ประมาณ) ตึงอยู่แล้ว และชิปคลาวด์ (แสดงเมื่อผิดปกติ) ทำให้ช่องหดลงอีก · fallback ไอคอนล้วน 44×44 + aria-label/tooltip ยอมรับได้เฉพาะเมื่อพื้นที่ไม่พอ (ข้อความหายตามสถานะคลาวด์ = layout เปลี่ยนเอง H4) · ทางที่เสถียรกว่า: ให้ช่องชื่องานเป็นตัวหด (min 150 · ตัด … + ชื่อเต็มใน tooltip) ก่อน tab · หน้าต่างกว้างกว่า 1440 (app-shell R11 ใหม่) ช่องนี้กว้างขึ้นเอง ปัญหาอยู่ที่ขั้นต่ำเท่านั้น
4. **ข้อมูลของงาน (ผูก my-work · X26 · OQ154):** "โหมดล่าสุดบันทึกกับงาน" + R3 "งานของแต่ละโหมดแยกกัน" = งานหนึ่งต้องเก็บ (ก) โปรแกรมบล็อก (ข) โค้ดที่แก้ (ถ้ามี · OQ147) (ค) โหมดล่าสุด · my-work R10/R2/R5 ยังไม่ระบุทั้งสามอย่าง → session หลักต้องแก้ my-work ก่อน handoff · เปิดงานเก่าที่ไม่มีค่าโหมด = บล็อก
5. **โหมดกำหนดว่าอะไรถูกจำลอง/ส่ง (X25 · OQ152):** ต้องเห็นชัดว่ากำลังจำลอง/ส่ง "บล็อก" หรือ "โค้ด" (tab ที่เลือก = แหล่งของโปรแกรม) · ถ้ากติกาต่างจากนี้ ต้องมีป้ายบอกที่ปุ่มส่ง
6. **คีย์ลัด:** ถ้ามีคีย์ลัดสลับโหมด ต้องไม่ชนกับตัวแก้โค้ด (Ctrl+/ = comment ฯลฯ) และคีย์ของพื้นที่ต่อบล็อก (+ − 0) · Mac: คำสั่งสลับโหมดควรอยู่ในเมนู View ของ menu bar ระบบด้วย (HM3) ถ้าแอปมี menu bar ระบบ

**ไม่ครอบคลุมใน requirement (เพิ่มใน OQ ที่มีอยู่ ไม่เปิดใหม่)**
- ปุ่ม "สร้างโค้ดจากบล็อกใหม่" ในโหมดโค้ด (เมื่อเก็บโค้ดที่แก้ไว้ บล็อกที่แก้ทีหลังไม่สะท้อน) → OQ147
- เลิกทำ (R2 60 ขั้น) ไม่ข้ามโหมด: การสลับโหมดไม่ใช่ขั้นที่เลิกทำได้ (dialog คือตัวกัน) · ตัวแก้โค้ดมี undo ของตัวเอง → บันทึกใน OQ152
