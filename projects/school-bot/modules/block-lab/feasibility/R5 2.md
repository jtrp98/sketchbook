# Block Lab · Feasibility R5: ความเสียหายสมจริงของอุปกรณ์จำลอง

**ผล: ทำได้มีเงื่อนไข** (2026-10-21 · ruler) · ส่วนอื่นนอกจาก §ผลตรวจ ruler เป็นข้อมูลอ้างอิงจาก Architect ระบบเก่า

## ผลตรวจ ruler (2026-10-21)
ออกแบบ "อุปกรณ์เสียทั่วไป 1 ชุด + 2 กรณี" ได้เลย (ไม่ block ออกแบบ) ช่องโหว่:
- **ลัดวงจร: อะไรคืออุปกรณ์ที่เสีย:** ลัดวงจร 5V–GND ไม่มีอุปกรณ์ปลายทางเสียจริง (สายหรือบอร์ด) แต่ AC-16/EC-08 กำหนดปุ่ม "เปลี่ยนอุปกรณ์ใหม่" เสมอ → ต้องกำหนดวัตถุที่แสดงเสีย + ปุ่มที่ใช้ (เช่น ไฮไลต์สายที่เกี่ยว + "เอาสายนี้ออก") → OQ28
- **เปลี่ยนอุปกรณ์แล้วเสียซ้ำทันที** ถ้าสาเหตุ (ไม่มีตัวต้านทาน) ยังอยู่ · ต้องบอกวิธีแก้ก่อนปุ่มเปลี่ยน และข้อความรอบ 2 ต้องไม่โทษเด็ก → OQ28
- **เสียหลายอุปกรณ์พร้อมกัน** ต้องกำหนดการแสดง (รายการ/ตัวแรก) → OQ28
- **ผู้ใช้อยู่แท็บ stage:** สถานะเสียอยู่ใน SCR-17 ต้องมีตัวบอกที่เห็นจากทั้งสองแท็บและที่ SCR-16 (ไอคอน + ข้อความ) และต้องระบุว่าเสียแล้วหยุดทั้งตัวจำลองและ stage (R10) → OQ28
- **"ห้ามกะพริบ" ใช้กับสถานะเสียเท่านั้น** แต่ LED ที่กะพริบตามโปรแกรมเด็ก (delay 50 ms = 10 ครั้ง/วินาที) เป็นความเสี่ยง WCAG 2.3.1 เช่นกัน → OQ34
- **H9:** ข้อความมี 2 กรณี ถ้า OQ1 ตอบ A (หลายชนิด) ต้องมีข้อความสำรองทั่วไป + รหัสข้อผิดพลาด (เช่น E-SIM · กฎรหัส error ใน context.md) · ตอนนี้ requirement ไม่ระบุรหัส
- ถ้า OQ1 ตอบ B: ค่ากระแสแสดงเป็น "ปกติ/เกิน" เท่านั้น ห้ามแสดงตัวเลขที่ไม่ได้คำนวณจริง

## DEV-Q13 (Open · OQ-18)
**คำถาม:** ตัวจำลอง: ไลบรารีจำลอง AVR จำลองเฉพาะ MCU · ต้องมีส่วนคำนวณวงจรเพิ่มเพื่อหาค่ากระแสและความเสียหายไหม · อุปกรณ์ใดใน ARC-I09 เสียได้ ด้วยเงื่อนไขอะไร (เช่น LED ไม่มีตัวต้านทาน, ลัดวงจร 5V–GND, ขาจ่ายกระแสเกิน, servo ต่อผิดขา) · แสดงค่าไฟ/กระแสได้ระดับไหน (ค่าต่ออุปกรณ์ / แค่ปกติ–เกิน) · dev ส่ง "รหัสสาเหตุ" ให้ UI เลือกข้อความเด็กได้ไหม
- **A (คำนวณวงจรได้):** ST-29 ครบหลายชนิด + แสดงค่ากระแสต่ออุปกรณ์
- **B (จำกัด):** เฉพาะ LED ไม่มีตัวต้านทาน + ลัดวงจร · ค่ากระแสแสดงเป็นระดับ (ปกติ/เกิน) · ชนิดอื่นไม่เสีย
- สถานะ: **Open** (ถาม dev)

## ข้อกำหนดตรวจ (WCAG 2.3.1 · AC-16)
สถานะเสียต้องไม่กะพริบเกิน 3 ครั้ง/วินาที (ไม่กะพริบเลย) · ไม่ใช้สีอย่างเดียวบอกว่าเสีย (ไอคอน + ข้อความ)
