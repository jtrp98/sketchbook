## ผลตรวจ ruler (2026-10-28 · R3/R17/R9 โหมดโค้ด ตาม OQ161)

**ข้อขัดในเอกสาร (X31 · session หลักแก้ข้อความ):** R3 ส่วนแก้ 2026-10-26 ("เช็ก syntax realtime + hint") และ 2026-10-27 (ค) (ชิป "ปัญหา N ข้อ" · ตัวเช็ก realtime) · "dialog" กลับโหมดบล็อก · R9 "ตัวเช็ก syntax realtime ไม่ปิดกั้นการส่ง" และ "(2026-10-22) ส่งลงบอร์ดถูกปิดกั้นเมื่อ R17 พบปัญหา" (ต้องเติม "เฉพาะโหมดบล็อก") · AC-20 "When พิมพ์ผิดไวยากรณ์ Then เห็นบรรทัดที่ผิด" (ตอนนี้เห็นหลังแปลงโค้ดใน Output เท่านั้น) · R17 (OQ152 ข) "โหมดโค้ดตรวจ (2)(4)" vs แก้ 2026-10-28 "ไม่ปิดกั้น" → ไม่บอกว่าป๊อปอัปยังขึ้นไหม (→ OQ167)

**เงื่อนไข:**
1. **คีย์บอร์ด (WCAG 2.1.2):** §11.18 ให้ Tab = ใส่คำจาก autocomplete · ตัวแก้โค้ดปกติ Tab = ย่อหน้า → ต้องกำหนดทางออก: Tab ใส่คำเฉพาะตอนรายการเปิด · Esc ปิดรายการ · Esc แล้ว Tab (หรือ Ctrl+M) = ออกจากตัวแก้ · บอกวิธีออกใน aria-describedby
2. **ไม่ปิดกั้นส่ง (H9):** compile ไม่ผ่าน = ไม่มีอะไรถูกส่ง ข้อความต้องบอก "ยังไม่ได้ส่ง บอร์ดยังใช้โปรแกรมเดิม" · ลิ้นชักหุบอยู่ → เปิดแท็บ Output เอง + ประกาศ (role=alert ครั้งเดียว) ไม่ใช่แค่ต่อท้าย log (polite) · กดบรรทัดใน Output → โฟกัสตัวแก้ที่บรรทัดนั้น
3. **H1/H5 ที่หายไปพร้อมแผงปัญหา:** เด็กไม่รู้ว่าผิดจนกด เริ่ม/ส่ง → ยอมรับได้ (แบบ Arduino) แต่ควรคงเครื่องหมายบรรทัดที่ compile ไม่ผ่านไว้ในตัวแก้จนกว่าจะแก้/แปลงใหม่ (ไอคอน + ข้อความ ไม่ใช่สีอย่างเดียว)
4. autocomplete: ชื่อคำสั่งอังกฤษ + คำใบ้ไทยสั้น · `role=listbox` + `aria-activedescendant` · ไม่เปิดเองระหว่าง IME ภาษาไทยกำลังประกอบคำ (compositionstart)
5. popup ยืนยันกลับโหมดบล็อกใต้ tab (§11.9 alertdialog) ทำได้ · tab เป็นไอคอนล้วน popup ต้องมีหัวข้อเป็นข้อความ (ดู R19)

**ผล: ทำได้มีเงื่อนไข** (2026-10-27 · ruler · ตรวจใหม่ส่วนที่แก้ 2026-10-26: โหมดโค้ดแก้ได้ · ไม่ sync กลับ · เช็ก syntax realtime · แท็บโค้ดล้วน · ส่วนอ่านอย่างเดียวในโหมดบล็อกใช้ผล 2026-10-21) · ส่วนอื่นนอกจาก §ผลตรวจ ruler เป็นข้อมูลอ้างอิงจาก Architect ระบบเก่า

## ผลตรวจ ruler (2026-10-27 · OQ139, OQ144, OQ147, OQ148)

**ทำได้:** ตัวแก้โค้ดในแอป (เลขบรรทัด · undo ของตัวเอง · ตัวชี้ปัญหาที่บรรทัด) เป็นของที่มีไลบรารีพร้อม · แปลงบล็อก→โค้ดทางเดียวตอนสลับใช้ตัวสร้างโค้ดเดิมของ R3 · แท็บ "โค้ด C++" ในโหมดบล็อกเป็นโค้ดล้วนอ่านอย่างเดียว (OQ139) ไม่ขัดข้อใด

**ข้อขัดในตัว requirement (session หลักแก้ข้อความ · ไม่ต้องถามผู้ใช้ · X23)**
- ประโยคแรกของ R3 "อ่านอย่างเดียว ตรงกับบล็อก แก้ไม่ได้" · AC-11 "เห็น Arduino C++ ที่ตรงกับบล็อกและแก้ไม่ได้" · เป้าหมาย module "(โค้ด C++ อ่านอย่างเดียว)" (requirements.md + INDEX) ขัดกับโหมดโค้ดที่แก้ได้ → ต้องระบุว่า "อ่านอย่างเดียว" ใช้กับแท็บโค้ดในโหมดบล็อกเท่านั้น และเพิ่ม AC ของโหมดโค้ด (Given แก้โค้ดแล้ว When กลับโหมดบล็อก Then เห็นคำเตือน · When พิมพ์ผิด Then เห็นบรรทัดที่ผิด + วิธีแก้ภาษา ป.3–4)

**เงื่อนไข**
1. **โหมดโค้ดกับ R9/R10/R16/R17/R7 ยังไม่นิยาม (X25 · OQ152 · block `approved`):** requirement เดิมเขียนสำหรับโปรแกรมบล็อกทั้งหมด
   - จำลอง/ส่ง: ใช้โปรแกรมของโหมดที่เลือกอยู่ (ข้อเสนอ) · ตัวจำลองรัน AVR จากโค้ดที่ compile แล้ว จึงรันโค้ดที่เด็กพิมพ์ได้จริง (ไม่ต้องตัวตีความใหม่) แต่ **เริ่มจำลองในโหมดโค้ดต้อง compile ก่อนทุกครั้ง** → สถานะ "กำลังแปลงโค้ด" และ "แปลงโค้ดไม่ผ่าน (บรรทัด N)" ของ R9 ต้องใช้กับการเริ่มจำลองด้วย (H1/H9 · เดิมขาดอยู่แล้วตาม §สรุป H1 ใน feasibility.md)
   - R17 ตรวจก่อนรัน: ข้อ (1) และ (3) อ้าง "บล็อกที่อ้างอุปกรณ์" ซึ่งไม่มีในโค้ด · เหลือ (2) อุปกรณ์ต่อสายไม่ครบ และ (4) วงจรอันตราย · การจับเลขขาในโค้ด (`digitalWrite(7, …)`) กับสายจริงทำได้เฉพาะเลขตรง ๆ ไม่ครอบตัวแปร → ข้อเสนอ MVP: ตรวจ (2)(4) + compile เท่านั้น
   - R16 dropdown อุปกรณ์ไม่มีในโหมดโค้ด · โค้ดที่แปลงมาเป็นเลขขา (เด็กต้องรู้ว่าขาไหนต่ออะไร) → ข้อเสนอ: ใส่คอมเมนต์ชื่ออุปกรณ์ตอนแปลง (`// LED แดง 1`) (เคยเสนอใน OQ139)
   - R7 stage: บล็อกตัวละครไม่มี C++ → ในโหมดโค้ด stage ไม่ขยับ ต้องบอกบน stage ว่า "ตัวละครใช้ได้ในโหมดบล็อก" ไม่ใช่ปล่อยนิ่งเงียบ (H1)
   - R10 "แก้ระหว่างจำลอง → หยุด": พิมพ์ในตัวแก้โค้ด 1 ตัวอักษร = แก้ → หยุด (ข้อเสนอ: ใช้กติกาเดียวกัน)
2. **ตัวเช็ก syntax ปิดกั้นส่ง (OQ148 · X12 เดิม):** ตัวตรวจ realtime ที่ไม่ใช่ compiler จะเตือนผิด/พลาดได้ (crayon ระบุเอง) · ถ้าใช้เป็นตัวปิดกั้นส่ง เด็กที่เขียนถูกจะติดทางตันไม่มีทางข้าม (H9 · UD5) · **ข้อเสนอ:** realtime = คำใบ้/รายการปัญหาเท่านั้น · ตัวปิดกั้นส่งจริง = ผล compile ตอนกดส่ง/เริ่มจำลอง (สถานะ "แปลงโค้ดไม่ผ่าน" ของ R9 มีอยู่แล้ว) + R17 ข้อที่ใช้ได้ · ชิป "ปัญหา N ข้อ" นับเฉพาะที่ compiler ยืนยัน หรือแยกป้าย "อาจผิด" · ถ้า dev ทำ realtime ด้วย compiler จริงได้ (DEV-Q ใน OQ144) ปัญหานี้หายเอง
3. **ข้อความ error ของ compiler ต้องแปลงเป็นภาษา ป.3–4:** ข้อความ avr-gcc ดิบเป็นอังกฤษเทคนิค · ต้องมีตารางจับคู่ error ที่พบบ่อย → ข้อความเด็ก + บรรทัด + รหัส (กฎ context.md) และข้อความกลางสำหรับ error ที่ไม่อยู่ในตาราง (ไม่แสดงข้อความดิบเป็นหลัก) · 3 ภาษา +40% → dev/Designer
4. **a11y ตัวแก้โค้ด (WCAG 2.1.2 · UD2 · HF คีย์บอร์ด):** Tab ในตัวแก้ใช้ย่อหน้า → ต้องมีทางออกจากตัวแก้ด้วยคีย์บอร์ดที่บอกไว้ (เช่น Esc แล้ว Tab หรือ Ctrl+M สลับโหมด Tab) ไม่งั้นเป็นกับดักคีย์บอร์ด · ตัวชี้ปัญหาที่บรรทัดต้องเป็นไอคอน + ข้อความ (R3 ระบุแล้ว) และ screen reader อ่านได้ (รายการปัญหาโฟกัสได้ กดแล้วไปบรรทัด) · ตัวอักษรโค้ด ≥ 16px · สี syntax highlight ทุกสี ≥ 4.5:1 บนพื้นตัวแก้ · ไม่ประกาศ aria-live ทุกครั้งที่พิมพ์
5. **Mac menu bar (HM3):** ตัวแก้โค้ดต้องใช้ Cut/Copy/Paste/Undo/Select All ผ่านเมนู Edit ของระบบได้ (และคีย์ลัด Cmd) แม้แอปใช้แถบหน้าต่างของตัวเอง
6. **ขอบเขตที่ต้องบอก dev:** ตัวอักษรไทยในโค้ด (ชื่อตัวแปรไทยไม่ใช่ identifier · ในสตริงได้) · `#include` ไลบรารีนอกชุดที่ฝังใน installer ทำไม่ได้ (ข้อความบอก) · โปรแกรมใหญ่เกินหน่วยความจำ Uno = ส่งไม่ได้ (ข้อความ) · ขนาดโค้ด/จำนวนบรรทัดสูงสุดในตัวแก้
7. **ข้อมูล (OQ147 + OQ154):** ต้องเก็บโค้ดที่แก้ + ธง "แก้แล้ว" กับงาน (my-work) · ถ้าเก็บไว้ ควรมีทาง "สร้างโค้ดจากบล็อกใหม่" (ยืนยันก่อนทับ) ไม่งั้นโค้ดค้างเก่าโดยเด็กไม่รู้ (H1)

- **โปรแกรมไม่สมบูรณ์** แผงโค้ดแสดงอะไร (ช่องว่าง) → OQ26
- **ชื่อตัวแปรไทย/จีน** ไม่ใช่ identifier ที่ avr-gcc ใช้ได้ → OQ25
- แผงโค้ดสำหรับ ป.1 อ่านไม่ออก ต้องย่อ/ซ่อนได้ ไม่กินพื้นที่หลัก (ดู OQ33)
