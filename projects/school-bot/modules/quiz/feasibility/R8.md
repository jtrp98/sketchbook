## R8: สถานะระบบ

**ผล: ทำได้มีเงื่อนไข (2026-11-06) · พร้อม: Yes (สถานะที่ระบุแล้ว) / Assume (สถานะที่ต้องเพิ่มด้านล่าง)** (OQ16, OQ42, OQ57 · answered OQ43, OQ54 · ผูก OQ34)

**ทำได้ (ตรวจแล้วไม่ขัดกัน):**
- skeleton ระหว่างโหลดค่า access (ห้ามแสดงล็อกแล้วค่อยปลด) · โหลด access ไม่ได้ = ล็อกทุกใบ + ลองอีกครั้ง (OQ43) · ตรงกับ R7 "(cloud ล้ม/ออฟไลน์และไม่มีแคช)" · ถ้ามีแคชของบัญชีนี้ใช้แคช
- โหลดเนื้อหาไม่สำเร็จ (ST-12) แยกจากโหลดความคืบหน้าไม่ได้ (ห้ามแสดงเป็นครั้งแรก/ดาว 0) · ใช้กับ config ของ item เกมด้วย (config เกมมาจาก cloud เหมือนข้อแบบฝึก · ดึงทั้งด่านก่อนเริ่ม)
- ออกกลางด่าน (ST-14) ใช้กับทุกชนิดด่าน (OQ54) · game-platform ตั้ง `save.resume: false` ของบทเรียนแล้ว (06-config-schema หมายเหตุ) ไม่ขัด
- ออฟไลน์/กำลัง sync ที่แถบหน้าต่าง (app-shell R3) · ออฟไลน์เปิดด่านที่ไม่มีแคช → OQ16 (เดิม)

**ขัดกัน (ต้องแก้ requirement · ไม่ต้องถาม):**
1. **"ครั้งแรกของแต่ละ level → ชี้ไปด่านที่ 1 ปุ่มเริ่ม (ST-09)" ขัดกับ R7 กรณีไม่รู้ชั้น** (Level 1 เปิดแต่ทุกด่านล็อก) · อ่านตามตัวอักษร เด็กที่ไม่รู้ชั้นเห็นปุ่มเริ่มที่กดไม่ได้ · แก้ R8: "ครั้งแรก (ยกเว้นกรณีไม่รู้ชั้น R7)" และระบุว่ากรณีไม่รู้ชั้นแผนที่ไม่มีด่าน "กำลังเรียน" แสดงแถบแจ้งเตือนแทนปุ่มเริ่ม
2. **ST-14 "ความคืบหน้าในด่านนี้จะหาย" ไม่จริงทั้งหมดในด่านที่มีวาดหุ่น:** ถ้ากด "เสร็จแล้ว" ไปแล้ว ผลงานวาดถูกบันทึกที่งานของฉัน (ST-14 เอง) แล้วออกก่อนจบข้อแบบฝึก → ผลด่านหาย แต่ผลงานวาดไม่หาย · ข้อความยืนยันต้องไม่บอกว่า "ทุกอย่างหาย" (H1) · แก้ ST-14: ข้อความยืนยันบอกเฉพาะผลของด่านนี้ และบอกว่าผลงานที่กด "เสร็จแล้ว" อยู่ในงานของฉัน (ถ้อยคำ Designer เสนอตาม brand §7) · ผลต่อ my-work → OQ58

**สถานะที่ยังขาดใน R8 (ค้างจากรอบ 2026-11-01 + ใหม่จากด่านเกม · เพิ่มใน R8 ได้โดยไม่ต้องถาม):**
- **โหลดภาพแผนที่ไม่สำเร็จ/ช้า** (ค้าง): พื้นเรียบ + node ใช้งานได้ ภาพไม่ block การเล่น · โหลดทีละเทอม (ตาราง R → D ใน INDEX ระบุว่ายังขาด)
- **session หมดอายุกลางด่าน** (ค้าง): เล่นต่อได้ ผลเขียนลงเครื่อง (R5) ขอ login ใหม่ตอนส่งขึ้น cloud · ห้ามเด้งออกจากด่าน (H3)
- **ภารกิจต้องใช้โปรแกรมรุ่นใหม่กว่า** (ใหม่ · ด่านเกม): config ของ item เกมมี `schema_version`/engine (06-config-schema) · ถ้าบริษัทเผยแพร่ด่านที่ใช้ความสามารถของ engine รุ่นใหม่ เครื่องที่ยังไม่อัปเดตเล่นด่านนั้นไม่ได้ และเพราะไม่มีข้ามด่าน (R7) เด็กติดทั้ง level (H9) · ต้องมีสถานะ "อัปเดตโปรแกรมเพื่อเล่นภารกิจนี้" แยกจากโหลดไม่สำเร็จ (ผูก module update-software ที่จะเปิด) + ข้อกำหนดเนื้อหา: cloud ห้ามส่งด่านที่รุ่นแอปนั้นเล่นไม่ได้ให้เป็นด่านถัดไปโดยไม่มีข้อความนี้
- **ข้อมูลด่านผิด** (ใหม่): ด่านผสมที่ข้อแบบฝึก ≠ 3 / ด่านเกมไม่มีเป้าหลัก (R7 "ระบบตรวจได้เสมอ") · เป็นข้อกำหนดฝั่งเผยแพร่เนื้อหา (ตรวจก่อนเผยแพร่ ห้ามปล่อย) · ฝั่งแอปถ้าเจอ ใช้สถานะ "โหลดเนื้อหาไม่สำเร็จ" (ST-12) ไม่คำนวณดาวผิด
- **จบ level** (ค้าง): edge case มีแล้ว (เส้นชัย + ไปที่ด่านสุดท้าย) · การ์ด Level ใช้ "ผ่าน y/y" ตาม R12 + ข้อความ "จบแล้ว" ไม่ใช้สีอย่างเดียว

**ช่องว่างที่ผู้ใช้ต้องตัดสิน:**
- **เพิ่ม N (ครูเปิด level เพิ่ม) มีผลเมื่อไร** → OQ57 · R7 กำหนดเฉพาะลด N (ล็อกเมื่อ login ครั้งถัดไป) · ผลต่อ R8: ค่า access โหลดตอนไหน (ตอน login อย่างเดียว หรือทุกครั้งที่เปิดหน้าเลือก Level) และ skeleton เกิดที่ไหน
- level ที่เข้าได้แต่ยังไม่มีเนื้อหา → OQ42 (เดิม · ยังเปิด)

**ผลต่อ module ที่พึ่งพา:** `app-shell` R5 dialog ปิดโปรแกรมยังไม่รู้สถานะ "กำลังทำแบบฝึก/เล่นเกมในบทเรียน" (OQ34 เดิม · ทางออกกลางด่านต้องดักทุกทาง H5) · app-shell R6 ยังไม่ระบุว่า login คืนชั้น (OQ28 · เงื่อนไขก่อน dev)

**DS gap:** `DS gap: skeleton (โครงรอโหลด) ของการ์ด Level และแผนที่ · ใช้ที่ QuizLevelsV1 (D1) ระหว่างโหลดค่า access/ความคืบหน้า, QuizMapV1 (D2) · ใกล้เคียงที่สุดใน DS: ไม่มี (Card สถานะปิดใช้ = ผิดความหมาย ดูเหมือนล็อก · spinner `sb-spin` ใช้ได้แต่ R8 กำหนด skeleton)` · ไม่ทำให้ทำไม่ได้ ต้องเติมก่อนแก้ D1

Heuristic: H1 (skeleton ไม่หลอกว่าล็อก · ข้อความยืนยันออกไม่บอกเกินจริง), H3 (session หมดไม่เด้งออก), H5 (ดักทางออกทุกทาง), H9 (ด่านต้องใช้รุ่นใหม่ = ทางตัน) · `knowledge/universal-design.md` (เด็กเล็กไม่ติดทางตัน)
