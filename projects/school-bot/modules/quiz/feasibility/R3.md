### ข้อที่ถ้อยคำขัด/ตกหล่น (session หลักแก้ได้ไม่ต้องถาม)
1. R3 ยังมีประโยค "ตอบแล้วกด 'ตรวจ' → เห็นถูก/ผิด + เฉลยสั้น → ไปข้อต่อ" ก่อนกติกาลองซ้ำ · ขัดกับกลุ่ม "ซ้ำ" (ผิดแล้วต้องใบ้ + ตอบใหม่) → เขียนเป็น "ถูก = เฉลยเหตุผลสั้น แล้วไปต่อ · ผิด = ตามกติกาลองซ้ำ"
2. R3 ไม่ระบุว่าตอบถูกในครั้งที่ 2–3 ได้เห็นเฉลยเหตุผลหรือไม่ (PR-A7 "ถูกก็บอกว่าทำไมถูก") → ระบุ
3. R3 "การกระทำ: ตอบ, ตรวจ, ออก" → เพิ่ม "ไปต่อ" (หลังใบ้ขั้น 3/เฉลย) และการแก้คำตอบเดิมหลังผิด
4. R3 กลุ่ม (ก)–(ง) vs กิจกรรมเสริม: ระบุว่า `14`/`15`/`16` นับ x/n (จบข้อ = กดไปต่อ/เสร็จแล้ว) หรือไม่ (ตาม OQ77)
5. R4 ระบุ "n = 0" เฉพาะเกมล้วน → เพิ่ม n = 0 ที่ไม่มีเกม (ผ่านเมื่อจบทุก item · ดาว "ไม่มี") ตาม OQ77
6. ENT-10 ยังมีแค่ "ข้อถูก/ทั้งหมด" → เพิ่มตาม OQ74 ถ้าผู้ใช้เลือกเก็บรายข้อ
7. คำสามคำใกล้กัน: "ลองซ้ำ" (R3) · "ลองใหม่" (ถ้อยคำมาสคอต R9) · "เล่นใหม่/เล่นอีกครั้ง" (ปุ่มระดับด่าน R4/OQ30) → ระบุใน R9/R3 ว่าระดับข้อ **ไม่มีปุ่ม** (หลังใบ้ แก้คำตอบแล้วกด "ตรวจ" ซ้ำ) ส่วนปุ่มระดับด่านใช้ "เล่นอีกครั้ง" เท่านั้น · ถ้อยคำสุดท้ายตาม brand §7

### คำตอบ Q-I: ต้องเก็บ "จำนวนครั้ง/ใบ้ที่ใช้ต่อข้อ" หรือไม่
ไม่ใช่เงื่อนไขของ UI/ดาว (ดาวคิดจากข้อถูก/ผิดเท่านั้น) · เป็นการตัดสินเรื่องข้อมูล · เก็บทีหลังไม่ได้ (ผลที่ไม่ได้เก็บย้อนไม่ได้) · ตัวเลือก (OQ74):
- ก) **ไม่เก็บ** (ENT-10 เดิม: ข้อถูก/ทั้งหมด + ดาว) · เบาสุด · ข้อเสีย: แยก "ถูกครั้งแรก" กับ "ถูกครั้งที่ 3" ไม่ได้ ตรวจดาวย้อนไม่ได้ ครูไม่เห็นข้อที่เด็กติด (ถ้าเว็บครูอยากทำภายหลัง)
- ข) **เก็บรายข้อใน log ตอนจบด่าน** `{item_id คงที่, ถูก/ไม่ถูก, ครั้งที่ใช้ (1–3), ใบ้ขั้นสูงสุดที่เห็น (0–3)}` ในผลการเล่นเดียวกัน (ENT-10 + คิว sync เดิม · ไม่มีคิวใหม่) · ไม่แสดงบน UI นักเรียน (ไม่เป็นคะแนน) · เว็บครูเลือกใช้ phase 2 · ข้อเสีย: ผลหนักขึ้นเล็กน้อย (≤ 8 ข้อ × 4 ค่า) · `item_id` ต้องคงที่ข้ามเวอร์ชันเนื้อหา (ข้อกำหนด dev เพิ่ม) · ไม่เพิ่มข้อมูลส่วนบุคคล (NFR-05 ผ่าน) · **ruler แนะนำ**
- ค) เก็บยอดรวมต่อด่าน (ครั้งรวม/ใบ้รวม) · เล็ก · บอกไม่ได้ว่าข้อไหน
ผลต่อ module อื่น: `teacher-web` (เฉพาะเมื่อเลือกแสดง · phase 2 หรือ OQ22) · `my-work` ไม่กระทบ · game-library ไม่ต้องเก็บ (GP ไม่มี "ครั้ง")

## R4: ดาว 0–3

**ผล: ทำได้มีเงื่อนไข · พร้อม: Yes (สูตร/เกณฑ์) / Wait (OQ75, OQ77 กระทบความหมายของดาว)**
- นิยาม "ข้อถูก" ใหม่ไม่ขัดสูตร จำนวนเต็ม `ถูก×100 ≥ 60×n` ใช้ได้ต่อ (ตารางด้านบน) · ผลรอบ `R4.md` ยังใช้ได้
- **ความสมเหตุสมผลของเกณฑ์ (ผลรอบนี้ ไม่ใช่ข้อห้าม):** คำนวณกรณีเดาล้วน (ไม่ใช้ใบ้ ตัดตัวเลือกที่ผิดออกหลังผิด): ข้อ 4 ตัวเลือกใน 3 ครั้ง = 75% ต่อข้อ → n=5 เดาแล้วได้ ≥60% (ผ่านด่าน) ราว **90%** และได้ 5/5 (3 ดาว) ราว 24% (เทียบ `01-choose-4` ครั้งเดียว เดาแล้วผ่านราว 10%) · ข้อ 2 ตัวเลือก (`02`, `10` และเลือกทีละขั้น) 2 ครั้ง = **100%** ถ้าตัวเลือกที่ผิดถูกปิดหลังผิด → "กันการเดา" (PR-A44) ไม่เป็นจริง และ `02` ให้ข้อถูกเสมอ → OQ75
- ด่านผสม: ดาว = จำนวนข้อถูก (R4) ไม่ใช่สูตร 60/80/100 (n=3: 2/3 ได้ 2 ดาว แทน 1 ดาวตามสูตร) · ตั้งใจแล้ว (OQ50) · R4 เขียนไว้ชัดแล้ว ไม่ต้องแก้
- n ตัดสิน = 0 โดยไม่มีเกม: ดู R3 ข้อ 5 / OQ77

## R9: มาสคอต (หลอดไฟ · ถ้อยคำ "ลองใหม่")

**ผล: ทำได้ · พร้อม: Yes** · ข้อควรแก้ถ้อยคำ
- **ท่าชนกัน:** เหตุการณ์ "ตอบผิดครั้งที่ 1–2 ในข้อกลุ่มซ้ำ" ได้ทั้ง ท่าตอบผิด (คิด ?) และท่าใบ้ (หลอดไฟ) พร้อมกัน → R9 ต้องระบุท่าต่อเหตุการณ์: ผิดแล้วมีใบ้ = ท่าหลอดไฟ + ข้อความ · ผิดครั้งสุดท้าย/`01-choose-4` ผิด = ท่าคิด ? + เฉลย · ไม่เปลี่ยนท่าซ้ำหลายท่าในจอเดียว (Designer เสนอแล้วถาม · PR-A22)
- "ลองใหม่" ใช้ได้เฉพาะข้อความในข้อลองซ้ำ ไม่ใช่ปุ่ม (R3 ข้อ 7) · `01-choose-4` ผิดห้ามมีข้อความชวน "ลองใหม่" (ไม่มีให้ลอง · H1/H5 ไม่หลอกให้กดหา)
- **ใบ้ในข้อแบบฝึกเป็น "ขึ้นเองตามครั้งที่ผิด" (PR-A1) แต่ PR-A4/A33 พูดถึง "ปุ่มใบ้" ที่กดได้** (เกม) → ถ้าทำปุ่มกดเอง เด็กกดใบ้ขั้น 3 ก่อนตอบ แล้วตอบถูกได้ดาวเต็ม ("ใบ้ไม่กระทบดาว") และขัดข้อสมมติ PR-Q2 ที่ว่าไม่มีข้อ "ถูกหลังใบ้ขั้น 3" → OQ76
- `brand.md` §8 ต้องตรวจให้ตรง R9 ใหม่ (ท่าหลอดไฟใช้ในข้อแบบฝึก · รอบ 2026-11-01 บันทึกแล้วว่าเคยขัดเดิม) — ชี้ผล ไม่แก้
- ยังคงค้างเดิม: ท่าผล 0/1–2 ดาว, ท่าผ่านด่านเกม (Designer เสนอ)

## R10: เสียงตอบสนอง · ไม่ใช้เมนูซ้อน

**ผล: ทำได้มีเงื่อนไข · พร้อม: Assume** (OQ73 DS gap · OQ79)
- ไม่ขัดข้อ "ไม่มีเสียงอ่านโจทย์" (คนละประเภท · ถ้อยคำแยกชัดแล้ว) · เสียงเป็นข้อมูลเสริม ไม่ใช่ช่องทางเดียว (PR-A17) · เสียงสั้น < 3 วินาที ไม่ autoplay วน → WCAG 1.4.2 ไม่ถูกบังคับ แต่ยังต้องปิดได้ตาม R10
- **ช่องโหว่: "ปิดเสียงได้" ไม่ระบุที่ปิด/ค่าเริ่มต้น/การจำ/ขอบเขต** → ห้องคอมใช้ร่วม (R5) เสียงดังตอนเริ่มรบกวนห้อง · และ "ไม่ใช้เมนูซ้อน" แปลว่าปุ่มปิดเสียงต้องเป็นปุ่มสลับ (toggle) เดี่ยวที่เห็นตลอด ไม่ใช่รายการใน dropdown/popover (popover ของแถบหน้าต่างใน app-shell เป็นของ module อื่น แต่ใช้ไม่ได้กับตัวควบคุมนี้) → OQ79
- **การลาก/วางมีเสียง:** เสียง "วาง/ต่อ" ต้องมีตอนใช้ทางแตะ-แตะ (R10 ทางเลือกแทนลาก) ด้วย ไม่ใช่เฉพาะตอนลาก
- **ลิขสิทธิ์/แหล่งเสียง:** เป็นงานนอก UI ที่ session หลักหา (OQ70) · ถ้าได้ไม่ครบก่อนออกแบบ D3/D4 → ออกแบบเป็นจุดเรียกเสียง (event) ไม่ผูกไฟล์ · ไม่ block approved
- **DS gap (OQ73 เดิม + เพิ่ม):** (1) ชุดเสียง วาง/ต่อ/กด/เฉลิมฉลอง · (2) ตัวควบคุมปิดเสียง (ปุ่มสลับ + ไอคอนเสียง/ปิดเสียง) · ใช้ที่ D3 (HUD หน้าเล่น), D4 (ผลจบด่าน) · ใกล้เคียงที่สุดใน DS: ไม่ทราบ (ไม่ได้ read DS · ds-build ไม่มีเสียง) · (3) ถ้าผู้ใช้ตอบแสดงจุด "ครั้งที่ n จาก 3" (OQ80 ก): ตัวบอกครั้งที่ตอบ ใช้ที่ D3 · ใกล้เคียงที่สุด: ไม่ทราบ (ใช้ Tag/Badge ได้ไหมต้อง crayon ตรวจ) · (4) แผงใบ้ 3 ขั้นของข้อแบบฝึก + ไอคอนใบ้ = OQ63 เดิม (ไม่เพิ่ม)
