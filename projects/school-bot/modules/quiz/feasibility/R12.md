### รอบ 2026-11-06: ตรวจซ้ำหลังแก้ตาม OQ52 + ST-11

**ทำได้:** การ์ด 6 ใบเรียงคงที่ · ใบใน access เปิด ใบอื่นใช้ DS `Card` สถานะปิดใช้ (`aria-disabled` + popup เหตุผล · ds-build 2026-11-05 · ไม่ใช่ gap) · ไม่มีป้าย "ชั้นของฉัน" (OQ41) · "ผ่าน x/y ภารกิจ" นับทุกชนิดด่านจาก manifest ปัจจุบัน + ดาวที่ได้ไม่มีตัวหาร (OQ52) คำนวณจาก log เดียวกับแผนที่ (R5) · AC-05 ตรงกัน

**ขัดกัน / ตกหล่น (ต้องแก้ requirement · ไม่ต้องถาม):**
1. **R6 ไม่มีจุดแสดงดาวรวมแล้ว** (ตัดจากหน้าหลัก · app-shell OQ23) → "ดาวที่ได้แล้วนับเสมอ รวม level ที่ครูปิด" (OQ52) มีผลได้ที่เดียวคือ **การ์ดที่ล็อก** · R12 ต้องระบุว่า **การ์ดล็อกของ level ที่เคยเล่นแสดง "ผ่าน x/y" + ดาวที่ได้** (ไม่งั้นคำตอบ OQ52 ไม่มีที่แสดง) · การ์ดที่ยังไม่เคยเล่นแสดงอย่างไร → OQ55
2. **ST-11 เหตุผลล็อกระดับ level มีข้อเดียว** ("level สูงกว่าสิทธิ์ที่ครูเปิด → ติดต่อครูเพื่อปลดล็อก") แต่ R7 มี 4 กรณีที่ต่างกัน: (ก) สูงกว่าชั้นตามปกติ (ค่าเริ่มต้น N = ชั้น · ครูไม่ได้ทำอะไร) (ข) ครูลด N ต่ำกว่าชั้น (ค) ไม่รู้ชั้น (Level 2–6 ล็อก + Level 1 ทุกด่านล็อก) (ง) โหลด access ไม่ได้ (ล็อกทุกใบ + ลองอีกครั้ง) · (ค)(ง) ไม่มีข้อความใน ST-11 · ต้องเพิ่มทั้ง 4 กรณีใน ST-11 · ถ้อยคำ (ก) เทียบ (ข) → OQ56
3. **ป้าย/ปุ่ม "เล่นล่าสุด" ใน D1 และ "เรียนต่อ" ของ app-shell R7:** level ที่เล่นล่าสุดอาจถูกล็อกหลังครูลด N (ข้อค้างจากรอบ 2026-11-05) · "เรียนต่อ" ต้องไปเฉพาะ level ที่เข้าได้ ถ้า level ล่าสุดล็อก → ไปหน้าเลือก Level (เสนอ · ผลต่อ app-shell R7 · ตัดสินตอนแก้ D1/หน้าหลัก)
4. **ตัวเลข "x/y" เมื่อบริษัทแทรกด่าน/เปลี่ยนชนิดด่าน:** ใช้ manifest ปัจจุบัน (R2 feasibility 2026-11-01) · เปลี่ยนชนิดด่านให้ใช้ ID เดิม → สถานะผ่านคงอยู่ (ผ่าน = เคยผ่าน) ดาวเดิมนับต่อตาม OQ52 · ด่านใหม่ที่แทรกกลางช่วงที่ผ่านแล้ว = เปิด (ด่านก่อนหน้าผ่าน) และกลายเป็น "กำลังเรียน" (ด่านแรกที่ยังไม่ผ่าน) → x ลดลงได้ 1 และ "ไปที่ฉัน" ย้อนไปด่านนั้น · ทำได้ สอดคล้องกฎเดิม ไม่ต้องถาม แต่ต้องเขียนเป็นข้อกำหนดเนื้อหา/dev (ไม่ใช้ ID ใหม่เมื่อแค่เปลี่ยนชนิด)

**ช่องว่างที่ผู้ใช้ต้องตัดสิน:**
- **OQ55** การ์ดที่ยังไม่เคยเล่น (เปิดหรือล็อก) แสดงความคืบหน้าอย่างไร ("ผ่าน 0/44 · 0 ดาว" ดูเหมือนได้ศูนย์ · H1)
- **OQ56** เหตุผลบนการ์ดล็อกกรณี "สูงกว่าชั้นตามปกติ" ใช้ "ติดต่อครูเพื่อปลดล็อก" เหมือนกรณีครูลด N หรือไม่ (ถ้าใช้ทุกใบ เด็ก ป.1 จะเห็นชวนติดต่อครู 5 ใบ และครูถูกขอเปิด level ที่ไม่ตรงชั้น)
- **OQ57** ครูเพิ่ม N มีผลเมื่อไร (การ์ดเปลี่ยนจากล็อกเป็นเปิดตอนไหน)
- เดิม: OQ27/OQ42 level ที่เปิดแต่ยังไม่มีเนื้อหา · OQ19 ชื่อ/ภาพเกาะจริง

**DS gap:** skeleton ของการ์ด (ดู `R8.md`) · ค้างเดิม: ภาพธีม 6 level + `level-1..6` (G3/G4) · แถบแจ้งเตือนกรณีไม่รู้ชั้นใช้ `sb-notice`/`Banner` ที่มีใน DS ได้ (ไม่ใช่ gap · รายละเอียดรอ app-shell แผน 4)

### รอบ 2026-11-05: การ์ดไม่ตรงชั้นล็อก + ป้าย "ชั้นของฉัน" (ยังใช้ได้ ยกเว้นส่วนป้ายที่ตัดแล้ว · OQ41)
- **ทำได้:** การ์ดล็อกยังแสดงภาพธีม ชื่อ คำอธิบาย + ไอคอนกุญแจ + ข้อความ "ล็อก" (ไม่ใช้สีอย่างเดียว · 1.4.1) · `aria-disabled="true"` ไม่ใช้ `disabled` (โฟกัสได้ แตะแล้วเห็นเหตุผล · H1/H9 · R7) · สั่นเบา ๆ `dur-shake` · reduced-motion = ไม่สั่น แสดงเหตุผลอย่างเดียว
- **ลำดับ/ตำแหน่ง:** 6 ใบเรียงตาม Level 1–6 คงที่ (H6) · การ์ดที่เปิดต้องเด่นด้วยมากกว่าสี · ระหว่างโหลดค่าระดับ level ใช้ skeleton (OQ43)
