## R1: เมนูบทเรียน → เลือก Level → แผนที่

**ผล: ทำได้ · พร้อม: Yes** (ผลเดิม + ปรับ)
- สถานะ "ลองแล้วได้ 0 ดาว" ไม่ใช่สถานะที่ 4: ด่านปลดล็อกแล้วแต่ยังไม่ผ่าน = "กำลังเรียน" (เดิม) · ต่อไปมี "กำลังเรียน" ได้เพียง 1 ด่านต่อ level (ด่านแรกที่ยังไม่ผ่าน) ผู้เล่นซ้ำด่านที่ผ่านแล้วไม่เปลี่ยนสถานะ
- ภาพอ้างอิงแผนที่และหน้าด่านไม่มี sidebar/ปุ่ม home (เต็มจอ มีแค่ "กลับ" / ✕) ขณะที่หน้าเลือก Level มี sidebar → ต้องตัดสินตอนออกแบบ (Delegated → Designer ต้องไม่ขัด app-shell R7/R5): ทางไปหน้าหลัก/Lab อื่นจากแผนที่ (เสนอ: ผ่าน "กลับ" ไปหน้าเลือก Level หรือแถบหน้าต่าง) · ทางออกกลางด่านต้องดักทุกทาง (✕, กลับ, ปิดโปรแกรม, ปุ่ม home บนแถบ) ใช้ยืนยันเดียวกัน (H5)

## R2: เนื้อหาจาก cloud · ครูเปิด/ปิด

**ผล: ทำได้มีเงื่อนไข · พร้อม: Assume** (OQ5, OQ18, OQ23, OQ22)
- ด่านต้องมี ID คงที่ (ไม่ใช้ลำดับ) · ผลเก็บตาม ID + เวอร์ชันเนื้อหา · ถ้าบริษัทแทรก/ลบ/สลับด่านภายหลัง: ด่านที่เคยผ่านเปิดตลอด (ผ่านแล้วไม่ล็อกกลับ) · จำนวน "ผ่าน x/y" นับจาก manifest ปัจจุบันเท่านั้น (ไม่ให้ x > y) · ผลของด่านที่ถูกลบเก็บไว้แต่ไม่นับในแผนที่
- ต้องมี **manifest ต่อ level** (จำนวนด่านต่อเทอม ชื่อด่าน ตำแหน่ง node) ที่ดึงตอน login/เปิดหน้าเลือก Level ให้ครบ 6 level เพื่อวาดการ์ด (ด่านที่ผ่าน/ทั้งหมด) · ใช้แคชได้ · เนื้อหาข้อสอบดึงทั้งด่านก่อนเริ่ม (ผลเดิม OQ16)
- ข้อมูลที่แผงภารกิจต้องใช้เพิ่ม (R13): ชื่อด่าน, สิ่งที่ได้เรียนรู้ (รายการ), วิธีทำ, แท็ก, ลำดับ · ยังไม่อยู่ในแหล่งเนื้อหาที่ระบุ (Course Plan มีหัวข้อรายแถว) → รวมใน OQ23 (ต้องมีฟิลด์เหล่านี้ใน cloud ไม่งั้นแผงว่าง)
- ลำดับเลข "ภารกิจที่ n": นับต่อเนื่อง 1..N ข้ามเทอม หรือเริ่มใหม่ต่อเทอม (Designer เสนอ · เสนอต่อเนื่อง เพราะเทอม 2 ต่อเนื่อง R7)
- "ครูเปิด/ปิดหน่วย" ยังไม่นิยาม → OQ22 · Proposed ตัดออกจาก phase 1 (เหตุผลล็อก "ครูปิด" จึงยังไม่ต้องมี UI ใน phase 1 แต่เผื่อที่ในแผงเหตุผล)

## R3: แบบฝึก 4 กลุ่ม 5–8 ข้อ ไม่ลองซ้ำ ไม่มีใบ้

**ผล: ทำได้มีเงื่อนไข · พร้อม: Assume** (OQ11, OQ13 ก, OQ20)
- **คะแนนต่อข้อ (OQ13 ก):** แนะนำ **ถูกทั้งข้อ = 1 ข้อ ผิด = 0 ไม่ให้บางส่วน** ทุกกลุ่ม เพราะ R4 และหน้าผล ("ตอบถูก 4/5 ข้อ") ใช้จำนวนเต็ม และเกณฑ์ไม่ปัดเศษ · ข้อจับคู่ 4–5 คู่ถูกทั้งข้อเข้มสำหรับ ป.1 ไม่มีลองซ้ำ → ให้คุมจำนวนคู่ ≤ 4 ในข้อ (ข้อกำหนดเนื้อหา OQ23) · เฉลยต้องโชว์ลำดับ/คู่/ค่าที่ถูกทั้งหมด (เดิม)
- **"ข้าม" (OQ11):** เมื่อไม่ลองซ้ำและไม่มีใบ้ ปุ่มข้าม = ตอบผิดโดยไม่ได้เห็นเฉลย หรือสร้างเส้นทางที่ 2 ที่ต้องมีข้อความยืนยัน (H5) · ภาพอ้างอิงทุกภาพไม่มีปุ่มข้าม · **แนะนำตัดปุ่ม "ข้าม" ออกจาก R3** (การกระทำ: ตอบ ตรวจ ออก) · ถ้าผู้ใช้ต้องการคงไว้ ต้องบอกก่อนกดว่านับเป็นผิด + แสดงเฉลย
- **ปุ่ม "ตรวจ":** ใช้ `aria-disabled` + บอกเหตุผล (เช่น "เลือกคำตอบก่อน", "วางให้ครบทุกช่อง") จนตอบครบ (H5) · ข้อเรียง/จับคู่มี "ล้าง/เริ่มใหม่" ก่อนตรวจ (ยังไม่ใช่ลองซ้ำหลังตรวจ) · หลังตรวจแล้วล็อกคำตอบ ไม่ย้อนแก้
- **ทางเลือกแทนการลาก (WCAG 2.5.7):** เรียงบล็อก/จับคู่/ลากป้าย = แตะเลือกแล้วแตะวาง ใช้ได้ด้วยคีย์บอร์ด (โฟกัสเห็น ลูกศร/Enter/Space) และมีเสียงสถานะด้วย aria-live ("เลือกป้าย x แล้ว วางที่ช่องไหน") · ช่องวาง ≥ 44 และเว้นระยะไม่ชนกัน (2.5.8) · สไลเดอร์ลาก = มี ‹ › คู่เสมอ (R10) ครบ 2.5.7
- **สไลเดอร์ (OQ20):** (1) ก้านสไลเดอร์ในภาพอ้างอิง ~26px < R10 (44) → ขยายจุดจับ (2.5.8 ขั้นต่ำ 24) (2) ค่าเป้าต้องอยู่บนกริดของ step ของ ‹ › และสไลเดอร์ ไม่งั้นไปไม่ถึง (เช่น step 5° ต้องเป้าเป็นพหุคูณ 5 และ tolerance ≥ ครึ่ง step) (3) ข้อความ "ใกล้แล้ว! ห่างจากเงา 20°" เป็น feedback ขณะปรับ ใกล้เคียง **คำใบ้ต่อเนื่อง** ซึ่งขัด "ไม่มีคำใบ้" ตามถ้อยคำ แต่เงาที่เห็นอยู่แล้วเป็นเป้าชัด ข้อความจึงเป็นทางเลือกที่ไม่ใช้ตา (a11y) · แนะนำคงไว้และถือเป็น feedback ไม่ใช่ใบ้ → ให้ผู้ใช้ยืนยันใน OQ20 (4) แจ้งผลด้วย aria-live แบบหน่วงเมื่อหยุดปรับ ไม่อ่านทุก 1° (H1) (5) "ถูกเมื่อทุกข้อต่อพร้อมกัน" ถูกทั้งข้อ (ตาม OQ13 ก)
- โครง: แถบ progress รองรับ 5–8 ข้อ (OQ14 answered) · ความคืบหน้า x/n แสดงเสมอ · ภาพอ้างอิงเป็น 1440×900 ไม่มีแถบหน้าต่าง ของจริงสูง 840 → ตรวจ overflow ตอน +40% (ไทย/EN/中文) เลื่อนเฉพาะแผง · ไม่มีจับเวลา (เดิม)
- ภาพ/สื่อโหลดไม่สำเร็จรายภาพ: ต้องมี fallback ข้อความ + ลองใหม่ ไม่ทำให้ทั้งด่านพัง (เดิม) · เลือกตอบด้วยภาพต้องมี alt/ข้อความกำกับ

## R4: ดาว 60/80/100% กับ 5–8 ข้อ

**ผล: ทำได้ · พร้อม: Assume** (OQ12)
- **ตรวจครบทุก N แล้ว** (เทียบเลขจำนวนเต็ม `ถูก×100 ≥ 60×N` ห้ามใช้ทศนิยม): N=5 → 3/4/5 · N=6 → 4/5/6 · N=7 → 5/6/7 · N=8 → 5/7/8 ได้ครบ 3 ระดับและเรียงต่างกันทุก N (ตัวอย่างใน R4 ถูกต้อง · เพิ่ม N=7) · ถ้า cloud ส่งด่านนอกช่วง 5–8 ให้คำนวณด้วยสูตรเดียวกัน ไม่ล้ม (ข้อมูลผิดไม่ block ผู้เล่น)
- **เล่นซ้ำ (OQ12):** ผลเป็น log เพิ่มอย่างเดียว · ดาวบนแผนที่ = **สูงสุดต่อด่าน** · "ผ่านแล้ว" = เคยได้ ≥ 1 ดาวครั้งใดก็ได้ · ผลใหม่ต่ำกว่าเดิมไม่ลดดาวและไม่ล็อกกลับ · "ดาวใหม่ +n" = ส่วนเกินดาวสูงสุดเดิม · **n = 0 ต้องไม่แสดงการ์ด "+0"** แสดง "ดาวสูงสุดของด่านนี้ x/3" แทน (H1)
- **ปุ่ม "ด่านต่อไป":** 0 ดาว (ด่านถัดไปยังล็อก) → ไม่ชวนไปด่านล็อก ใช้ "เล่นอีกครั้ง" เป็นปุ่มหลัก + บอกว่าต้องได้ 60% ก่อน · ด่านสุดท้ายเทอม 1 → ไปด่านแรกเทอม 2 (ช่วงฉลอง checkpoint) · ด่านสุดท้ายเทอม 2 → กลับแผนที่ที่เส้นชัย
- ภาพอ้างอิงผลจบด่านมี 🏅 และสัญลักษณ์ ▶ ↺ (ตัดเหรียญแล้ว ที่เหลือแทนด้วย Lucide `play`, `rotate-ccw` ตาม brand §6) · ชื่อปุ่ม: ภาพใช้ "เล่นอีกครั้ง" R4 ใช้ "เล่นใหม่" → เลือกคำเดียว (Designer เสนอ ให้ตรง brand §7)
- ผลจบด่านต้องไม่รอ cloud: บันทึกลงเครื่องแล้วแสดงผลทันที ส่งขึ้น cloud เบื้องหลัง (ดู R5)

## R5: phase 1 เก็บผลที่ cloud School Bot · ออฟไลน์ sync

**ผล: ทำได้มีเงื่อนไข · พร้อม: Assume** (OQ17 answered · OQ21, OQ28) · ผลรอบ 2026-11-01 (เดิมรวม R5/R16 · ส่วน R16 รอบ 2026-11-05 ย้ายไปหัวข้อ R16)
