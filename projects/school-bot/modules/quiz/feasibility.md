# Quiz (บทเรียน): Feasibility (จาก role 2)

**ผล: ทำได้มีเงื่อนไข** (2026-10-30)

สรุป: ทำได้ทุกข้อ ไม่มี OQ ที่ block โครงหน้า (OQ5/OQ7 ผู้ใช้ตัดสินแล้วว่าไม่ block โครงหน้า · ดู INDEX) · เงื่อนไขหลัก: (1) กติกาคะแนนต่อข้อ/จำนวนข้อขั้นต่ำยังไม่กำหนด ทำให้ดาว 3 ระดับอาจไปไม่ถึง (OQ13, OQ14) (2) ขัดกันเองเรื่องคำใบ้ (R9 มี R3 ไม่มี · OQ15) และ "ลองใหม่นะ" กับการนับผิด (OQ13) (3) เนื้อหาดึงจาก cloud แต่ต้องเล่นต่อได้ออฟไลน์ ต้องกำหนดการ cache (OQ16) (4) คิวคะแนนกับ logout/เปลี่ยนเครื่อง (OQ17) · ที่ต้องตอบก่อน `approved` (ผู้ใช้ยืนยัน): OQ13–OQ17 แนะนำให้ตอบอย่างน้อย OQ13, OQ14 ก่อน (กระทบหน้าด่านและผลจบด่านโดยตรง) · ที่เหลือใช้ข้อสมมติ Proposed ออกแบบได้ ติดป้าย

Heuristic ที่ใช้ตรวจ: H1 สถานะระบบ · H5 ป้องกันผิดพลาด · H9 error/recovery · universal-design (เด็ก ป.1) · knowledge/ ที่ใช้ได้ครบตาม README (ไม่มีเกณฑ์เฉพาะ quiz)

พร้อมออกแบบ: **Yes** เริ่มได้ · **Assume** ออกแบบตามข้อสมมติ รอคำตอบก่อน dev · **Wait** รอก่อนออกแบบส่วนนั้น

## R1: แผนที่หน่วยและด่าน (SCR-06)

**ผล: ทำได้ · พร้อม: Yes**
- ช่องโหว่: นิยามสถานะไม่ครบ มี 3 (ผ่าน/กำลังเรียน/ล็อก) แต่ด่านที่เล่นแล้วได้ 0 ดาว (<60%) ไม่ใช่ทั้ง "ผ่าน" และ "ล็อก" · ข้อเสนอ: ด่านปลดล็อกแล้วที่ยังไม่ผ่าน = "กำลังเรียน" (มีได้เพียงด่านเดียวต่อหน่วยตามลำดับ) แสดงบันทึก "ลองแล้ว ยังไม่ผ่าน" ได้ ไม่ใช่สถานะที่สี่
- ด่านที่ผ่านแล้วต้องเล่นซ้ำได้ (R4 เล่นใหม่) · แสดงดาวสูงสุดต่อด่าน (OQ12 Proposed)
- จำนวนหน่วย/ด่านไม่ทราบ (OQ5) → แผนที่ต้องเลื่อนในแผงเดียว (R11 app-shell ห้ามเลื่อนทั้งหน้า) และไม่ตายตัวกับจำนวนด่าน (BUG-01 ของหน้าหลักเป็นบทเรียน: ข้อมูลหน่วยจริงห้ามตายตัว)
- ต้องบอกด่านปัจจุบันชัด (H1) · ปุ่มเรียนต่อจากหน้าหลักต้องไปด่านเดียวกัน

## R2: เนื้อหาจาก cloud · ครูเปิด/ปิดหน่วย

**ผล: ทำได้มีเงื่อนไข · พร้อม: Assume (OQ5 ไม่ block โครงหน้า · ป้ายเนื้อหาตัวอย่างว่าสมมติ)**
- **ขัดกันเอง:** เนื้อหาดึงจาก cloud (ST-12) แต่ edge case บอกเน็ตหลุดระหว่างเล่นด่านเล่นต่อได้ และ login ต้องออนไลน์ แล้วเปิดด่านใหม่ตอนออฟไลน์ล่ะ → ไม่กำหนด · **OQ16** Proposed: ดึงเนื้อหาด่านทั้งด่านก่อนเริ่ม (ไม่ดึงทีละข้อ) เก็บแคชตอน login · ออฟไลน์เปิดได้เฉพาะด่านที่แคชไว้ ส่วนที่ไม่มี แสดง "ต้องต่อเน็ตเพื่อโหลดด่านนี้" แยกจากกรณีโหลดล้มเหลว (H9)
- ครูปิด/เปิดหน่วยต้องดึงสถานะจาก cloud (module teacher-web FR-27) · ออฟไลน์อาจใช้สถานะเก่า (ยอมรับ ติดป้ายใน dev)
- เนื้อหาถูกอัปเดตระหว่างนักเรียนเล่นด่าน: ใช้ฉบับที่โหลดไว้จนจบด่าน (Proposed ไม่ต้อง OQ)
- **สถานะที่ขาด (H1):** ไม่มีหน่วยที่เปิดให้ห้อง (ครูปิดหมด/ยังไม่มีเนื้อหา) → หน้าว่างพร้อมคำอธิบาย "ครูยังไม่เปิดบทเรียน" ไม่ใช่แผนที่ว่าง · ต้องมีใน R8
- ภาพ/สื่อในคำถาม (OQ5): โหลดไม่สำเร็จเป็นรายภาพ → ต้องมี fallback ข้อความ/ลองใหม่ ไม่ทำให้ทั้งด่านพัง

## R3: คำถาม 3 แบบ (SCR-07)

**ผล: ทำได้มีเงื่อนไข · พร้อม: Assume**
- **ขัดกันเอง 1:** R9 "ตอบผิด: ลองใหม่นะ" แต่ R4 นับดาวจากข้อถูก ไม่ชัดว่าตอบผิดแล้วลองข้อเดิมซ้ำได้ (ถ้าได้ ต้องนับถูก/ผิดแบบใด) หรือดูเฉลยแล้วไปข้อต่อ · **OQ13** Proposed: ตรวจแล้วเห็นเฉลย ไปข้อต่อ ไม่ลองซ้ำข้อเดิม (ข้อความ "ลองใหม่นะ" หมายถึงเล่นด่านใหม่ ไม่ใช่ข้อเดิม)
- **ขัดกันเอง 2:** R9 มี "คำใบ้ (หลอดไฟ)" แต่ R3 ไม่มีการกระทำคำใบ้ (ตอบ ตรวจ ข้าม ออก) · **OQ15** Proposed: ไม่มีปุ่มคำใบ้ใน MVP (ตัดการใช้ท่าหลอดไฟออกจาก Quiz จนกว่าจะตัดสิน)
- การให้คะแนน เรียงลำดับ/จับคู่: ถูกทั้งข้อหรือบางส่วน · Proposed ถูกทั้งข้อ (ข้อละเท่ากัน) · ปุ่ม "ตรวจ" ใช้ไม่ได้จนกว่าตอบครบ และบอกว่าต้องทำอะไร (H5) · เรียงลำดับ/จับคู่ ต้องมี "ล้าง/เริ่มใหม่" ก่อนตรวจ (H3)
- **ทางเลือกแทนการลาก (R10):** แตะเลือก-แตะวางต้องใช้ได้ด้วยคีย์บอร์ดและโฟกัสเห็นชัด (WCAG 2.1.1, 2.5.7) ไม่ใช่แค่แตะ · เฉลยของข้อเรียงลำดับ/จับคู่ต้องแสดงลำดับ/คู่ที่ถูกทั้งหมด
- ข้าม (OQ11): ถ้านับเป็นไม่ถูกและย้อนกลับไม่ได้ ต้องยืนยันก่อน (H5) หรือเลื่อนไปท้ายข้อ · Proposed ข้าม = ไม่ถูก ไม่ย้อนกลับ มีข้อความบอกก่อนกด
- ออกกลางด่าน (ST-14): ไม่ใช่แค่ปุ่ม "ออก" ต้องดักการออกทุกทาง (sidebar, home, ปิดโปรแกรม dialog ของ app-shell R5, กลับ) ให้ยืนยันเดียวกัน (H5) · ปิดโปรแกรม/แอปค้างกลางด่านความคืบหน้าหาย (สอดคล้อง ST-14) · ให้ app-shell แสดงเหตุผลนี้ใน dialog ปิดโปรแกรม
- ไม่มีตัวจับเวลา (ห้ามเพิ่ม · รางวัลไม่เป็นแรงกดดัน R10)

## R4: ดาว 0–3 และผลจบด่าน (SCR-08)

**ผล: ทำได้มีเงื่อนไข · พร้อม: Assume (OQ12 Proposed ออกแบบได้)**
- **ช่องโหว่คณิตศาสตร์ (สำคัญ · OQ14):** เกณฑ์ ≥60/80/100% กับจำนวนข้อ N: N=3 → ผลได้ 0/33/67/100% ไม่มี 2 ดาว (ถึงไม่ได้) · N=4 → 75% ได้ 1 ดาว ไม่มี 2 ดาวจนถึง 4/4 · ทุกระดับไปถึงได้ต่อเมื่อ N≥5 (3/5=60, 4/5=80, 5/5=100) · ต้องกำหนด N ขั้นต่ำต่อด่าน และกฎปัดเศษ (เทียบแบบไม่ปัด เช่น 3/5 = พอดี 60 ผ่าน)
- "คะแนน" ที่ส่งเข้า SchoolBright = จำนวนข้อถูก / ร้อยละ / แต้ม ไม่ระบุ · **OQ13** Proposed: ส่ง ถูก/ทั้งหมด + ร้อยละ + ดาว
- ได้ 0 ดาว: ปุ่ม "ไปต่อ" ต้องไม่ชวนให้ไปด่านที่ล็อกอยู่ · Proposed: ซ่อน/ปิดพร้อมเหตุผล เน้น "เล่นใหม่" ข้อความไม่ลงโทษ (ลองใหม่นะ) ไม่ใช้สีแดงตัดสิน (H5, brand §7)
- ด่านสุดท้ายของหน่วย/ของทั้งหมด: "ไปต่อ" ไปหน่วยถัดไป หรือกลับแผนที่เมื่อไม่มีด่านถัดไป · จบหน่วย (R9 กอดหัวใจ) ไม่มี SCR/ST รองรับ ต้องเพิ่มองค์ประกอบ "จบหน่วย" ใน SCR-08 (ดู R9)
- เล่นซ้ำ (OQ12): ผลใหม่ต่ำกว่าเดิมต้องไม่ทำให้ดาวบนแผนที่ลด และต้องไม่ปลดล็อกสถานะที่เคยปลดถอยกลับ (Proposed)
- ดาวแสดงด้วยรูป + ตัวเลข ไม่ใช้สีอย่างเดียว

## R5: ส่งคะแนนเข้า SchoolBright

**ผล: ทำได้มีเงื่อนไข · พร้อม: Assume (OQ7 ไม่ block โครงหน้า แต่ block ก่อนส่ง dev)**
- **ต้องการ idempotency:** ส่งซ้ำจากคิวต้องไม่สร้างคะแนนซ้ำ ใช้รหัสผลการเล่นเดียวต่อรอบ (นักเรียน+ด่าน+เวลา) · ต้องมีก่อน dev (OQ7 ถ้า SchoolBright ไม่มี API: ย้ายไปเก็บ cloud School Bot แล้วเว็บครูอ่านจาก cloud เรา · ผลต่อ UI: ไม่เปลี่ยนมาก เปลี่ยนข้อความ "ส่งแล้ว" เป็น "บันทึกแล้ว")
- **คิวผูกอะไร (OQ17):** ผลการเล่นเก็บ cloud ของ School Bot (EC-04) แต่คิวส่ง SchoolBright ถ้าอยู่แค่ในเครื่อง การเปลี่ยนเครื่อง/ล้างเครื่อง/ออกจากระบบ (app-shell R8) ทำคะแนนที่รอส่งหาย ขัด AC-06 · Proposed: บันทึกผลลง cloud ของเรา ก่อนเสมอ (ตอนออนไลน์) แล้วส่ง SchoolBright จาก cloud/เครื่อง · ออฟไลน์ + ออกจากระบบ: เตือน "มีคะแนนรอส่ง N รายการ" (H5)
- ส่งไม่สำเร็จถาวร (หลายครั้ง · OQ8): ต้องไม่ติด "รอส่ง" ตลอดกาลเงียบ ๆ · ฝั่งเด็กยังเป็น "รอส่งคะแนน" (ไม่ใช่ error ที่น่ากลัว) ฝั่งครูเห็น "ส่งไม่สำเร็จ" (SCR-23) และมีทางลองใหม่/แจ้งผู้ดูแล
- **สถานะต้องคงอยู่หลังออกจาก SCR-08 (H1):** แสดงป้าย "รอส่งคะแนน" ที่การ์ดด่านบนแผนที่ด้วย ไม่ใช่แค่หน้าผล · และไม่ซ้ำกับตัวบอกสถานะคลาวด์ที่แถบ (app-shell R3: เฉพาะงานที่ผิดปกติ) แยกความหมาย: แถบ = งานบันทึกขึ้นคลาวด์ · ป้ายนี้ = คะแนนส่ง SchoolBright · ใช้คำต่างกัน
- นักเรียนไม่มีห้อง (ยังไม่ถูกจัดห้อง/ย้ายห้อง) ตอนเล่น: ENT-10 "ห้อง ณ เวลานั้น" ว่าง · Proposed: ส่งโดยเว้นห้อง ไม่ block (ผู้ใช้/dev ยืนยันใน OQ7)
- Arm Lab/Block Lab ไม่ส่งคะแนน (ตรงกับ DEC-18)

## R6: ความสำเร็จ ดาวและเหรียญ (?)

**ผล: ทำได้มีเงื่อนไข · พร้อม: Assume (ดาว) / Wait (เหรียญ)**
- เกณฑ์เหรียญ OQ4 ยังไม่ตัดสิน · ไม่ block โครงหน้า แต่ block หน้าตา/ขณะได้เหรียญ · ผู้ใช้ตอบ OQ4 ก่อน design ส่วนเหรียญ
- ข้อเสนอ (ค) "เล่นต่อเนื่อง" ขัด R10 (รางวัลต้องไม่ดึงให้ใช้นาน) · แนะนำตัดทิ้ง เหลือ (ก)/(ข)
- ความสำเร็จแสดงที่หน้าหลัก (app-shell R7) ต้องคำนวณจากผลด่านเดียวกัน · ผลซ้ำ/ดาวสูงสุดต้องสม่ำเสมอ · เหรียญที่ได้แล้วไม่ถอน (แม้ครูปิดหน่วยภายหลัง OQ10)

## R7: สถานะด่านและการล็อก

**ผล: ทำได้มีเงื่อนไข · พร้อม: Assume (OQ9/OQ10 Proposed)**
- เหตุผลล็อกมี 2 ข้อ ซ้อนกันได้ (ยังไม่ผ่านด่านก่อน + ครูปิดหน่วย) → Proposed แสดง "ครูปิดหน่วยนี้" ก่อน (เด็กทำอะไรไม่ได้) · ครูปิดหน่วย = ทุกด่านในหน่วยล็อกพร้อมกัน
- ไม่ใช้ `disabled` ที่โฟกัส/แตะไม่ได้: แตะที่ด่านล็อกต้องเปิดคำอธิบาย (ไม่พึ่ง hover · R10) โฟกัสด้วยคีย์บอร์ดได้ (aria-disabled) · ภาษาเด็ก ไม่ตำหนิ
- OQ10: ครูปิดหน่วยที่ผ่านแล้ว · Proposed ผลเดิมคงอยู่ เล่นซ้ำไม่ได้ · ด่านกำลังเล่นให้เล่นจนจบ (ส่งผลได้) แล้วบอกว่าเล่นต่อไม่ได้ — ต้องให้ผู้ใช้ยืนยัน (กระทบข้อมูลครู)
- ปลดล็อกตามด่านก่อน (OQ9) · เล่นข้ามด่านไม่ได้ Proposed · หน่วยถัดไปปลดเมื่อผ่านด่านสุดท้ายหน่วยก่อน (ไม่ใช่ครบทุกดาว)

## R8: สถานะระบบ

**ผล: ทำได้ แต่ requirement ขาดสถานะ · พร้อม: Yes**
ที่มีแล้ว: ครั้งแรก, โหลด, โหลดไม่สำเร็จ, ออกกลางด่าน, ออฟไลน์ (แถบ) · ที่ต้องเพิ่ม (ไม่ต้องถามผู้ใช้ ระบุเป็นเงื่อนไขของ design):
- ไม่มีหน่วยที่เปิด (ครูปิดหมด/ cloud ไม่มีเนื้อหา)
- ออฟไลน์แล้วเปิดด่านที่ไม่มีแคช (แยกจากโหลดล้มเหลว · OQ16)
- โหลดแผนที่ได้แต่โหลดเนื้อหาด่านไม่สำเร็จ (ลองใหม่ที่ด่าน ไม่เด้งกลับทั้งหน้า)
- ระหว่างส่งคะแนน (กำลังส่ง) ก่อน ST-15/16 · โหลดต้องไม่ block ปุ่ม "ไปต่อ" (ส่งเบื้องหลัง)
- session หมดอายุกลางด่าน: เล่นต่อได้ ผลเข้าคิว แล้วขอ login ใหม่ตอนส่ง
- ST-09 ครั้งแรก: ใช้ได้เมื่อไม่มีผลการเล่น ไม่ใช่เมื่อไม่มีงาน (ใน SCREEN_INVENTORY เดิมกำกวม)
- สถานะกำลังโหลด ใช้มาสคอตวิ่ง + ข้อความ (app-shell R9) ไม่เกิน ~150px

## R9: มาสคอต

**ผล: ทำได้ · พร้อม: Yes**
- ต้องมีข้อความกำกับ alt ไม่กะพริบ (ตรงกับ AC-19) · เคารพ prefers-reduced-motion
- ขัดกับ R3: ท่า "คำใบ้ (หลอดไฟ)" ไม่มีฟีเจอร์รองรับ → OQ15
