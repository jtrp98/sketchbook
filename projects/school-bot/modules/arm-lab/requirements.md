# Arm Lab: Requirements (จาก role 1)

> นำเข้ารายละเอียดจากระบบเก่า (`Handoff/01_REQUIREMENT` v3.1 + ผลหลังจากนั้นถึง 2026-10-21) · **sketchbook เป็นแหล่งความจริงแล้ว** ไม่ต้องเปิดโฟลเดอร์เดิม · ID เดิม (FR/NFR/EC/AC/DEC/ST/SCR) เก็บไว้ในวงเล็บเพื่อ grep ข้ามไฟล์ · ป้ายหลักฐาน (Confirmed/Observed/Proposed ฯลฯ) ดู `../../context.md`
> R1–R11 ID เดิม ไม่เปลี่ยนความหมาย · R12–R17 เพิ่มวันนี้ (นำรายละเอียดฟังก์ชัน 6A ที่ผู้ใช้อนุมัติแล้ว และผล CR-11 เข้ามา) ดู CHANGELOG

## เป้าหมาย
นักเรียน ป.1–6 (UI เดียวกันทุกชั้น) สอนท่าแขนกล 6 ข้อต่อ (S0–S5) แล้วเล่นเป็นลำดับ กับหุ่นที่มีบอร์ด Raspberry Pi ผ่าน USB · ครูตั้งค่าขั้นสูงแบบ Zide ในโหมดครู · ฐานงานออกแบบ: frame 6A แขนกล (MainV6A) ที่ผู้ใช้อนุมัติแล้ว (รีดีไซน์จาก Zide)

## Requirements
ลำดับ: M = Must · ? = ยังไม่ยืนยัน (ดู OQ)

- R1 (M): ใช้ frame 6A แขนกล (MainV6A) เป็นฐานฟังก์ชันและ layout · **อนุมัติแล้ว (DEC-08)** แก้ผ่านใบสั่งแก้เท่านั้น ห้ามทำใหม่ทั้งหน้า · ฟังก์ชันและพฤติกรรมความปลอดภัยต้องครบตาม R5, R12–R16 หลังปรับให้เข้ากับ cloud, Raspberry Pi และ ป.1–6 · **ขนาดปุ่ม/ตัวอักษรคงตาม 6A เดิม ไม่ปรับให้ผ่านเกณฑ์ ≥16px/44px** (ผู้ใช้ตัดสิน 2026-10-21 · OQ20) · โน้ตเพื่อทบทวนอนาคต: ใน 6A มี control ต่ำกว่า 16px อยู่ 129 จาก 152 ตัว ไม่ผ่านเกณฑ์เด็กของ brand/context.md (ความเสี่ยงที่ยอมรับ ร่วมกับ RSK-04) · (FR-10, AC-07, DEL-04)
- R2 (M): ใช้กับแขนกลที่มีบอร์ด Raspberry Pi · โปรโตคอล "ใกล้เคียง Zide" (ผู้ใช้ตอบ 2026-10-20 → คง 6A เกือบทั้งหมด) · 6A สมมติ COM7 ที่ 115200, PWM 500–2500, คำสั่งรูปแบบ `{G0001#000P1500T3000!}` [Observed EV-03] · รายการค่าตั้งขั้นสูงยืนยันกับ firmware → OQ1, OQ12 · (FR-11, DEC-07)
- R3 (M): แขนกลบนจอ**ไม่ขยับไม่ว่ากรณีใด** (ไม่มีการจำลอง) ทั้งเล่นท่า ขยับข้อต่อ หรือทำอะไรก็ตาม · (FR-12, AC-08, CON-07)
- R4 (M): โหมดครูของ Arm Lab: การตั้งค่าขั้นสูงแบบ Zide · ครู**ของโรงเรียนเดียวกับนักเรียนที่ login อยู่** เข้าได้โดย login ด้วยบัญชี SchoolBright ของตัวเองใน dialog (แทน "ใส่รหัส") · (FR-13, AC-09, DEC-09, UJ-06) · การจบเซสชันครู → OQ9
- R5 (M): ปุ่มหยุดเห็นได้ตลอด · เตือนก่อนสั่งขยับไกลหรือเล่นวนไม่หยุด · ปิดปุ่มสั่งงานเมื่อหลุดการเชื่อมต่อ · (FR-14, NFR-04, AC-07)
- R6 (M): งานบันทึกบน cloud ผูกกับบัญชีเป็นค่าเริ่มต้น · (FR-22, AC-13, DEC-13) · รายละเอียดหน้ารวมงาน/sync อยู่ module `my-work`
- R7 (M): export งานเป็นไฟล์ .ini ได้ (Arm Lab = .ini ที่เปิดใน Zide ได้ · ผู้ใช้ตอบ 2026-10-20) · ค่า S5 ใน .ini เป็น PWM ตรงตัว ไม่ผ่านการปัดเป็น % (R13 · 2026-11-04) · (FR-23, AC-13)
- R8 (M): กู้คืนงานสำรองที่อยู่ในเครื่องได้ (6A สำรองอัตโนมัติทุก 10 วินาที) · (FR-24, AC-13)
- R9 (?): นำท่าหรืองานจากไฟล์ .ini เข้ามาได้ · Inferred จาก frame (Ctrl+A) · frame ปัจจุบันทำปุ่ม "นำเข้าจากไฟล์ .ini…" แล้ว · → OQ4 · (FR-25)
- R10 (M): ใช้ UI เดียวกันทั้ง ป.1–6 ต้องอ่านและใช้ได้สำหรับ ป.1 · เป้า WCAG 2.2 AA + เกณฑ์เด็ก (`../../context.md`) · ไม่มีตัวช่วยเพิ่มสำหรับ ป.1–3 ใน MVP (RSK-04 ยอมรับ) · frame เดิมสมมติผู้ใช้ ป.4–6 ต้องปรับข้อความ/ความซับซ้อน (CF-02) · **ยกเว้นขนาดปุ่ม/ตัวอักษร: คง 6A เดิมตาม R1 (ยังไม่ผ่านเกณฑ์ 16px/44px · ทบทวนภายหลัง)** · (NFR-02, DEC-06, DEC-19, EC-06, AC-15)
- R11 (M): เชื่อมต่อหุ่นผ่าน USB ในโปรแกรมติดตั้ง Windows/Mac · ไม่ต้องติดตั้ง driver (ฝังใน installer) · สถานะ: ยังไม่เชื่อม (ปุ่มสั่งงานปิด) / กำลังเชื่อมต่อ / เชื่อมแล้ว / หลุด · ชื่อหุ่นและการจับคู่ → OQ5 · (NFR-03, EC-03, FR-11, ST-19, ST-20) · **เชื่อมไม่สำเร็จ** (หุ่นไม่ตอบ/พอร์ตถูกใช้) → กลับ "ยังไม่เชื่อม" + ข้อความผลบนหน้าเชื่อมต่อ ไม่ลิงก์กลับ workspace (ข้อเสนอ ruler ผู้ใช้ยังไม่ยืนยัน) · **ทางเข้า (ผู้ใช้ตัดสิน 2026-11-04 · OQ30, OQ43):** เข้า Arm Lab เห็นหน้างาน ไม่บังคับผ่านหน้าเชื่อมต่อก่อน · ปุ่มเชื่อมหุ่นถูกไฮไลต์ ชื่อ **"เชื่อมหุ่น"** (ยังไม่เชื่อม) / **"เปลี่ยนหุ่น"** (เชื่อมแล้ว) · ยังไม่เชื่อม: กดในพื้นที่ทำงานหลักขึ้น popup เตือนให้เชื่อมหุ่นแล้ว popup สั่น (ลดการเคลื่อนไหว = ไม่สั่น ใช้ไฮไลต์) ⟨OQ31/OQ34: ข้อยกเว้นของ "กดที่ใดก็ตาม" (แถบบน ☰ บันทึก ส่งออก ปุ่มหยุด dialog ระบบ)⟩ · **flow เริ่มต้น (ผู้ใช้ตัดสิน 2026-11-04):** กด "เชื่อมหุ่น" ใน workspace → หน้าเชื่อมต่อ → เลือกหุ่น → เชื่อมต่อ → กลับ workspace ทันที **ไม่มีขั้นพาไปท่าพัก ไม่มีติ๊กในหน้าเชื่อมต่อ ไม่มีขั้นตั้งชื่อไฟล์** · เชื่อมสำเร็จ: เน้น+สั่น "เพิ่มท่า" เฉพาะไฟล์ที่ไม่มีท่า G#### ที่ผู้ใช้เพิ่ม (ไม่นับท่า 0) · เชื่อมหุ่นไว้แล้วในรอบนี้แล้วเปิดไฟล์ใหม่/ไฟล์ที่สอง ⟨OQ54 ค: ข้ามเลย หรือ popup "ใช้หุ่นเดิมต่อ/หุ่นใหม่"⟩ · **ไฟล์อัตโนมัติ (ผู้ใช้ตัดสิน 2026-11-04 · OQ48, OQ54):** ทางเข้า "เริ่มต้น" = **เฉพาะเข้า Arm Lab ครั้งแรกจากปุ่มใน workspace ที่ไม่มีไฟล์งาน** ⟨OQ54 ข/OQ57 ง: นิยาม "ครั้งแรก/ไม่มีไฟล์งาน" และทางอื่นเมื่อไม่มีไฟล์ให้กลับ⟩ · เชื่อมสำเร็จ → สร้างไฟล์ชื่อ `Arm Lab 2026-11-04` (วันที่ปัจจุบัน ค.ศ. ISO) ซ้ำในบัญชีนักเรียน → ต่อท้าย ` (2)` ใช้เลขว่างถัดไป ไม่ใช้เลขที่ลบแล้วซ้ำ · ทางอื่น (กดเชื่อม/เปลี่ยนหุ่นจาก workspace ที่มีงาน · เชื่อมกลับหลังหลุด · กลับไฟล์ที่เปิดอยู่) → กลับไฟล์เดิม ไม่สร้างใหม่ ไม่เปลี่ยนชื่อ · **บันทึกจริงเมื่อมีการแก้ครั้งแรก** (เชื่อมแล้วออกโดยไม่แก้ = ไม่เกิดไฟล์ ไม่มี leave guard) · เลขต่อท้ายคำนวณตอนบันทึกจริง ⟨OQ54 ก⟩ · เปลี่ยนชื่อด้วยมือใน my-work ที่ชื่อซ้ำ = ปฏิเสธตามเดิม · **ชื่อหุ่น (ผู้ใช้ตัดสิน 2026-11-04 · OQ49, OQ55):** ชื่อ default **"หุ่น 1", "หุ่น 2" ตามลำดับที่เจอ** · เด็กตั้ง/แก้ชื่อได้**เฉพาะในหน้าเชื่อมต่อ** (ไม่มีที่แก้ใน workspace) · ใช้ชื่อบนแถบ/ปุ่ม · **ความเสี่ยงที่ผู้ใช้รับ:** ลำดับอาจเปลี่ยนทุกครั้งที่เสียบใหม่ เครื่องที่ต่อหุ่นตัวเดียวทุกเครื่องได้ "หุ่น 1" เหมือนกัน เด็กแยกตัวไม่แน่นอน (ชื่อเป็นข้อมูลความปลอดภัย) ⟨OQ55: แสดงพอร์ตต่อท้ายไหม · ผูกชื่อกับหุ่นอย่างไร (OQ5) · ชื่อซ้ำที่เด็กพิมพ์⟩ · **เชื่อมกลับเองเมื่อเป็นหุ่นตัวเดิม พักไว้รอ proof (OQ5)** ตอนนี้ใช้ปุ่ม "กลับหน้าเชื่อมต่อ" เท่านั้น · **กด "เปลี่ยนหุ่น" ไม่ขึ้น popup "งานยังไม่ได้บันทึก" (ผู้ใช้ตัดสิน 2026-11-04 · OQ42):** ไปหน้าเชื่อมต่อได้ทันที (ท่าและค่าอยู่ในไฟล์ ไม่ใช่ในหุ่น · งานไม่หาย) · ปุ่ม "กลับ Arm Lab" จากหน้าเชื่อมต่อกลับงานเดิมครบ

### รายละเอียดฟังก์ชัน 6A (Observed EV-03 · frame อนุมัติแล้ว ต้องรักษาไว้)
