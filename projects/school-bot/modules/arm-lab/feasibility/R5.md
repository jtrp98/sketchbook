## R5: ปุ่มหยุด · เตือน · ปิดปุ่มเมื่อหลุด
**ผล: ทำได้มีเงื่อนไข**
- ฟังก์ชันพื้นฐานมีใน 6A ทำได้ · เงื่อนไข:
  1. **ปุ่มหยุดไม่ถูกบัง** (AUD-F01 สูง · CR-10 ทาง ก): ต้องแก้แถบหน้าต่างที่ต้นฉบับ (app-shell OQ12) ก่อนใช้แถบใน Arm Lab · ต้นฉบับ z 80 > `z-stop` 70
  2. **ขัดกันในคำเดียว R5 ↔ R16:** R5 "ปิดปุ่มสั่งงานเมื่อหลุด" แต่ R16 "ปุ่มหยุดยังเห็นอยู่" → ต้องนิยามว่า "ปุ่มสั่งงาน" **ไม่รวมปุ่มหยุด** ปุ่มหยุดตอนหลุดไม่ใช้ `aria-disabled` แบบเทา (context.md: ปุ่มที่ดูใช้ได้แต่ไม่ทำงานเป็นข้อบกพร่อง AUD-F07) แต่ต้องมีผลชัด = เปิดข้อความวิธีหยุดทางกายภาพ
  3. **สถานะปุ่มหยุดที่ไม่ได้ระบุ:** ST-19 (ยังไม่เชื่อม) · ST-20 (กำลังเชื่อม) · ST-48 (กำลังพาไปท่าพัก/ล็อก) · ตอนกำลังเชื่อมหุ่นอาจกำลังเล่นโปรแกรมจากบอร์ดอยู่แล้วโดยแอปไม่ทราบ → ปุ่มหยุดต้องเห็นทุกหน้าที่หุ่นอาจขยับ (รวมหน้าเชื่อมต่อ SCR-13 ตามที่ R16 บอก) และพฤติกรรมตอนยังไม่ได้ต่อต้องไม่บอกว่า "หยุดแล้ว"
  4. **หยุดแล้วไม่ได้รับคำตอบ:** ส่งคำสั่งหยุดแต่ไม่มี ack/ timeout (E-NOREPLY) → ต้องไม่ขึ้น "หยุดแล้ว" ให้ตกไปข้อความ ST-21 (หยุดทางกายภาพ) · ไม่มีข้อกำหนดเวลา timeout (OQ14)
  5. **ออกจากตัวแก้ไข/สลับงาน/ปิดแอป ขณะหุ่นกำลังขยับ:** ☰ › งานของฉัน (Ctrl+O), งานใหม่ (Ctrl+N), sidebar, ปุ่ม ‹ หน้าหลัก, ปิดโปรแกรม (app-shell R5) · หน้าอื่นไม่มีปุ่มหยุด หุ่นเล่นต่อได้โดยผู้ใช้ไม่มีทางหยุดจากจอ → ต้องกำหนด (OQ15) · ข้อเสนอ: ห้ามออก/สลับขณะหุ่นขยับ จนกว่าจะกดหยุด (dialog "หยุดก่อนแล้วไปต่อ" ที่ไม่เขียนว่าหยุดแล้วถ้า firmware ไม่ยืนยัน)
  6. **dialog ปิดแอป (app-shell R5) เขียน "หยุดหุ่นแล้วจึงปิด"** ขัดกับห้ามเขียน "หุ่นหยุดแล้ว" (context.md · DEV-Q15) และทำไม่ได้ตอนหลุด → ฝั่ง app-shell ต้องปรับตาม (ระบุเป็นผลกระทบ module ที่พึ่งพา)
- ขีดจำกัดค่าและเตือน: ดู `R12.md` (R13, R15)

## R11: เชื่อมต่อหุ่น USB · สถานะ
**ผล: ทำได้มีเงื่อนไข**
- 4 สถานะ (ยังไม่เชื่อม/กำลังเชื่อม/เชื่อมแล้ว/หลุด) ใน R11 **ไม่ครอบคลุม** กรณีที่ ConnectV3 มีอยู่แล้ว: "เชื่อมต่อไม่สำเร็จ" (E-NOREPLY หุ่นไม่ตอบ · E-BUSY พอร์ตถูกใช้) ไม่มี ST ในรายการ (H1/H9 สูง-กลาง) → ควรเพิ่มสถานะ ST ใหม่ใน requirement ให้ตรงกับ frame (รายงานกลับ session หลัก)
- **เลือกผิดหุ่น (H5 สูงด้านความปลอดภัย):** wrapper "Many" ของ ConnectV3 แสดงหุ่นหลายตัว (หุ่นกลุ่ม 3 COM7 / กลุ่ม 5 COM9) ในห้องเรียนที่หุ่นหลายตัวต่อเครื่องเดียวกัน/พอร์ตสลับกัน เด็กเลือกผิดแล้วสั่งหุ่นของกลุ่มอื่นขยับ · ต้องมีทางยืนยันก่อนสั่ง (เช่น ชื่อหุ่นตรงกับป้ายบนตัวหุ่น หรือ firmware มีคำสั่งกะพริบไฟ) ซึ่งขึ้นกับ OQ5 (ชื่อหุ่นเก็บในหุ่นได้ไหม) → OQ14
- ชื่อ/พอร์ตจริงต้องมาจากข้อมูล (CR-08 ปิดแล้ว) ไม่ตายตัว · แถบหน้าต่างรับ prop
- driver/สิทธิ์ admin ดู `R1.md` (R2) · OQ14
- ข้อมูลอุปกรณ์ ENT-19 (ชนิด แขน Pi, พอร์ต, ชื่อหุ่น, สถานะ) · ชื่อหุ่น Delegated (OQ5)

## R16: หุ่นหลุดและเชื่อมกลับ (ST-21, ST-48)
**ผล: ทำได้มีเงื่อนไข (ความเสี่ยงสูงสุดของ module นี้ · พฤติกรรมหุ่นเป็น Unknown)**
ทิศทางของข้อกำหนดถูกต้อง (ไม่อ้างว่าหยุดแล้ว · ปุ่มหยุดคงอยู่ · ไม่มีทางข้าม) ที่ ruler ตรวจเพิ่มพบดังนี้

| # | ประเด็น | ระดับ | สิ่งที่ต้องทำ |
|---|---|---|---|
| 1 | **ท่า 0 ≠ ท่าพัก (ขัดกันเอง R12 ↔ R16):** R12 ระบุเป็นคนละท่า (EV-03) แต่ ST-48 ใช้ท่า 0 เป็นท่าพัก (Inferred) · ท่า 0 = "แขนตั้งตรง" ซึ่งอาจเป็นท่าสูงและไม่เสถียรกว่าท่าพักจริง ถ้าพาไปท่าที่ไม่ปลอดภัย = เสี่ยงหุ่น/เด็ก | สูง | ห้ามออกแบบข้อความที่ผูกชื่อ "ท่า 0" กับ "พัก" จนกว่าตอบ OQ11 · ใน design ใช้ชื่อกลางว่า "ท่าพัก" และเก็บเป็นค่าอ้างอิง ปรับได้ |
| 2 | **ตำแหน่งปัจจุบันของหุ่นไม่ทราบหลังเชื่อมใหม่** (อ่านค่าได้ไหมเป็น Unknown OQ11) → การเคลื่อนไป "ท่าพัก" อาจเป็นการขยับไกลและเร็ว ซึ่งเป็นสถานการณ์ที่ R15 ต้องเตือน (30°) แต่คำนวณระยะไม่ได้ | สูง | ถือว่า "ไกลเสมอ": ใช้เวลาเข้าท่านานสุดที่ปลอดภัย (ค่า Proposed 9000 ms · ยืนยันที่ OQ11/OQ14) + เตือนก่อน ไม่พึ่งการคำนวณมุม → OQ16 |
| 3 | **"ดูรอบหุ่นแล้ว" เป็นการยืนยันโดยเด็ก** ทำเป็นนิสัยโดยไม่ดูจริงได้ (ป.1) · ยอมรับได้เป็นด่านเสริมไม่ใช่ด่านหลัก ต้องบอกสิ่งที่ต้องดู ("มือและหน้าอยู่ห่างแขนหุ่น") และให้ครู/ผู้ใหญ่รับทราบสำหรับ ST-48 ถ้าเห็นสมควร | กลาง | ข้อความเฉพาะเจาะจง · Designer |
| 4 | **ST-48 ล็อกถาวร (ไม่มีทางข้าม) แต่ไม่มีทางออกที่ไม่ใช้หุ่น:** ถ้าพาไปท่าพักไม่สำเร็จ (หุ่นติด, firmware ไม่รองรับ) → วน ST-21 · นักเรียน/ห้องทั้งห้องใช้ Arm Lab ไม่ได้เลย และ "ไม่มีทางลัดกลับ Arm Lab" กำกวมว่า ST-21 ที่ดู/บันทึกได้คือ "Arm Lab" หรือไม่ (H3 ผู้ใช้ควบคุมได้) | สูง | นิยามโหมด "ไม่ใช้หุ่น" (ดู บันทึก ส่งออก ค้นหา แต่ปุ่มสั่งหุ่นปิดทั้งหมด) ที่เข้าได้จาก ST-21 และ ST-48 ไม่ใช่การข้าม · ผู้ใช้ยืนยัน → OQ15 |
| 5 | **ST-48 ไม่ครอบคลุม:** (ก) หลุดอีกครั้งระหว่างพาไปท่าพัก (ข) กดหยุดระหว่างพาไปท่าพัก (ค) พาสำเร็จแต่ไม่มี ack (ง) การเชื่อมต่อครั้งแรกในเซสชัน (ไม่ใช่หลังหลุด) ก็ไม่ทราบตำแหน่งหุ่นเช่นกัน แต่ R16 บังคับเฉพาะหลังหลุด (จ) สถานะ "กำลังพาไปท่าพัก" ต้องแสดง (H1) พร้อมปุ่มหยุดเห็นอยู่ | สูง | เพิ่มสถานะย่อยของ ST-48 · พิจารณาใช้กติกาท่าพักกับการเชื่อมต่อครั้งแรกด้วย (Proposed) → OQ16 |

| 9 | **ข้อความ ST-21 ถาวร ยาว + 3 ภาษา +40% + ป.1:** ต้องกระชับ มีไอคอน เป็นตัวตัดสินว่าอ่านรู้เรื่อง | กลาง | Designer · highlighter ตรวจ |

## ข้อมูลอ้างอิง (จาก Architect เดิม · ไม่ใช่ผลของ ruler)

### การเข้าถึง / เด็ก ป.1
- **สั่น = การเคลื่อนไหว:** สั่นครั้งเดียว 0.45s (`dur-shake`) ไม่เข้าข่าย WCAG 2.2.2 (เกิน 5 วินาที/อัตโนมัติ) และไม่ใช่แสงวาบ (2.3.1) · ผู้ใช้ตั้ง "ลดการเคลื่อนไหว" (2.3.3 เป็นระดับ AAA ไม่ใช่เป้าหมาย แต่ DS กฎการเคลื่อนไหวข้อ 3 บังคับทุก animation ต้องมีแบบ `prefers-reduced-motion`) = ไม่สั่น ใช้วง Attention Ring นิ่ง (ความเข้ม .5 ตาม DS) + popup ขึ้นเหมือนเดิม · **ห้ามใช้การสั่นเป็นตัวสื่อความเดียว** ข้อมูลต้องอยู่ในข้อความ/ไอคอนของ popup (WCAG 1.3.3/1.4.1)
- Attention Ring วนไม่หยุดเป็นข้อตัดสินของ DS อยู่แล้ว (ไม่ใช่ของใหม่) · ถ้าต้องการให้ผ่าน 2.2.2 เคร่งครัด ต้องมีทางหยุดวง (ไม่อยู่ในขอบเขตรอบนี้ · บันทึกไว้)
- **popup:** `role="alertdialog"` มีชื่อ · focus ย้ายเข้า popup ที่ปุ่มหลัก ("เชื่อมหุ่น") และวน focus ภายใน · Esc ปิด popup ก่อน (ตรงข้อเสนอ OQ13: มี popup เปิด = Esc ปิดสิ่งนั้น ไม่หยุดหุ่น) · ปิดแล้วคืน focus ให้ตัวที่กด · กดซ้ำตอน popup เปิดอยู่ = สั่นอีก ไม่ซ้อน ไม่ประกาศซ้ำกับ screen reader · ข้อความ 1 ประโยคสั้น + ไอคอน/มาสคอตเหมาะ ป.1 (ถ้อยคำตาม brand.md §7 · ruler ไม่กำหนดข้อความ) · ขนาดปุ่ม/ตัวอักษรตาม R1 (คง 6A) · การเด้งทุกครั้งที่กดทำให้รำคาญ/ถูกปิดเป็นนิสัย (OQ31 ข้อ ง)

7. **ปุ่ม/ชิป "เปลี่ยนหุ่น" ไม่โชว์ชื่อ vs เสี่ยงสั่งหุ่นผิดตัว vs brand §11.3/D2/OQ33 ข้อเดิม:** brand §11.3 ชิปอุปกรณ์แสดง "ชื่อ · พอร์ต · สถานะ" · D2 แสดงชื่อ · ผู้ใช้ตอนนี้: ชิปแสดง "เชื่อมต่อแล้ว/ยังไม่เชื่อมต่อ" ไม่ระบุชื่อ · popup ไฟล์ที่สอง "ใช้หุ่นเดิมต่อ" โดยไม่บอกว่าหุ่นไหน ในห้องที่มีหลายตัว/เครื่องใช้ร่วม (OQ33 ข้อ (3) ของ ruler เรื่อง logout ตัดการเชื่อมยังไม่มีคำตอบ) = เสี่ยงสั่งหุ่นของกลุ่มอื่น (H5) → OQ41
8. **สี:** ชิปแดง + popup พื้นแดงสำหรับ "ยังไม่เชื่อม" (สถานะเริ่มต้นปกติ ไม่ใช่ความผิดพลาด) ชนกับ DS: แดง = หยุด/error · ปุ่มหยุดแดงอยู่ใกล้ (ระวังเด็กไปกดหยุดเพื่อแก้) · ไฮไลต์ส้มทุกจุด (OQ34 ตอบแล้ว) ทำให้ส้ม "กดแล้วหุ่นขยับ" (DS) ไม่แยกจาก "เชื่อมหุ่น/เพิ่มท่า" ที่ไม่ขยับ → สัญญาณความปลอดภัยของส้มอ่อนลง · ถ้าเน้นชิปแดงด้วยวงส้ม = สองสีบนจุดเดียว → รวมใน OQ36
9. **เอกสารยังไม่ตามคำตัดสิน (ให้ session หลักแก้ตามกฎเปลี่ยน requirement):** R11 ยังเขียน "popup เตือนทุกการกด/ข้ามขั้นเมื่อไฟล์ที่สอง" (ไม่มี popup เลือกหุ่นเดิม/ใหม่ · ไม่มี OQ31 (ค) · ไม่มีชิป 2 สี) · R16 ไม่มี popup 1–4/ชิปแดง/ST-48 ใน Arm Lab (OQ32) · D2 ยังเป็นแบบ ST-48 ในหน้าเชื่อมต่อ · INDEX.md ตาราง R→D→OQ ยังไม่ติด OQ35–OQ41 และ "สถานะ" ยังเขียน OQ31–OQ34 `open` ทั้งที่ OQ31, OQ32 answered แล้ว (แก้ในรอบนี้บางส่วน) · OQ33 ถูกตอบสองรอบ (เลขข้อไม่ตรงกับของ ruler: "ข้อ (4) ปุ่มไม่โชว์ชื่อ" = ข้อ (5) ของ ruler) · OQ33 ข้อ (3) logout/ข้อ (6) ST-20 ไม่มีคำตอบ → รวมใน OQ41

### 3. แถบเหลืองหุ่นหลุด: หลุดระหว่างขยับ (ควบคุมไม่ได้) เทียบกับตอนนิ่ง (ผู้ใช้เลือกเหลืองทั้งสอง · ไม่เปลี่ยนการตัดสิน · ชี้ความเสี่ยงที่เหลือ)
- **แยกสองกรณีทางเทคนิคไม่ได้เชื่อถือ:** แอปรู้เฉพาะ "ส่งคำสั่งเล่นอยู่ตอนขาด" ไม่รู้ว่าหุ่นเล่นจากบอร์ดต่อหรือไม่ (OQ11 ทาง B) → "ตอนนิ่ง" ก็อาจยังขยับได้ จึงควรใช้ข้อความหยุดทางกายภาพชุดเดียวกันทั้งสองกรณี (ตรงที่ผู้ใช้ตัดสิน) แต่ต้องไม่ให้ "นิ่ง" สื่อว่าปลอดภัย
- **ความเสี่ยงของเหลือง (caution) สำหรับสถานะอันตราย:** DS ใช้แดง = หยุด/error · ป.1 อ่านสีก่อนข้อความ · เหลืองเท่ากับ "ไม่ด่วน" · เปรียบเทียบกับเหตุ "หุ่นขยับโดยแอปควบคุมไม่ได้" (RSK-A4 · R16 ข้อ 7 ความเสี่ยงสูง) · ความแตกต่างที่ควรเหลือไว้ได้ **โดยไม่เปลี่ยนสี:** ไอคอนนำ/ข้อความบรรทัดแรก ("หุ่นอาจยังขยับ" เทียบ "หุ่นหลุดแล้ว") · live region แบบ assertive สำหรับกรณีขยับ / polite สำหรับนิ่ง · อย่าใช้สีเป็นตัวสื่อเดียว (WCAG 1.4.1) → OQ47 ให้ผู้ใช้เลือกว่าจะยอมให้ข้อความต่างกันตามกรณีหรือไม่

3. **(สูง · ขึ้นกับ dev) ระบุ "หุ่นตัวเดิม" (OQ61 วิธีตรวจ):** auto-connect ปลอดภัยเฉพาะเมื่อมี ID ที่เชื่อถือได้ (serial ของ USB/Pi · พอร์ตเดียวกันไม่พอ: ห้องเรียนสลับสาย/หุ่นได้ และชื่อ "หุ่น 1" ซ้ำทุกเครื่อง OQ55) · ถ้า dev ทำไม่ได้ ต้องมีทางสำรอง (ไม่เชื่อมเองเลย / ถามเด็กยืนยัน) → **OQ64** · การเชื่อมเองต้องไม่ส่งคำสั่งขยับใด ๆ (handshake อย่างเดียว · ไม่ส่งคำสั่งค้างตอนหลุดซ้ำ) = เงื่อนไขก่อนส่ง dev
4. **(กลาง) R11 ขัด R16 ใหม่:** R11 ยังเขียน "เชื่อมกลับเองเมื่อเป็นหุ่นตัวเดิม พักไว้รอ proof (OQ5) ตอนนี้ใช้ปุ่ม 'กลับหน้าเชื่อมต่อ' เท่านั้น" · ประโยค "ข้อความด้านล่างที่ขัด…ถูกแทน" ใน R16 ไม่ครอบ R11 (อยู่ด้านบน) และ R16 ยังมีประโยค "แถบเขียว+นับวินาที พักไว้รอ proof (OQ5)" ค้าง → session หลักแก้ R11/R16 ตามกฎเปลี่ยน requirement (ไม่ต้องถามผู้ใช้ · เป็นผลของคำตัดสิน 2026-11-05)
5. **(กลาง · H3/a11y) ฉากหลังไม่คลุมแถบ N1:** ถ้า N1 "เห็นได้" อย่างเดียว ก็ต้องเป็น inert (modal ตาม WCAG/aria-modal) · ถ้า N1 "กดได้" (☰ บันทึก ส่งออก บ้าน ชิปหุ่น) ต้องตัดสินว่ากดแล้วทำอะไร ขณะ modal เปิด (เมนูขึ้นทับ modal? ปิด modal ก่อน?) · และ focus trap ต้องรวม N1 ด้วย → **OQ65**
6. **(กลาง) หลุดซ้ำระหว่าง modal "ต่อกลับแล้ว" / ระหว่างกำลังไปท่าพัก:** ไม่ระบุ · ข้อเสนอ: แทนที่ (ไม่ซ้อน) ด้วย modal หลุดทันที · ระหว่างไปท่าพักห้ามแสดง "ถึงท่าพักแล้ว" · ตำแหน่งไม่ทราบ · พอกลับมาขึ้น "ต่อกลับแล้ว" ใหม่ · กันกระพริบ/ประกาศซ้ำเมื่อสายกระตุก (OQ53 ค) → **OQ68**
7. **(กลาง · H9) state ที่ขาด:** (ก) หุ่นไม่ตอบแต่สายยังเสียบ (R16 นับเป็นหลุด) → modal "สายหุ่นหลุด · เสียบสายกลับ" ผิดความจริง (ข) ตรวจพบหุ่นเดิมแต่เชื่อมเองไม่สำเร็จ (พอร์ตถูกใช้/ไม่ตอบ) ชิปค้าง "กำลังเชื่อมต่อ..." หรือกลับ "ขาดหาย" + บอกอะไร (ค) ไปท่าพักล้มเหลว/ไม่มี ack (OQ14) (ง) modal หุ่นตัวอื่น: ปุ่มครบไหม (มี "ปิดไว้ก่อน" ไหม) และเสียบหุ่นตัวอื่นตอนแถบเหลืองเปิด (ปิดไว้ก่อนแล้ว) ขึ้น modal เองไหม → **OQ68**
8. **(กลาง) อยู่หน้าอื่นตอนหลุด/ตอนหุ่นกลับ:** หน้า Home/งานของฉัน (มีชิปบน N1 ของ app-shell) และหน้าเชื่อมต่อ (ไปจากปุ่ม "เปลี่ยนไปใช้หุ่นตัวอื่น" แล้วเสียบหุ่นเดิมกลับ: เชื่อมเอง หรือแสดงในรายการให้เลือก) · R16 ระบุเฉพาะใน Arm Lab · กระทบ app-shell R4 → **OQ65**
9. **(ต่ำ) ลำดับชั้น (OQ39 ยังเปิด) ต้องปรับ:** เสนอ: ประคองแขน > modal หลุด/ต่อกลับ/หุ่นตัวอื่น (แทนกัน ไม่ซ้อน) > แถบเหลือง > dialog ระบบ (กู้คืน/leave guard: หลุดขณะเปิด → ?) > popup ขยับครั้งแรก (หลุดขณะเปิด → ปิด แล้วขึ้น modal หลุด) > popup เตือนเชื่อมหุ่น · ปุ่มหยุด `z-stop` เหนือทุกอย่าง · กรณี dialog ระบบเปิดอยู่ตอนหลุด รวมใน **OQ68**
10. **(ต่ำ) ชิปหุ่นบน N1:** "การเชื่อมต่อขาดหาย" ไอคอนแดงตามภาพอ้างอิง ขัดข้อตัดสิน DS "สถานะเตือนอุปกรณ์ = ไอคอน `warning-strong` + ข้อความ `text-primary`" (ds-build 2026-11-04) = **DS ขัดกับคำสั่ง** ผู้ใช้ตัดสิน → **OQ69** · กระทบ app-shell (ชิปเป็นของกลาง)

### 3. DS gap (ไม่เติมค่า · ห้าม agent แก้ DS)

- DS gap: ฉากหลัง dialog ที่เว้นแถบ N1 (ไม่เบลอ/ไม่คลุม) + เว้นปุ่มหยุด · ใช้ที่ modal หลุด/ต่อกลับ/หุ่นตัวอื่น · ใกล้เคียงที่สุดใน DS: `sb-scrim-lab` (เว้นเฉพาะมุมปุ่มหยุด · ยังไม่ยืนยันว่าเว้น N1) · ต่อจาก OQ34 ข้อ 2
- DS ขัดกัน (ไม่ใช่ gap): ชิปสถานะขาดหายสีแดง vs `warning-strong` (ข้อ 2.10) · ชิป spinner "กำลังเชื่อมต่อ..." ใช้ spinner ชั่วคราว

### 4. memory "ออกจากหน้าเชื่อมแล้วต้องใช้งานได้ ไม่มีติ๊ก/ท่าพักซ้ำ"
- **เชื่อมครั้งแรก:** หน้าเชื่อมต่อ → กลับ Arm Lab ใช้ได้ทันที ไม่มีขั้นกั้น ✓ · popup ขยับครั้งแรก = ติ๊กก่อนเล่น (ST-24 แบบใหม่) ซึ่ง memory ระบุว่า "คนละเคส ต้องคงไว้" ✓
- **หลุดแล้วเสียบกลับใน Arm Lab:** จบที่ modal ต่อกลับแล้วที่เดียว ✓ · checkbox + พาไปท่าพัก นับเป็นติ๊ก ไม่ถามซ้ำ ✓ · กด "ข้าม" → ติ๊กยังรีเซ็ต popup ขึ้นตอนสั่งขยับครั้งแรก (เป็นติ๊กก่อนเล่น ไม่ใช่ท่าพักซ้ำ) ✓ · แต่ modal ต้องกด 1 ครั้งก่อนทำงานต่อ = ขั้นเดียว (ไม่ซ้ำสองที่) ✓
- **พับแขนในหน้าเชื่อมต่อ:** popup ขยับครั้งแรกขึ้นเฉพาะยังไม่ติ๊ก ✓ (ไม่ใช่ติ๊กแยก)
- **ข้อสังเกต (ไม่ผิดตัวอักษร):** เปิดไฟล์/Ctrl+N ต้องเชื่อมใหม่ → ติ๊กรีเซ็ตทุกไฟล์ · เด็กที่เปิดหลายไฟล์ในคาบเดียวกับหุ่นตัวเดิมจะเจอหน้าเชื่อมต่อ + popup ติ๊กทุกไฟล์ = เสี่ยง "ติ๊กเป็นนิสัย" ตามเหตุผลใน memory · ผู้ใช้ตัดสินแล้ว (OQ65 ข) ไม่เปิด OQ · ธงให้ highlighter
- **ไม่พบขั้นท่าพักบังคับ** ในเอกสารปัจจุบัน (R16 ท่าพักเป็นทางเลือก) ✓

### 6. DS gap (ไม่เติมค่า · ห้าม agent แก้ DS)
- DS gap: การสั่นของปุ่ม (keyframe ของ `sb-btn` บนแถบ nav) + แบบ reduced-motion · ใช้ที่ ปุ่ม "เชื่อมหุ่น" บนแถบ N1 (Arm Lab) · ใกล้เคียงที่สุดใน DS: `dur-shake` 0.45s (มีแต่ duration) + Attention Ring (มีกฎ ไม่มี preview) → **OQ78** (แทนส่วน "popup สั่น" ของ OQ34 ข้อ 1)
- ค้างจากรอบ 7 (ผู้ใช้อนุมัติแล้ว รอเติม): `sb-progress` · variant `sb-scrim-lab` เว้นแถบ nav · spinner ในชิปยังเป็นค่าชั่วคราว (ds-build ข้อ 6) (OQ69)
