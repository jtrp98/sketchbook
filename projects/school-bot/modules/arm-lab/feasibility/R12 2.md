# Arm Lab: Feasibility R12–R15, R17 (ฟังก์ชัน 6A: ท่า · ข้อต่อ · แก้/อ่านท่า · เล่น · เมนูและคีย์ลัด)

ตรวจโดย ruler 2026-10-21 · ข้อมูล ENT และ BUG อ้างอิงจาก Architect เดิม (ตาราง BUG ดู `../feasibility.md`) · ความรุนแรง สูง/กลาง/ต่ำ ตาม CLAUDE.md

## R12: ท่าและท่าชุด
**ผล: ทำได้มีเงื่อนไข**
- ตรวจ: ท่า 0 แก้ไม่ได้ (UI ต้องบอกเหตุผล ไม่ใช่แค่จาง) · BUG-05 (tooltip G/K สลับ) แก้ตามโค้ด · ท่า 0 ≠ ท่าพัก ขัดกับ R16 (ดู `R5.md`)
- **เลิกทำ 6 วินาที (H3/H5 กลาง-สูง):** ลบ/ตัด/วางท่าหายถาวรเมื่อพ้น 6 วินาที · ป.1 อ่าน/ตัดสินใจไม่ทัน · WCAG 2.2.1 · context.md "ไม่มีแรงกดดันด้านเวลาโดยไม่จำเป็น" · เสนอให้ยืดหรือมีที่เก็บท่าที่ลบ (ประวัติ ENT-23 ปัจจุบันเป็นแค่ log) → OQ17 · BUG-11 (ลบท่าในตารางไม่ยืนยัน แต่ในแผงกด 2 ครั้ง) ต้องทำให้สม่ำเสมอ
- **ขาดนิยาม (กลาง):** (1) การเรียงลำดับท่า (ลาก? ปุ่มขึ้น/ลง? ต้องมีทางไม่ลาก WCAG 2.5.7) (2) ท่าชุด K####: สร้าง/แก้/เล่น/เด็กเข้าใจได้ไหม ใน requirement มีแค่สีและรหัส (3) จำนวนท่าสูงสุด (ขึ้นกับบอร์ด OQ14) (4) การเล่นเมื่อมีท่าเดียวหรือไม่มีท่า → เหตุผลที่ปุ่มเล่นปิด (5) BUG-09 `recoverYes` พังเมื่อท่า < 3 → OQ20 (1)(2)
- ENT ที่เกี่ยว (เดิม): ENT-14 ท่า (G####, ค่าข้อต่อ S0–S5, มือคีบ %, เวลา ms · แก้ที่ SCR-12 · ท่า 0 แก้ไม่ได้) · ENT-15 ท่าชุด (K####) · ENT-23 ประวัติ (การกระทำ เวลา)

## R13: ข้อต่อและขีดจำกัด
**ผล: ทำได้มีเงื่อนไข**
- ขีดจำกัดชัด (S0 ±180 · S1–S4 ±135 · มือคีบ 0–100% · 1000–9000 ms) ตรวจได้ แต่:
  1. **"ป้องกันหรือเตือน" กำกวม (H5 สูง):** ค่าที่พิมพ์เกินต้อง clamp, ปฏิเสธ หรือเตือนแล้วยอม? เมื่อค่ามีผลทันทีกับหุ่น (R14) การ "เตือนแล้วยอม" ส่งค่านอกขอบเขตไปหุ่นได้ → ข้อเสนอ: ไม่ส่งค่านอกขอบเขตไปหุ่นเลย (clamp + แจ้ง) → OQ17
  2. **ค่าระหว่างพิมพ์:** พิมพ์ "180" ผ่าน "1","18","180" ถ้าแต่ละการกดส่งคำสั่ง หุ่นกระตุก/ขยับผิด → ใช้ค่าเมื่อกดยืนยัน/ออกจากช่อง (Enter/blur) และกันช่องว่าง/ตัวอักษร/ทศนิยม/ลบอย่างเดียว/เลขไทย → OQ17
  3. **ขนาดก้าวไม่สม่ำเสมอ (BUG-11):** กดค้าง 3° vs พิมพ์/ลูกศร 1° · และอัตราการเกิดซ้ำตอนกดค้างต้องไม่ทำให้หุ่นขยับเร็วกว่าที่ปลอดภัยโดยไม่ผ่านเตือน 30° (สะสมหลายก้าว) → OQ17
  4. **ค่าเริ่มต้นไม่สอดคล้อง (BUG-06):** เวลาท่า 0 ตาราง 2000 vs `POSE0.t` 3000 · มือคีบท่าใหม่ 0% vs ท่า 0 50% (มือคีบเปลี่ยนฉับพลันเมื่อเล่นท่าแรก) · ต้องเลือกค่าเดียว Proposed: เวลา 3000 ทุกท่า · ท่าใหม่คัดลอกค่าจากท่าก่อนหน้า (ท่าแรก = ท่า 0) → OQ17
  5. หน่วย "ms" และ "°" สำหรับ ป.1 → แสดงเป็นวินาที (ดู `R1.md` R10) · ไฟล์ .ini ยังเป็น ms
  6. S0 ±180° ปลายทั้งสองห่าง 360° ผ่านหลังหุ่น: ท่าจาก +170° ไป −170° เป็นการหมุน 340° ไม่ใช่ 20° → นิยามของ "ไกลเกิน 30°" (ดู R15) ต้องไม่ใช้ระยะทางสั้นสุดแบบวงกลม
- ค่ามาจากข้อสมมติ 6A (Observed) · ขีดจำกัดจริงของ Pi/ฮาร์ดแวร์ ยืนยัน firmware (OQ1, OQ12) · ขีดจำกัดทางกลที่ไม่เท่ากันต่อข้อต่อ (S1–S4 ชน/ชนโต๊ะ) ไม่ระบุ

## R14: แก้ท่า อ่านท่าปัจจุบัน ประวัติ
**ผล: ทำได้มีเงื่อนไข (ฟีเจอร์ "อ่านท่าปัจจุบัน" ขึ้นกับ firmware)**
- ตรวจ "ต้องให้หุ่นอยู่ที่ท่านั้นก่อนจึงแก้ได้": ไม่ได้ระบุ (1) กลไก "ไปท่านั้น" (ปุ่ม? อัตโนมัติเมื่อเลือกท่า? ใช้เวลาเท่าใด? เตือนไกลเกิน 30°?) (2) สถานะ "กำลังไปท่า" (H1) และเมื่อไม่ถึงท่า/ไม่มี ack (3) แก้ท่าเมื่อยังไม่เชื่อม/หลุด (R16 ว่าแก้ไม่ได้ แต่ ST-19 ไม่ได้ระบุ → สรุปว่านักเรียนที่ยังไม่ต่อหุ่นสร้าง/แก้ท่าไม่ได้ ซึ่งขัดกับการเตรียมงานล่วงหน้าและอาจไม่ใช่เจตนา) → OQ17 ข้อ "แก้ท่าตอนยังไม่เชื่อม"
- **ปลดล็อกข้อต่อ (คลายแรงบิด) = ความเสี่ยงต่อมือเด็กและหุ่น (สูง):** แขนอ่อนตกตามแรงโน้มถ่วง โดยเฉพาะท่า 0 ตั้งตรง · มี "เตือน + นับถอยหลัง" แล้ว แต่ต้องกำหนด: ยกเลิกได้ระหว่างนับ · วิธีล็อกกลับ · ต้องประคองแขนก่อน · ตอนหลุดขณะแขนอ่อน (ล็อกกลับไม่ได้) · เปิดให้ ป.1–6 ใช้เองหรือเฉพาะโหมดครู → OQ18
- "อ่านค่าตอนคลายแขน" บน Pi ยังไม่ยืนยัน (OQ1/OQ12): ถ้าไม่ได้ ต้องถอดปุ่ม "อ่านท่าปัจจุบัน" และขั้นตอน "ปลดล็อก" ทั้งชุด (ลดความเสี่ยงไปด้วย) → ทางเลือกคือกรอกมุมเอง
- ต้องใช้คำ "อ่านท่าปัจจุบัน" (brand §7) · ประวัติ (ENT-23): เก็บที่ไหน นานเท่าใด ใครเห็น (เก็บเท่าที่จำเป็น NFR-05) ไม่ระบุ → ต่ำ ส่ง dev

## R15: การเล่น
**ผล: ทำได้มีเงื่อนไข**
- ตรวจ **"เตือนเมื่อสั่งขยับไกลเกิน 30°" (ST-23) ทำไม่ได้ตามข้อความปัจจุบันในบางกรณี (สูง):** ไม่ระบุว่า (ก) วัดต่อข้อต่อหรือรวม (ข) วัดจากไหน: ท่าก่อนหน้าในลำดับ หรือตำแหน่งจริงของหุ่น (ไม่ทราบหลังเชื่อมใหม่/แขนอ่อน/เชื่อมครั้งแรก) (ค) **ท่าสุดท้ายวนกลับท่าแรก** เมื่อเล่นหลายรอบ/วนไม่หยุด ไม่ปรากฏในลำดับแต่เป็นการเคลื่อนที่จริง (ง) มือคีบ (%) ไม่มีหน่วยองศา (จ) เตือนครั้งเดียวก่อนเล่นทั้งลำดับหรือทุกก้าว (เด็กกดผ่านจนชิน = เตือนแล้วไม่ได้ผล) ข้อเสนอ: ตรวจทั้งลำดับก่อนเริ่ม รวมท่าแรกจากตำแหน่งที่ไม่ทราบ (ถือว่าไกล) และท่ากลับ แล้วเตือนครั้งเดียวพร้อมลิสต์ก้าวที่ไกล → OQ16
- **ติ๊ก "ดูรอบหุ่นแล้ว" (ST-24):** ไม่ระบุว่ารีเซ็ตเมื่อใด (ทุกครั้งที่เล่น / ทุกเซสชันเชื่อม / เมื่อหลุด ST-48) → Proposed: รีเซ็ตทุกการเชื่อมต่อใหม่ + เมื่อแก้ลำดับท่าหลังติ๊ก → OQ16
- **เล่นจากบอร์ด/อัปโหลดลงบอร์ด (H1/H5/H9 สูง):** ไม่มีสถานะกำลังอัปโหลด (progress) · อัปโหลดล้มเหลว/หลุดกลางทาง → โปรแกรมบนบอร์ดค้างครึ่ง ๆ กลาง ๆ หรือเก่าของกลุ่มอื่น (หุ่นร่วมกันหลายกลุ่ม: "หุ่นกลุ่ม 3/5") · "เล่นจากบอร์ด" รันโปรแกรมที่ไม่ใช่งานบนจอ → ต้องบอก "โปรแกรมที่อัปโหลดล่าสุดเมื่อ…" และเขียนทับต้องแจ้ง · จำนวนท่าสูงสุดบนบอร์ด · เล่นต่อเองตอนเปิดไฟ (OQ14) · ST-21 ขณะ "เล่นจากบอร์ด": แอปไม่รู้ว่าหุ่นยังเล่นอยู่
- เลือกช่วงท่า/รอบ: ตรวจ (H5) ช่วงกลับด้าน/ว่าง · รอบ 0, 10, ว่าง, ทศนิยม · ลบท่าที่อยู่ในช่วงที่เลือก · แก้ลำดับขณะเล่น (ควรล็อกแก้ท่า/ลำดับขณะ ST-22) · วนไม่หยุด (ST-23) ต้องมีทางหยุดชัดและ ป.1 เข้าใจ "ไม่หยุดเอง" · ไม่ระบุว่ามีหยุดอัตโนมัติเมื่อไม่มีการใช้งาน
- **สถานะเล่นเสร็จ/หยุดผิดปกติ (H1):** ไม่มีสถานะ "เล่นจบ" / "หยุดกลางทางเพราะไม่ตอบ" ในรายการ ST → ควรเพิ่ม
- ปุ่มหยุดสีแดง "อยู่ข้างปุ่มเล่น" ขัดกับ context.md "อยู่ห่างจากปุ่มสั่งให้ทำงาน" (กดผิดปุ่ม) · ตำแหน่งตายตัวตาม brand D-01 (ปุ่มกลม/ตำแหน่งตายตัวทุกหน้า) → Designer ตัดสินและบันทึกเหตุผล ต้องไม่ใกล้จนแตะผิด (เป้า ≥ 44px + ระยะห่าง)
- ENT-16 การตั้งค่าการเล่น (ช่วงท่า, รอบ 1–9/วน, โปรแกรม/บอร์ด)

## R17: เมนู ☰ และคีย์ลัด
**ผล: ทำได้มีเงื่อนไข**
- เมนู: รายการครบกับ my-work R5/R6/R9 ✓ · เมนูครูมีใน ☰ · "เกี่ยวกับ School Bot Studio" ✓
- **คีย์ลัดชนมาตรฐาน (BUG-10 · กลาง):**
  - **Mac ใช้ ⌘ ไม่ใช่ Ctrl** (HM5, HF15): requirement เขียน Ctrl+… ทุกตัว ต้องระบุการจับคู่ Windows Ctrl / Mac ⌘ และแสดงตามระบบ · ⌘H = ซ่อนแอป (ระบบ) ชนกับ "ประวัติ" และแอปมีปุ่ม "ซ่อน" ของตัวเองอยู่แล้ว (app-shell R2) · ⌘A = เลือกทั้งหมด ในช่องกรอกมุม/เวลา (R13) ซึ่งเป็นการใช้ปกติ · Ctrl+H ใน Windows = แทนที่ในหลายโปรแกรม (ชนน้อยกว่า)
  - ข้อเสนอ: เปลี่ยน "นำเข้า (Ctrl+A)" และ "ประวัติ (Ctrl+H)" เป็น shortcut อื่นที่ไม่ชนระบบ หรือไม่มี shortcut (ป.1–6 ไม่ได้ใช้คีย์ลัด) แต่คงรายการใน ☰ · คงคีย์มาตรฐาน S/N/O ตามหน้าที่เดิม (HM5)
  - **Esc หยุดหุ่นทั้งหมดตอนไม่มีอะไรเปิดอยู่ (Inferred):** ทิศทางปลอดภัย (หยุดคือด้านปลอดภัย) จึงควร**คงไว้เป็นทางลัดเสริม** ไม่ใช่ทางเดียว · กติกาที่ต้องเขียน: ในช่องกรอก Esc = ยกเลิกการแก้ค่า (ไม่หยุด) · มี dialog/popover เปิด Esc = ปิดสิ่งนั้น · ที่เหลือ Esc = หยุด · ห้ามเขียน "หยุดแล้ว" ถ้า firmware ไม่ยืนยัน (เหมือน R16) · ต้องแสดงบนปุ่มหยุด (tooltip ไม่พอ ไม่มี hover → ข้อความกำกับ) · Mac ผู้ใช้อาจกด Esc เพื่อออกเต็มจอ/ปิดอื่น → ต้องไม่ทำให้หยุดโดยไม่ตั้งใจจนเด็กงง (ไม่มีอันตราย แต่ต้องบอกสถานะ) · ปิดไว้ไม่ได้ block → OQ13 (ruler เสนอเพิ่ม)
  - ใน design ต้องไม่ให้ปุ่มหยุดหายหรือกดพลาดเพราะย้ายคีย์ลัด (ตามที่ OQ13 ระบุ)
- **งานใหม่ (Ctrl+N):** ใช้ leave guard เดียวกับ ☰ › งานของฉัน ✓ แต่ต้องเพิ่มกรณีหุ่นกำลังขยับ (OQ15) · "บันทึกก่อนสลับ" เมื่อ sync ไม่สำเร็จ → leave guard แสดงทางเลือก (my-work) ใช้ซ้ำได้
- ตามแนว HM3: คำสั่งทุกตัวควรอยู่ในเมนู · แอปมีเมนูของตัวเองใน ☰ + แถบ Mac menu bar ของระบบ (ต้องมีขั้นต่ำ Quit/Hide/Settings ตามระบบ · เรื่อง dev/app-shell)
