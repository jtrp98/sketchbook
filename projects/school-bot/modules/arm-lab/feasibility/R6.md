## R6: บันทึกบน cloud
**ผล: ทำได้มีเงื่อนไข**
- สถานะบันทึก 4 แบบอยู่ที่แถบหน้าต่าง (app-shell R3) ใน Arm Lab ใช้ซ้ำได้ ไม่ต้องทำซ้ำ · H1/H9 ครอบคลุม (E-CLOUD)
- **ฉบับใหม่กว่าชนะ ขัดกับ "ไม่เสียงาน" (สูง · H5/H9):** EC-01 บอกเน็ตหลุดแล้วไม่เสียงาน แต่ R8 (my-work) ให้ฉบับใหม่กว่าทับฉบับเก่า และ "ใหม่กว่า" วัดจากอะไรยังเป็น Unknown (นาฬิกาเครื่องโรงเรียนอาจผิด) · เด็กที่ทำท่าหุ่นออฟไลน์ครึ่งชั่วโมงอาจเสียงานเงียบ ๆ โดยเห็นแค่ข้อความ "ถูกแทนด้วยฉบับใหม่กว่า" → ข้อเสนอ: เก็บฉบับที่ถูกแทนเป็นสำรองในเครื่องให้กู้คืนได้ (ใช้กลไก R8) · (เกิดที่ my-work เป็นหลัก ruler เปิด OQ21 ใน arm-lab เพื่อติดตามผลกระทบ และแจ้ง session หลักให้ยกเข้า my-work OQ2)
- **ส่งงานไปหุ่นขณะ sync ไม่สำเร็จ:** USB กับ cloud เป็นอิสระต่อกัน (R16 บอกบันทึกได้ตอนหุ่นหลุด) · ต้องไม่ผูกปุ่มหยุด/เล่นกับสถานะ sync
- **"บันทึกสำเนา…" (R17):** requirement ไม่ได้ระบุ: ตั้งชื่อ ชื่อซ้ำ แล้วอยู่ที่งานเดิมหรือสลับไปงานสำเนา → Designer ตัดสินและบันทึกเหตุผล (my-work R5 ระบุ error ชื่อว่าง/ซ้ำสำหรับเปลี่ยนชื่อ ให้ใช้กติกาเดียวกัน)

## R7: export .ini
**ผล: ทำได้มีเงื่อนไข**
- ทำได้แม้ออฟไลน์/หุ่นหลุด (เป็นงานในเครื่อง) · ต้องระบุว่าข้อมูลที่ export ตรงกับสถานะบนจอ (รวมการแก้ที่ยังไม่ sync)
- เงื่อนไข: "เปิดใน Zide ได้" ขึ้นกับ OQ1 (โครงสร้างค่าของหุ่น Pi) · ค่า/โครงสร้างต้องผ่านขีดจำกัด R13 · ท่า 0 และท่าชุด (K####) ต้องกำหนดว่า export/ไม่ export อย่างไร
- สถานะที่ต้องมี (H9): export ไม่สำเร็จ (ไม่มีสิทธิ์/ดิสก์เต็ม/ชื่อไฟล์มีอักขระต้องห้ามของ Windows/Mac · ชื่อไทย) · ชื่อไฟล์ตั้งต้นจากชื่องาน

## R8: กู้คืนสำรองในเครื่อง
**ผล: ทำได้**
- ตรงกับ my-work R3/SCR-10/ST-18 (FRM-07 ยังไม่ออกแบบ · เป็นของ my-work)
- ข้อควรกำหนด: สำรองทุก 10 วินาทีเป็นการเขียนดิสก์ถี่ → dev ตรวจผลกับเครื่องโรงเรียนช้า · สำรองต้องไม่มีสถานะหุ่น (ไม่ restore ท่าที่ "หุ่นอยู่") และหลังกู้คืน หุ่นจะไม่อยู่ที่ท่าใด → การแก้ท่าต้องรอไปท่านั้นก่อน (R14) ซึ่งทำให้ UI ต้องสื่อได้ว่า "ยังไม่ได้ไปท่านี้"

## R9: นำเข้า .ini (?)
**ผล: ทำได้มีเงื่อนไข (ยังรอ OQ4)**
- ทางเทคนิคทำได้ (frame ทำปุ่มแล้ว EDIT-04) และไม่ block ออกแบบ · ขาดกติกา (H5/H9):
  1. ตรวจไฟล์: ไม่ใช่ .ini / เสียหาย / จาก Zide ที่ขีดจำกัดต่างกัน (ค่าเกิน ±180/±135, เวลานอก 1000–9000) → ต้องกำหนด "ปรับให้อยู่ในขอบเขตและแจ้ง" หรือ "ปฏิเสธ" (ข้อเสนอ: ปฏิเสธพร้อมบอกบรรทัด/ท่าที่เกิน ไม่ปรับเงียบ ๆ เพราะค่านำเข้าสั่งหุ่นจริง)
  2. รหัสท่าซ้ำ (G####/K####) · ท่าเกินจำนวนที่บอร์ดรับ (Unknown OQ14) · ไฟล์ใหญ่
  3. นำท่าเข้ามาต่อท้าย/แทนที่ (dialog "นำท่าจากงานอื่นมาต่อ" ใน my-work R9 บอกแค่ "นำท่ามาต่อ") · เลิกทำได้ไหม
  4. ไม่มีเน็ต: ใช้ได้เฉพาะนำเข้าไฟล์ (my-work R9) ✓
  5. สถานะกำลังอ่านไฟล์ (H1) และรหัส error ใหม่ (เช่น E-IMPORT) · ใช้ถ้อยคำตาม brand §7
- OQ4 ซ้ำกับ my-work OQ4 (Proposed: อยู่ในขอบเขต)
