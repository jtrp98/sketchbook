# school-bot-web feasibility · R1: login 2 บทบาท (ครู + นักเรียน) · เมนูตามบทบาท

**ผล: ทำได้มีเงื่อนไข** (2026-11-11 · ruler · ตรวจตาม R1 ฉบับแก้ 2026-11-11) · ตารางด้านล่างหัวข้อ "ข้อมูลอ้างอิงเดิม" เป็นของ Architect เดิม (ก่อนมีบทบาทนักเรียน)

## ผลตรวจ ruler 2026-11-11

**ไม่ขัดกันเอง** · OQ3 (2026-10-20 "MVP มีครูอย่างเดียว") ถูกแทนด้วย OQ15/OQ18 แล้ว ไม่นับเป็นข้อขัด

**ตารางสิทธิ์ที่ได้จาก R1 + กฎ "สิทธิ์ตามบทบาท"**

| หน้า | ครู | นักเรียน | ยังไม่ login |
|---|---|---|---|
| Guideline (R9–R14) | เห็น | เห็น | ไป login (ดูข้อ 3) |
| ภาพรวมห้อง/รายคน/ตั้งค่า/แก้ปัญหาหุ่น (R3–R6) | เห็น (เฉพาะห้องที่สอน R7) | ไม่มีสิทธิ์ (ST-37) | ไป login |

**ช่องว่าง/เงื่อนไข**
1. **หน้า login (block ออกแบบ SCR-21 เท่านั้น):** R1 ไม่บอกว่าหน้าเดียวมี 2 ทาง (ปุ่ม SSO ครู + ฟอร์มนักเรียน) หรือแยกหน้า · ขั้นตอนนักเรียนในแอปคือ โรงเรียน → username → password (`app-shell` R6) · → OQ31 (เปิดอยู่) · ฟอร์มนักเรียนต้องมีสถานะเดียวกับแอป: รหัสผิด (ST-07), ค้นโรงเรียนไม่พบ (ST-06), ลืมรหัส "บอกครูให้ช่วยรีเซ็ต" (ST-08 · ทางที่ครูรีเซ็ตยังไม่มี → OQ8)
2. **ที่มาบัญชีนักเรียน (block ส่ง dev ไม่ block ออกแบบ):** "บัญชีเดียวกับในแอป" ต้องใช้ระบบยืนยันตัวตนเดียวกับ `app-shell` R6 ซึ่งยังขึ้นกับ API SchoolBright ข้อ (2) login นักเรียน (OQ1 เปิดอยู่)
3. **เข้าลิงก์ตรงโดยยังไม่ login / session หมดอายุ:** requirement ไม่ระบุ · เงื่อนไข: ไป login แล้วกลับมาหน้าที่ขอ (บท Guideline เดิม) · เนื่องจาก phase 1 ไม่เก็บสถานะ (R9) session หมดอายุกลางบท = ขั้นต่อสายและสถานะรันหายทั้งหมด ต้องบอกผู้ใช้ก่อนส่งไป login (H1, H9)
4. **หน้าแรกหลัง login:** ครู = ภาพรวมห้อง (เดิม) · นักเรียนเห็นเมนูเดียวจึงต้องเป็น Guideline (สรุปได้จาก R1 ไม่ต้องถาม)
5. **นักเรียนเปิดหน้าครูโดยตรง:** ใช้ ST-37 ได้ แต่ข้อความเดิมของ ST-37 คือ "ไม่มีสิทธิ์ดูห้องนี้" (กรณีครูกับห้อง) · ต้องมีข้อความอีกแบบสำหรับนักเรียน + ปุ่มกลับไป Guideline (H9) · เมนูของครูต้องไม่อยู่ใน DOM/แถบเมนูของนักเรียน (ไม่ใช่แค่ทำเป็นเทา)
6. **Guideline ต้องไม่พึ่งข้อมูลห้องจาก SchoolBright:** ครูที่ยังไม่มีห้อง (R7) หรือ SchoolBright ล่ม (ST-35) ต้องยังเปิด Guideline ได้ · ดู `R2.md`
7. **เมนูบัญชีของนักเรียนบนเว็บ:** ออกจากระบบ + เปลี่ยนภาษา (R8) ต้องมีทั้งสองบทบาท · requirement ไม่ได้เขียนแต่สรุปได้จาก `app-shell` R8
8. **มาสคอตบนหน้า login (ใช้ร่วม 2 บทบาท):** R8 ไม่ครอบคลุม → OQ44
9. **ผู้ใช้อายุ ป.3–6 บนเว็บที่ออกแบบสำหรับครู:** เกณฑ์เด็กของแอป (`app-shell` R10 · `context.md`) ใช้กับส่วน Guideline ด้วยหรือไม่ requirement ไม่ระบุ · บันทึกเป็นความเสี่ยง ไม่เปิด OQ แยก (รวมใน OQ31 เมื่อออกแบบหน้า login ของนักเรียน)

**H1/H5/H9:** login ครู ครบตามเดิม (ST-07, ST-08, ST-35) · login นักเรียนยังไม่ครบจนกว่า OQ31 ตัดสิน

**DS gap:** ช่องกรอก/ฟอร์ม login (DSG-04 · G5 เดิม ยังไม่เติม) · โครงเว็บ + เมนูตามบทบาท (ดู `../feasibility.md` หัวข้อ DS gap · OQ46)

**OQ:** OQ1, OQ8, OQ31, OQ44 (เปิด) · OQ2, OQ3, OQ15, OQ18 (answered)
