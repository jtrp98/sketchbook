# school-bot-web feasibility · R12: ต่อสายทีละเส้นเป็นขั้น

**ผล: ทำได้มีเงื่อนไข** (2026-11-11 · ruler) · มี 1 ข้อที่ต้องตัดสินก่อน `approved` (OQ35)

## สถานะของบท (รวม R12 + R13)

| สถานะ | เงื่อนไข | ถัดไป | ย้อนกลับ | รัน |
|---|---|---|---|---|
| ฉากกำลังโหลด / โหลดไม่สำเร็จ | - | ปิด | ปิด | ปิด |
| ขั้นแรก | ขั้น 1 จาก N | ได้ | ปิด | ปิด + บอกเหตุผล |
| ระหว่างต่อ | ขั้น 2 … N−1 | ได้ | ได้ | ปิด + บอกเหตุผล |
| ต่อครบ พร้อมรัน | ขั้น N | ปิด | ได้ | ได้ |
| กำลังรัน | กดรันที่ขั้น N | ปิด | ได้ (= หยุดรันก่อน ตามกฎ) | เป็นปุ่มหยุด |

## ช่องโหว่/ข้อขัดกับ "ไม่เก็บสถานะ" (R9)
1. **เข้าบทใหม่ทุกครั้งต้องกดผ่าน N ขั้นก่อนรัน:** เลือกบท → เริ่มขั้น 1 เสมอ · เปลี่ยนไปบทอื่นแล้วกลับมา, รีเฟรช, session หมดอายุ ทำให้ต้องกดใหม่ทั้งหมด · ครูที่สาธิตหน้าห้องและผู้ที่ต่อของจริงเสร็จแล้วถูกบังคับกดซ้ำ (H7) · เว็บอ้างอิงรันได้ทันที · requirement ไม่ระบุว่า (ก) จำขั้นของแต่ละบทระหว่างที่ยังเปิดเว็บไหม (ข) รีเฟรชแล้วอยู่ขั้นเดิมไหม (ค) มีทางไปขั้นสุดท้ายทันทีไหม → **OQ35 · ต้องตัดสินก่อน `approved`**
2. **ด่าน "ครบทุกขั้น" ไม่มีการตรวจจริง:** ผู้เรียนไม่ได้ลากสาย ระบบจึงรู้เพียงว่ากด "ถัดไป" ครบ · ถ้าอนุญาตให้กดข้ามไปขั้นใดก็ได้ (เช่น กดที่ตัวบอกขั้น) ด่านนี้จะไม่มีผล · ไม่ใช่ข้อขัด แต่ต้องตัดสินพร้อม OQ35
3. **ย้อนขั้นหลังต่อครบ:** ปุ่มรันกลับเป็นปิด · ถ้ากำลังรัน = หยุดรัน (มีกฎแล้ว) · ค่าที่ปรับไว้ (แถบปรับค่า) และข้อความ Serial หลังหยุดเป็นอย่างไร → OQ37 (ดู `R13.md`)
4. **ปุ่มรันก่อนครบขั้น:** ต้องเห็นปุ่ม (ไม่ซ่อน) ในสถานะปิดใช้พร้อมเหตุผลที่อ่านได้ เช่น "ต่อสายให้ครบก่อน (ขั้น 2/5)" (H1, H5) · ตรงกับ pattern `Card` ปิดใช้ + เหตุผลของ DS
5. **ตัวบอกขั้น:** requirement มีเฉพาะปุ่ม ถัดไป/ย้อนกลับ · ต้องมี "ขั้น n จาก N" (H1) และขอบเขตปุ่ม (ขั้นแรกย้อนไม่ได้ · ขั้นสุดท้ายถัดไปไม่ได้)
6. **เปลี่ยน tab ระหว่างต่อสาย:** ขั้นต้องคงเดิม (ดู `R11.md` ข้อ 2)
7. **เปลี่ยนบทระหว่างต่อสาย:** ไม่มีอะไรสูญหายที่ต้องยืนยัน (ไม่มีงานของผู้ใช้) → ไม่ต้องมีกล่องยืนยัน
8. **มุมกล้อง:** เมื่อกด ถัดไป ถ้าสายเส้นใหม่อยู่นอกมุมที่ผู้ใช้หมุนไว้ ผู้ใช้จะไม่เห็นสิ่งที่เพิ่ม (H1) · ต้องมีกฎ (หันกล้องให้ หรือชี้ทิศ) ให้ Designer เสนอ · ถ้ากล้องขยับเองต้องเคารพ prefers-reduced-motion
9. **สีสาย:** ห้ามสื่อด้วยสีอย่างเดียว (ข้อความ "จากขาใดไปขาใด" มีอยู่แล้ว ผ่าน) · ค่าสีสายต้องมาจาก DS (DS gap) และควรใช้ชุดเดียวกับตัวจำลองบอร์ดของ `block-lab`
10. **ต่างจากตัวจำลองของ Block Lab:** ใน Block Lab ผู้ใช้ลากสายเอง แต่ที่นี่ดูตามอย่างเดียว · ต้องบอกในหน้าว่าเป็นการดูตามแล้วไปต่อของจริง (H2, H4)
11. **ตัวอย่าง Innovation (R14):** มีชิ้นส่วนมากกว่า จำนวนขั้นจึงมากกว่าบท Sensor หลายเท่า ทำให้ข้อ 1 หนักขึ้น

**H1/H5/H9:** ต้องเติมข้อ 4, 5 · error ของฉากอยู่ที่ `R11.md`

**DS gap:** ตัวบอกขั้น + ปุ่มถัดไป/ย้อนกลับ (stepper · ds-build ระบุ "wizard" ยังไม่มี · ใกล้เคียง: `AttemptDots` แต่ความหมายต่างกัน ใช้แทนไม่ได้) · สีสาย → OQ46

**OQ:** OQ35, OQ37, OQ46 (เปิด) · OQ19 (answered)
