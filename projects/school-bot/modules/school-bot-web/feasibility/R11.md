# school-bot-web feasibility · R11: หัวข้อ Sensor (บท 3D 33 รายการ)

**ผล: ทำได้มีเงื่อนไข** (2026-11-11 · ruler)

## ตรวจกับ `block-lab/sensor-list.md`
- 33 รายการตรงกัน · **ป้ายชนิดในตารางไม่ตรงการทำงานจริง:** RGB LED (#1), Active Buzzer (#2), OLED (#27), Passive Buzzer (#32) ติดป้าย Input แต่เป็นตัวส่งออก · ตัวส่งออกจริงมี **7 รายการ** (#1, #2, #16, #17, #27, #32, #33) · edge case ใน requirements เขียน "Buzzer" คำเดียว ต้องอ่านว่ารวมทั้ง Active และ Passive · เงื่อนไข: บท (tab Overview) ต้องไม่ใช้ป้าย Input/Output จากตารางตรง ๆ
- R15 "ลำดับต้องตรง sensor-list" กับกลุ่มย่อย Sensor 7 กลุ่มของ block-lab R20 (5): รายการบท 33 แถวเรียง 1–33 หรือจัดกลุ่มเหมือน Block Lab ยังไม่ระบุ → OQ45

## ช่องว่าง
1. **tab "Example" กับ Try it yourself (R13):** R11 มี 4 tab (Overview · Pinout · Example · Specifications) และ R13 มี "Try it yourself" · ไม่ระบุว่าโค้ด + ปุ่มรันอยู่ใน tab Example หรือเป็นแผงแยกที่เห็นตลอด · มีผลต่อกฎ "เปลี่ยน tab ขณะรัน" → OQ36
2. **โหมดต่อสาย (R12) กับ tab:** ขั้นต่อสายเป็นสถานะของฉาก ไม่ใช่ tab → เปลี่ยน tab ต้องไม่เปลี่ยนขั้น · ข้อมูลขาใน tab Pinout กับข้อความขั้นต่อสายต้องมาจากข้อมูลชุดเดียว (ไม่เขียนสองที่)
3. **การ์ดชี้ชิ้นส่วน:** ชิ้นส่วน/สายที่ยังไม่ถึงขั้น (R12) ต้องไม่มีการ์ดชี้ · การ์ดที่ถูกชิ้นส่วนบังเมื่อหมุนฉากต้องมีกฎ (ซ่อนหรือย้าย) · ต้องเข้าถึงได้โดยไม่ต้องชี้ในฉาก 3D (รายการชิ้นส่วนที่กดด้วยคีย์บอร์ดได้ · WCAG 2.1.1)
4. **ผังวงจรย่อ:** ไม่ระบุว่าแสดงวงจรครบเสมอ หรือเฉพาะถึงขั้นปัจจุบัน · ให้ Designer เสนอแล้วผู้ใช้ตรวจ (ไม่ block)
5. **สถานะฉาก 3D (H1/H9):** requirement มี "กำลังโหลด/โหลดไม่สำเร็จ + ลองใหม่ โดย tab และโค้ดยังอ่านได้" · ยังขาด:
   - เปลี่ยนบท = โหลดโมเดลใหม่ทุกครั้ง ต้องมีสถานะโหลดระหว่างบท และรายการบทต้องกดบทอื่นต่อได้ระหว่างโหลด
   - เบราว์เซอร์ไม่รองรับ/ปิด WebGL · เครื่องช้า · ฉากหลุดกลางคัน (context lost) → OQ25 (เปิดอยู่) · **เพิ่มประเด็นใน OQ25:** เมื่อไม่มีฉาก 3D ปุ่มรัน (R13) และขั้นต่อสาย (R12) เป็นอย่างไร (ปิดพร้อมเหตุผล หรือใช้ภาพ 2D รายขั้น)
   - ขณะฉากยังโหลดไม่เสร็จ: ปุ่ม ถัดไป/ย้อนกลับ/รัน ต้องปิดพร้อมเหตุผล (H5)
6. **รายการบท:** 33 แถว ต้องบอกบทที่เปิดอยู่ (H1) · ไม่มีเครื่องหมายเรียนแล้ว (R9) · บทที่ยังไม่ผ่านการตรวจ (R15) แสดงอย่างไร → OQ43
7. **ชิ้นส่วนประกอบในฉากนอกเหนือโมดูลของบท** (เช่น LED แสดงผลของเซนเซอร์, ตัวต้านทาน, breadboard): เป็นเนื้อหา (R15) แต่กำหนดจำนวนขั้นต่อสายและจำนวนการ์ดชี้ → ต้องอยู่ในข้อมูลบท
8. **รุ่นโมดูลจริงในชุดอุปกรณ์ไม่ทราบ:** เซนเซอร์สี, ท่าทาง, OLED, MPU6050 มีหลายรุ่นที่ขาและ library ต่างกัน · ร่าง Pinout/โค้ดไม่ได้ถูกต้องจนกว่าจะรู้รุ่น → OQ42 (block เนื้อหา ไม่ block ออกแบบ)
9. **ปริมาณงาน:** โมเดล 3D 33 โมดูล + Uno + ของประกอบ (เปลวไฟ น้ำ ดิน รีโมท ฯลฯ) · ไม่ใช่ประเด็น logic ของ UI · บันทึกเป็นความเสี่ยงด้านกำหนดส่ง

**H1/H5/H9:** ครอบคลุมบางส่วน · ต้องเติมข้อ 5 และ OQ25

**DS gap:** การ์ดชี้ชิ้นส่วนในฉาก · ชุดควบคุมฉาก (หมุน/ซูม/คืนมุมมอง) · สีสาย/สีไฮไลต์ในฉาก 3D · รายการบท · แถบข้อมูลในหน้า (แจ้งโหลดไม่สำเร็จ + ลองใหม่) → OQ46 · มีแล้วใน DS: `Tab`, `Skeleton`, `EmptyState`, `Tooltip`, `Popover`

**OQ:** OQ25, OQ36, OQ42, OQ43, OQ45, OQ46 (เปิด) · OQ16, OQ17 (answered)
