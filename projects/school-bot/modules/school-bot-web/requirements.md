# เว็บ School Bot (เดิม "เว็บครู" · module เดิมชื่อ teacher-web): Requirements (จาก role 1)

> นำเข้าจากระบบเก่า (`Handoff/01_REQUIREMENT` v3.1, `02_FEASIBILITY` v3 รวมคำตอบผู้ใช้ถึง 2026-10-21) · **sketchbook เป็นแหล่งความจริงแล้ว** ไม่ต้องเปิดโฟลเดอร์เดิม · ID เดิม (FR/NFR/EC/AC/DEC/ST/SCR/ENT/ARC-I/DEV-Q) เก็บในวงเล็บเพื่อ grep · ป้ายหลักฐานดู `../../context.md`
> ใช้คำตอบล่าสุดของผู้ใช้จาก feasibility รอบ 2 (2026-10-20) แม้ `04_DECISIONS` เดิมยังเปิดอยู่ (บันทึกไว้ใน `oq.md`)

## เป้าหมาย
**แก้ 2026-11-11 (ผู้ใช้):** เว็บนี้คือ **เว็บ School Bot** ที่ครูและนักเรียน login แล้วเห็นเนื้อหาตามบทบาท (เช่น Guideline เห็นทั้งคู่ · ตั้งค่าและคะแนนเห็นเฉพาะครู) · เพิ่มเมนู **Guideline** = ความรู้ที่ควรรู้ของ Block Lab และ Arm Lab (phase 1 เฉพาะ Block Lab) เพื่อให้ครูและนักเรียนใช้งานได้โดยไม่ต้องมีพื้นฐานโค้ด และให้โรงเรียนเห็นว่าชุดหุ่น + บทเรียนนำไปประดิษฐ์นวัตกรรมได้ (R9–R15) · ข้อความเดิมก่อนแก้อยู่ที่ `../../archive/2026-11-11_school-bot-web-R1-R8-before-chg.md`

ส่วนของครู (เดิม):
ครูในโรงเรียนลูกค้า SchoolBright ใช้เว็บ School Bot (แยกต่างหากจากแอปนักเรียน เปิดผ่านเบราว์เซอร์) เพื่อ **ดูความคืบหน้าและคะแนน Quiz ของนักเรียนรายเทอมและรายปี จัดตามห้อง** · **ตั้งค่า** (เปิด/ปิดหน่วย เวลาเปิดด่าน ดูเครื่องและหุ่น) · **แก้ปัญหาหุ่น** (คู่มือ + สถานะหุ่นที่แอปรายงาน) · ครูจัดการทุกอย่างผ่านเว็บ ส่วนแอปเป็นพื้นที่ของนักเรียน ยกเว้นโหมดครูของ Arm Lab (DEC-14 · อยู่ module `arm-lab`)

## Requirements
ลำดับ: M = Must · ? = ยังไม่ยืนยัน (ดู OQ)

- R1 (M): ครู login เข้าเว็บด้วย**บัญชี SchoolBright** (SSO ปุ่มเดียว) · ลืมรหัส → ส่งไปที่ SchoolBright · **แก้ 2026-11-11 (OQ15, OQ18):** มี 2 บทบาท **ครู** (บัญชี SchoolBright) และ **นักเรียน** (บัญชีเดียวกับที่ใช้ login ในแอป School Bot Studio) · เมนูแสดงตามบทบาท: นักเรียนเห็นเฉพาะ Guideline · ครูเห็นทุกเมนู (R2–R6 + Guideline) · นักเรียนเปิดหน้าของครูโดยตรง = ไม่มีสิทธิ์ (ST-37) · หน้า login ของนักเรียน/ลืมรหัส → OQ31 · ผู้บริหารอาจมีในอนาคต · รหัสผิดแสดงข้อความบอกวิธีแก้ (ST-07) · ดู OQ2, OQ3 · (FR-29, UJ-05, DEV-Q09, SCR-21)
- R2 (M): ตัวกรองช่วงเวลาและห้อง **ปีการศึกษา → เทอม / ทั้งปี → ห้อง อยู่บนสุดของทุกหน้าที่แสดงผล** (บังคับ) · ครูเลือกแล้วเห็นความคืบหน้าและคะแนน Quiz ตามตัวเลือกนั้น ทั้งแบบรายเทอมและรายปี · จัดคะแนนเข้าเทอมด้วยวันเริ่ม–จบของเทอมจาก SchoolBright · ทุกคะแนนเก็บ**เวลาที่ได้ + ห้อง ณ เวลานั้น** (Proposed) · API SchoolBright ยังไม่ทราบ → OQ1 · (FR-26, DEC-15, AC-14, ARC-I01, ENT-05)
- R3 (M): หน้า**ภาพรวมห้อง**: สรุปความคืบหน้าและคะแนน Quiz รายคนของทั้งห้อง · ห้องหนึ่งอาจมีนักเรียน 40+ คน จึงต้อง **ค้นชื่อ · เรียงตามคะแนนหรือความคืบหน้า · กรอง "ยังไม่เริ่ม"** · เปิดรายคนได้ · แสดงเฉพาะผล **Quiz** (ไม่แสดงงาน Arm/Block เพราะไม่มีคะแนน) · ตัวเลขสรุปใช้ ดาว 0–3 ต่อด่าน + คะแนนต่อด่าน + % ด่านที่ผ่าน (Proposed · OQ10) · (FR-26, DEC-18, SCR-22, ARC-I18, ARC-I02)
- R4 (M): หน้า**รายละเอียดนักเรียน**: ผลรายด่านของนักเรียนคนนั้น (ดาว คะแนน) พร้อมสถานะการส่งคะแนนเข้า SchoolBright (รอ/ส่งแล้ว/ล้มเหลว) · ย้อนกลับไปภาพรวมห้องได้ · ใช้ตัวกรองปี/เทอมตามหน้าภาพรวม · (FR-26, SCR-23, ENT-10, ENT-11)
- R5 (M): หน้า**ตั้งค่า**ของครู (MVP 3 รายการที่ผู้ใช้ยืนยัน): (1) **เปิด/ปิดหน่วยบทเรียนรายห้อง** (2) **กำหนดเวลาเปิดด่าน** (3) **ดูรายการเครื่องและหุ่นของห้อง** · บันทึกสำเร็จ/ไม่สำเร็จ แจ้งผล (ST-38) · ผลของการปิดหน่วยแสดงในแอปเป็นด่านล็อก (quiz · ST-11) · รายการอื่นนอกนี้ ผู้ใช้ให้ประเมินเพิ่มตามความเหมาะสมและ Architect ไม่เพิ่มใน MVP · รายละเอียดเวลาเปิดด่าน → OQ7 · (FR-27, ARC-I15, SCR-24, ENT-21)
- R6 (M): หน้า**แก้ปัญหาหุ่น**: คู่มือแก้ปัญหา (ค้นหาหัวข้อได้) + **สถานะหุ่นล่าสุดรายเครื่องที่แอปรายงานขึ้น cloud** (ตอบแล้วว่าได้ DEV-Q08 → A) · เว็บสั่งหุ่นตรงไม่ได้ (หุ่นต่อกับเครื่องนักเรียนผ่าน USB) จึงไม่มีปุ่มสั่งหุ่นบนเว็บ · คำสั่งที่ต้องทำกับเครื่องจริงอยู่ในเมนูครูในแอป (Proposed · OQ14) · ถ้าไม่มีรายงานสถานะ แสดงเฉพาะคู่มือ · (FR-28, ARC-I12, SCR-25, ENT-22)
- R7 (M): **สิทธิ์และข้อมูลเด็ก:** ครูเห็นเฉพาะห้องที่ตัวเองสอน (Proposed · OQ5 · ST-37 เมื่อไม่มีสิทธิ์) · เก็บข้อมูลเด็กเท่าที่จำเป็น (ชื่อ ห้อง ผลด่าน งาน) · **ไม่มีหน้ายินยอม** ผู้ใช้ยอมรับความเสี่ยง (ARC-I14 · ไม่ใช่คำปรึกษากฎหมาย) · (NFR-05, ARC-I14, RSK-05)
- R8 (M): **แพลตฟอร์มและขอบเขตข้อมูล:** เว็บในเบราว์เซอร์ ออกแบบหลักที่ **1280px ขึ้นไป รองรับ 1024px** (layout ยืดได้ · ใช้ Tweak 1024) · 3 ภาษา ไทย / EN / 中文 เผื่อข้อความยาว +40% · **ไม่ใช้มาสคอตในส่วนของครู** (R2–R6 · DEC-29) · **ส่วน Guideline ใช้มาสคอตได้** (แก้ 2026-11-11 · OQ23 · ท่าตาม `../../brand.md` §8 · หน้าที่ของมาสคอต → OQ30) · แสดงเฉพาะคะแนน Quiz (DEC-18) · ข้อมูลตัวอย่างทดสอบ: ห้อง 45 คน ชื่อไทยยาวสุด ~30 ตัวอักษร · (NFR-02, DSG-01, ARC-I19, ARC-I20, FR-04)
- R9 (M): **เมนู Guideline** เห็นทั้งครูและนักเรียน · 3 หัวข้อ: **Block** (R10) · **Sensor** (R11–R13) · **Innovation** (R14) · **phase 1 เฉพาะเนื้อหา Block Lab** (บอร์ด Arduino Uno) · เนื้อหา Arm Lab อยู่ phase ถัดไป และ phase 1 ไม่แสดงเมนู Arm Lab · **phase 1 ไม่เก็บความคืบหน้า** (ไม่มีตัวนับบทที่เรียนแล้ว · รอตัดสิน OQ24) · ภาพอ้างอิงรูปแบบของหัวข้อ Sensor/Innovation: https://learn-esp32.vercel.app/ (ผู้ใช้ 2026-11-11 · อ้างรูปแบบการใช้งาน ไม่คัดลอกหน้าตา/เนื้อหา) · (OQ15, OQ23)
- R10 (M): **หัวข้อ Block:** อธิบายบล็อกของ Block Lab ทีละตัว (คืออะไร ทำหน้าที่อะไร ต่ออย่างไร) ด้วยภาษาที่คนไม่มีพื้นฐานโค้ดเข้าใจ · แบ่ง 2 ระดับตามกลุ่มหมวดของ `block-lab` R18: **Basic** = กลุ่มพื้นฐาน (เริ่มต้น, ควบคุม, ตรรกะ, คณิต, ข้อความ) + กลุ่มข้อมูล (ตัวแปร, รายการ, ฟังก์ชัน) · **Advanced** = กลุ่ม School Bot (Car Control, มอเตอร์, Sensor, Display, Serial, Remote Control) · ผู้ใช้เลือกระดับ → หมวด → เห็น**การ์ดต่อบล็อก**: รูปบล็อก (หน้าตาและสีหมวดตรงกับ Block Lab) · คำอธิบาย · ช่องที่ต้องใส่ค่า · ตัวอย่างการต่อกับบล็อกอื่น · **animation เล็ก ๆ** (เนื้อหา animation → OQ29) · เป็นหน้า 2D ไม่มีฉาก 3D และไม่มีพื้นที่ลากต่อบล็อกเอง · หมวดที่ยังว่างใน MVP ของ Block Lab → OQ27 · (OQ20)
- R11 (M): **หัวข้อ Sensor = บทเรียน 3D หนึ่งบทต่อหนึ่งรายการ ครบ 33 รายการ**ตาม `../block-lab/sensor-list.md` (OQ16) · แต่ละบทมี: (1) **ฉาก 3D** บอร์ด Uno + โมดูล + สาย หมุน ซูม เลื่อน และคืนมุมมองเริ่มต้นได้ (2) **การ์ดชี้ชิ้นส่วน**ในฉาก (ชื่อ + คำอธิบายสั้น) (3) **แผงข้อมูล 4 tab:** Overview · Pinout · Example · Specifications (4) **ผังวงจรย่อ** เปิด/ปิดได้ (5) **รายการบท** เลือกบทใดก็ได้ ไม่ล็อกลำดับ บทที่เลือกแสดงฉาก ข้อมูล และโค้ดของบทนั้น · (OQ17)
- R12 (M): **ต่อสายทีละเส้นเป็นขั้น:** แต่ละบทมีลำดับขั้นการต่อ ปุ่ม ถัดไป / ย้อนกลับ · แต่ละขั้นฉาก 3D เพิ่มสาย 1 เส้น (หรือวางชิ้นส่วน 1 ชิ้น) พร้อมข้อความบอกว่าเสียบจากขาใดไปขาใด · ครบทุกขั้นแล้วจึงกดรันได้ (R13) · เป็นการดูตามแล้วไปต่อของจริง ผู้เรียนไม่ได้ลากสายเองในฉาก · (OQ19)
- R13 (M): **Try it yourself:** แสดง**โค้ด C++ ของบท แบบอ่านอย่างเดียว** (คัดลอกได้) · ปุ่ม รัน / หยุด · ขณะรัน: ฉาก 3D ทำงานตามบท · **ไฮไลต์บรรทัดโค้ดที่ตรงกับสิ่งที่ฉากกำลังทำ** · **แถบปรับค่า/การลากชิ้นส่วนในฉาก** แทนสิ่งที่เซนเซอร์วัด (เช่น ระยะ แสง ระดับน้ำ) และค่าที่ปรับสะท้อนในโค้ดเมื่อเกี่ยวข้อง · **แผงข้อความจากบอร์ด** (Serial) แสดงผลที่บทกำหนด · **พฤติกรรมของแต่ละบทเขียนไว้ล่วงหน้า ไม่จำลองชิปจริง และผู้เรียนแก้โค้ดไม่ได้** (OQ17) · ไม่แสดงบล็อกในบท 3D
- R14 (M): **หัวข้อ Innovation:** ตัวอย่างการนำแผงวงจรมาประยุกต์เป็นนวัตกรรม เพื่อให้โรงเรียนเห็นการนำไปแข่งขันหรือใช้ในโรงเรียน · phase 1 มี **4 ตัวอย่าง:** (1) เซนเซอร์แสงติดแผงโซลาร์เซลล์ให้หันตามแดด (2) เซนเซอร์วัดระดับน้ำตัด/ต่อปั๊มน้ำ (3) เซนเซอร์วัดระยะเตือนกันรถชน (4) เซนเซอร์ตรวจจับของหยุดสายพาน เรียกแขนกลมาหยิบ แล้วสายพานเดินต่อ · ใช้รูปแบบบทเดียวกับ Sensor (R11–R13) · ตัวอย่างที่ 4 ใช้แขนกล (หุ่น Raspberry Pi ของ `arm-lab`) → OQ26 · (OQ21)
- R15 (M): **ที่มาเนื้อหาบท** (ขาที่เสียบ, ลำดับสาย, โค้ด C++, คำอธิบาย, สเปก ของ R10–R14): Claude ร่างจากข้อมูลมาตรฐานของโมดูล แล้ว**ทีมตรวจทุกบทก่อนใช้จริง** · บทที่ยังไม่ผ่านการตรวจติดป้าย "ร่าง รอทีมตรวจ" ในเอกสาร และไม่ถือเป็นเนื้อหาพร้อมเผยแพร่ · ชื่อและลำดับเซนเซอร์ต้องตรง `sensor-list.md` · ชื่อบล็อก/หมวดต้องตรง `block-lab` · ผู้ตรวจและขั้นตอนเอาป้ายออก → OQ28 · (OQ22)

## กฎ/Logic
- AC-14: **When** ครูเลือกปีการศึกษา เทอม และห้อง **Then** เห็นความคืบหน้าและคะแนน Quiz ตามตัวเลือกนั้น ทั้งแบบรายเทอมและรายปี
- ตัวกรองบังคับทุกหน้า: ปี → เทอม/ทั้งปี → ห้อง (SCR-22 ตัวกรองบังคับ · SCR-23 ตามหน้า SCR-22 · SCR-24, SCR-25 กรองตามห้อง)
- ไม่มีข้อมูลในช่วงที่เลือก (เทอมใหม่/นักเรียนยังไม่เล่น) → บอกว่าไม่มีข้อมูลช่วงนี้ (ST-36)
- SchoolBright ล้มเหลว → กำลังโหลด/โหลดไม่สำเร็จ + ลองใหม่ (ST-35)
- ใช้ตารางข้อมูลที่ค้น เรียง กรองได้ และแถวเยอะ (DSG-07 ต้องเพิ่ม component ใหม่)
- login ครูในแอป (Arm Lab) ใช้บัญชี SchoolBright ตัวเดียวกัน (module `arm-lab` · FR-13)
- ดาว 0–3 ต่อด่าน: ≥60% = 1 ดาว · ≥80% = 2 ดาว · 100% = 3 ดาว (ที่มา quiz · ARC-I02 Closed) · เกณฑ์เหรียญยัง Delegated → Designer เสนอ (quiz · DSG-10)

- **Guideline (R9–R15 · 2026-11-11):** เลือกบท → ต่อสายทีละขั้นจนครบ → รัน → ปรับค่า/ลากชิ้นส่วน → หยุด · เปลี่ยนบทระหว่างรัน = หยุดรันของบทเดิม · ย้อนขั้นการต่อระหว่างรัน = หยุดรัน
- สิทธิ์ตามบทบาท (R1): Guideline = ครู + นักเรียน · R2–R6 = ครูเท่านั้น

## การตัดสินใจที่ผูกกับ module
- DEC-14 ครูจัดการทุกอย่างผ่านเว็บ School Bot ที่แยกออกมา ซึ่งออกแบบในรอบนี้ ส่วนแอปเป็นพื้นที่ให้นักเรียน
- DEC-15 เว็บครูดูผลได้ทั้งรายเทอมและรายปี จัดตามห้องจาก SchoolBright
- DEC-18 คะแนนที่ส่ง SchoolBright และผลบนเว็บครูมาจาก Quiz อย่างเดียว (CHG-06)
- DEC-29 ไม่ใช้มาสคอตบนเว็บครู · **แก้ 2026-11-11:** ใช้เฉพาะส่วนของครู ส่วน Guideline ใช้มาสคอตได้ (R8)
