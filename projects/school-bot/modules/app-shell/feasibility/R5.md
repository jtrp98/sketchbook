# App Shell · Feasibility R5: ปิดโปรแกรมอย่างปลอดภัย + ชั้นปุ่มหยุด (ข้อมูลอ้างอิงจาก Architect/Auditor เดิม · ไม่ใช่ผล ruler)

## พฤติกรรมที่ออกแบบแล้ว (FRM-05 · Observed)
- ปิดตอนหุ่นขยับ → dialog "หุ่นกำลังขยับอยู่" → **หยุดหุ่นแล้วปิด** (Tweak closeCase auto/robot · prop robotMoving, onStopRobot)
- ปิดตอนยังไม่ขึ้นคลาวด์ → แจ้งว่างานอยู่ในเครื่อง (ไม่หาย)
- dialog ใช้ z-dialog 30 เว้นแถบล่าง 76 (ปุ่มหยุดกดได้) · alertdialog มี aria-modal แต่ไม่มี focus trap ในโค้ด → ส่ง dev

## ประเด็นความปลอดภัย (Auditor รอบ 1 · AUD-F01 ระดับ C)
- wrapper แถบหน้าต่างเป็น **z 80** สร้าง stacking context เหนือปุ่มหยุด (z-stop 70) · ฉากหลัง dialog (absolute top 44 สูง 780) และตัวดักคลิกของ popover (fixed inset 0) ทับปุ่มหยุด → กดหยุดครั้งแรกแค่ปิด dialog/popover หุ่นยังขยับ
- หลักฐาน: connected + moving → กดปิดโปรแกรม → `elementFromPoint` กลางปุ่มหยุด = ฉากหลัง · เปิด popover อุปกรณ์ → กดหยุด → ยังขยับ · กดหยุดตรง ๆ (ไม่มี overlay) → หยุดได้
- ขัด NFR-04 "หยุดได้เสมอ" และ D-18 "ไม่มีอะไรสูงกว่า z-stop" · กระทบทุกหน้าที่ใส่แถบหน้าต่าง (Canvas A ทั้งหมด + ต้นฉบับ Canvas B)

**CR-10 (ผู้ใช้เลือก ก · 2026-10-21 · Decided):** ลดชั้นแถบหน้าต่างให้ต่ำกว่า z-stop · ฉากหลัง dialog/popover ของแถบเว้นปุ่มหยุด (ไม่ว่าปุ่มหยุดอยู่ header หรือแถบล่าง) · tooltip ไม่ทับปุ่มหยุด · เพิ่มชั้นแถบหน้าต่างในตาราง D-18 · ใช้กติกาเดียวกันทุกหน้าที่ import แถบ (ทางเลือก ข ที่ไม่เลือก: คงชั้น 80 แต่ให้คลิกฉากหลังตรงตำแหน่งปุ่มหยุด = หยุดหุ่น ซึ่งเปราะ)
งานที่เหลือ: แก้ที่ต้นฉบับ WindowBarV1 (Canvas B) แล้วสำเนาไป A · ต้องเสร็จก่อนใส่แถบใน Canvas C · เจ้าของ design system เพิ่มชั้นใน D-18

## ที่ต้องส่ง dev ตรวจซ้ำ
ลำดับ Tab: แถบหน้าต่าง → header (กลับ, หยุด) → เนื้อหา → แถบล่าง · หยุดทั้งหมดถึงได้ด้วยคีย์บอร์ดตลอด · focus วนใน dialog ปิดโปรแกรม · Esc ปิด · focus กลับปุ่มปิด
