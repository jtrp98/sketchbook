### ทำได้ (ตรวจแล้วไม่ขัด)

- **ไม่เกินเกณฑ์ nav:** 5 รายการระดับเดียว ไม่เกิน UI12/HM28 (≤ 6) · UI20/HM23 (≤ 2 ระดับ)
- **R12 ชื่อทางการ:** "เกม" เป็นคำทั่วไป ไม่ชนชื่อทางการ (School Bot Studio · Arm Lab · Block Lab) · ต้องเพิ่มคำ "เกม" (th/en/zh) ในตาราง "คำที่ตัดสินแล้ว" brand §7 (session หลัก)

### เงื่อนไข (ต้องครบก่อนออกแบบ/handoff ส่วนที่เกี่ยว)
1. **ปลายทางของเมนูเกม = module ใหม่ (ยังไม่มี):** app-shell ออกแบบได้เฉพาะ "รายการเมนู" ใน sidebar · หน้าคลังเกม/หน้าเกม/หน้าเล่น เป็นของ module เกม · **handoff ของ app-shell ส่วน sidebar ต้องรอ module เกมมี R# ของหน้าปลายทาง** ไม่งั้นเป็นทางตัน (H3) · ห้ามทำหน้า "เร็ว ๆ นี้" ชั่วคราวเอง (ผู้ใช้ตัดสินให้ทำเกมครบรอบแรก · context.md MVP/RSK-11)
2. **รายการหน้า N3 / highlight:** brand §11.2 (N3) และ §11.21 ระบุหน้าที่มี sidebar = หน้าหลัก, บทเรียน, งานของฉัน · ต้องเพิ่ม "หน้าคลังเกม (+ หน้าเกม/เลือกระดับ ถ้ามี sidebar)" ให้ highlight "เกม" · หน้าเล่นเกม = N2 ไม่มี sidebar (ชื่อหน้า "เกม · <ชื่อเกม>" ตามแบบ "บทเรียน · Level 1") · item ที่เป็นเกมในด่านบทเรียนยังอยู่ใต้ "บทเรียน" (ไม่ highlight เกม) · ทางเข้าจากที่อื่น (การ์ด "ลองเล่นต่อ" ในบทเรียน, "เกมแนะนำ" ถ้ามี) → ถึงหน้าคลัง/หน้าเกมแล้ว highlight "เกม" · ข้อนี้ module เกมต้องระบุใน R# และ session หลักต้องแก้ brand
3. **ปุ่มบ้าน + leave guard ระหว่างเล่นเกม (H5):** บ้าน = ไปหน้าหลักเสมอ (brand §11.2) · หน้าเล่นเกมที่มีงานสร้าง (Creative Workshop, สร้างด่านเอง) หรือสั่งหุ่นจริง (ถ้า Q6 ให้ joystick สั่งแขนจริง) ต้องมี leave guard และปุ่มหยุดตาม R5/NFR-04 · app-shell รับ guard จากหน้าเกมแบบเดียวกับ lab · module เกมกำหนดว่าเกมไหนต้อง guard
4. **ข้อความใน requirements ที่ค้างแบบเก่า (session หลักแก้ตามกฎการเปลี่ยน requirement):** AC-04 (กฎ/Logic หน้าหลัก) ยังเขียน "sidebar 4 เมนู" · บรรทัด "sidebar หุบ 104px / กาง 264px" ขัด brand §11.21 / ds-build (กว้าง 120 · ตัดสิน 2026-11-04) · "หัวกลุ่มเมนู 'เรียน' อยู่เหนือ บทเรียน" ต้องระบุว่าเกมอยู่กลุ่มไหน (OQ21) · context.md ขอบเขต MVP ยังเขียน "sidebar 4 เมนู"
5. **ความสำเร็จบนหน้าหลัก:** R7 ยังมี "ความสำเร็จ (ดาวและเหรียญ)" แต่ brief U8 (ผู้ใช้) "ซ่อนส่วนความสำเร็จไว้ก่อน" และ ds-build บันทึก "ซ่อนความสำเร็จ = เอาออกเฉย ๆ" → ขัดกันอยู่แล้วก่อนรอบนี้ · ประกอบกับคลังเกมมีสถิติ/เป้าเสริมแต่ไม่ให้ดาว (quiz R4 · Q7) → ต้องตัดสิน OQ23
6. **DS:** ไอคอนรายการ "เกม" ใน sidebar ต้องมาจาก DS (`bundle.js` มีไอคอน Lucide ~35 ตัว ตาม ds-build) · **ยังไม่ได้ยืนยันว่ามีไอคอนที่สื่อ "เกม"** → ถ้าไม่มี = `DS gap: ไอคอนเมนู "เกม" (เช่นจอยเกม) · ใช้ที่ sidebar รายการที่ 3 · ใกล้เคียงที่สุดใน DS: ไม่ทราบ (ต้อง list ไอคอนใน bundle.js)` · session หลักตรวจกับ DS ก่อนส่ง crayon · การ์ดเกม/ตัวกรองหมวดของหน้าคลัง = G7 (ds-build · ของ module เกม ไม่ใช่ app-shell)

### Edge case และสถานะ (H1/H5/H9)
- **ออฟไลน์:** login ต้องออนไลน์ หลัง login ทำงานต่อได้ (R6 edge case) · เมนูเกมตอนออฟไลน์ยังไม่ระบุ (เล่นได้ไหม, สถิติ/แกลเลอรีเก็บที่ไหน) → OQ22 · ตามกฎ HM2/H4 รายการ sidebar ไม่ควรหายตามสถานะ (ถ้าใช้ไม่ได้ให้บอกเหตุผลที่หน้าปลายทาง)
- **โหลดเกม (H1) / เกมเปิดไม่ได้ (H9):** สถานะโหลด/ผิดพลาดอยู่ที่หน้าปลายทาง (module เกม) ใช้ EmptyState/สถานะโหลด + มาสคอตตาม brand §11.23 · sidebar ไม่มีสถานะของตัวเอง
- **หน้าหลักครั้งแรก (ST-09):** ไม่เปลี่ยน ถ้าไม่เพิ่ม "เกมแนะนำ" · ถ้าเพิ่ม (OQ20) ต้องมีสถานะเมื่อยังไม่มีด่านล่าสุด (แนะนำจากอะไร) และสถานะว่าง
- **งานจากเกมสร้างสรรค์** (Shape Editor / สร้างด่านเอง / แกลเลอรี) ไม่ใช่งาน Arm/Block → ไม่อยู่ใน "งานล่าสุด 2 กลุ่ม" ตาม R7 ปัจจุบัน · ต้องยืนยัน OQ24 (กระทบ my-work ถ้าให้รวม)
