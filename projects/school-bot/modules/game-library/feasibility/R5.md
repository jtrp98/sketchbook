# game-library · Feasibility R5: ด่านวันนี้ (ruler 2026-11-06)

**ผล R5: ทำได้มีเงื่อนไข** · สรุปอยู่ใน `../feasibility.md` หัวข้อ R5

## สร้างจากวันที่ ไม่ใช้เน็ต

- ทำได้: seed = วันที่ → ด่าน · ทุกเครื่องได้ผลเดียวกันเมื่อ (1) วันที่ตรงกัน (OQ5, OQ11) และ (2) **ตัวสร้าง/คลังด่านหมุนเวียนเหมือนกันทุกรุ่นโปรแกรม** · เครื่องในห้องคอมอาจอัปเดตไม่พร้อมกัน → ถ้ารุ่นใหม่เปลี่ยนอัลกอริทึม เพื่อนได้คนละด่านในวันเดียวกัน · ข้อกำหนด dev: ผูกเวอร์ชันตัวสร้างกับช่วงวันที่ หรือห้ามเปลี่ยนผลของวันที่ที่ผ่านมาแล้ว/วันนี้
- ผลด่านวันนี้ใน log ใช้ "วันที่ของด่าน" เป็น ID (มีแล้วในกฎ "ผลที่เก็บต่อการเล่น") ✔

## ด่านที่สร้างต้องแก้ได้และมีทางแก้ (OQ1)

- ใบ้ขั้น 3 "ทำให้ดู 1 ก้าว" (R6) และเป้าหลักที่ระบบตรวจได้ ต้องรู้ทางแก้อ้างอิง · ด่านสุ่มต้องคืนทางแก้และรับรองว่าแก้ได้ทุกครั้ง (ยากมากใน G13, G14, G5, G4)
- OQ1 ทาง ก (หมุนด่านจากคลังที่ทีมเตรียม) แก้ปัญหานี้ได้ทุกเกม · แต่ถ้าคลังหมุนสั้นเกิน เด็กจะเจอด่านซ้ำ → ขนาดคลังเป็นข้อกำหนดเนื้อหา
- 07-priority วางตัวสร้างด่านไว้ขั้น 3 (สุดท้าย) · R5 เป็น M ทุกเกม → ต้องมีคลังหมุนเวียนก่อนถึงขั้น 3 อย่างน้อย

## ที่ยังไม่ระบุ (OQ11)

- ขอบวัน: เขตเวลาเครื่อง หรือเวลาประเทศไทย · เครื่องที่ตั้งเขตเวลาผิดจะได้ด่านคนละวันกับเพื่อนแม้นาฬิกาตรง
- หน้าจบด่านวันนี้: R6 มี "ด่านถัดไป" ซึ่งไม่มีความหมายกับด่านวันนี้ (มีด่านเดียวต่อวัน)
- เป้าเสริม/สถิติดีสุดของด่านวันนี้: สะสมเข้า "สถิติดีสุดของฉัน" ของเกม หรือเป็นของวันนั้นเท่านั้น (R5 บอกแค่ "ไม่นับใน ผ่าน x/y")
- ปุ่ม "ด่านวันนี้" บนหน้าเกมควรบอกว่าวันนี้ผ่านแล้วหรือยัง (H1) · Designer เสนอได้หลังตอบ OQ11

## นาฬิกา/ย้อนวัน

- "วันที่ผ่านไปย้อนเล่นไม่ได้" ตอนออฟไลน์บังคับไม่ได้ (เปลี่ยนนาฬิกาเครื่อง) · ไม่มีอันดับ/รางวัล (R9) จึงไม่มีผลเสีย · ไม่เปิด OQ เพิ่ม
- ข้ามเที่ยงคืน (edge case Proposed) ทำได้: ด่านผูกกับวันที่ตอนเริ่ม
