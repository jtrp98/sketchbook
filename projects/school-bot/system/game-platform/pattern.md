# Pattern กลาง (คลัง pattern ที่ 2 เมนูดึงไปสร้างด่าน)

ไฟล์นี้บอกว่า **มี pattern อะไรบ้าง** · กฎการใช้ → `pattern-rule.md` · ใช้ในเมนูเกม → `game.md` · ใช้ในเมนูบทเรียน → `quiz.md`

ป้ายหลักฐาน: **[ต้นฉบับ]** มีในแหล่ง · **[ยืนยัน]** ผู้ใช้ตัดสิน · **[อนุมาน]** ผมอนุมานจากหัวข้อหลักสูตร ยังไม่เทียบใบงานจริง · **[เสนอ]** เสนอเพิ่ม รอผู้ใช้ยืนยัน

## 1. โครง 2 ชั้น

```
เมนูบทเรียน (ตามหลักสูตร)      เมนูเกม (สนามเล่นอิสระ สร้างสรรค์)
        │                               │
        └──────────┬────────────────────┘
                   ▼
   ชั้น A: กิจกรรมในด่าน (16 แบบ)   ← กิจกรรมย่อยในด่าน
   ชั้น B: เกมจำลอง (GP-01…14)      ← โลกจำลองให้ลงมือ
                   ▼
   ตั้งค่าด้วย config เท่านั้น (engine ไม่รู้ว่าอยู่เมนูไหน · 02 §3.1, 06)
```

- ด่านบทเรียน = หยิบกิจกรรมในด่านและ/หรือ GP มาผสมตามหลักสูตร (ชนิดด่านดู `quiz.md`)
- เมนูเกม = หยิบ GP เป็นหลัก ไม่มีโจทย์ตอบคำถาม (ดู `pattern-rule.md` PR-G1)

## 2. ชั้น A: กิจกรรมในด่าน 16 แบบ

**กิจกรรมในด่าน** = กิจกรรมย่อยหนึ่งอย่างที่เด็กทำข้างในด่าน (เช่น เลือกตอบ จับคู่ เรียงขั้นตอน สร้างผลงาน) · เรียกด้วย **ลำดับ + ชื่อสื่อความหมาย** (`01-choose-4`, `03-match`, `06-order-3` … ถึง `16-create`) ลำดับ 01–16 ใช้อ้างอิงและเรียงในตาราง ชื่อหลังลำดับบอกว่าเป็นกิจกรรมอะไร · ชื่อเดิมคือ IT-01…16 แล้ว Q-01…16 (เปลี่ยน 2026-11-09 ตามคำสั่งผู้ใช้) · ไม่ใช่ด่าน และไม่ใช่แค่ "ข้อคำถาม" เพราะหลายอย่างเป็นการลงมือทำ · ต่างจาก GP ที่เป็นเกมจำลองทั้งหน้าจอ

กลุ่มกติกาลองซ้ำ (รายละเอียด PR-A1, PR-Q1): **ตอบ** = เลือกตอบ 4 ช้อยส์ เฉลยจบ ไม่ทำข้อซ้ำ · **ซ้ำ** = ตอบได้รวม 3 ครั้ง + ใบ้ 3 ขั้น (ผิดครั้งที่ 3 → ใบ้ขั้น 3 แล้วไปต่อ) · **ไม่ตัดสิน** = ไม่มีถูกผิด

เดิม 12 แบบ (FM1/FM2 10 แบบ + R3 อีก 2 คือ `01-choose-4`, `11-slider-match`) · เพิ่ม 4 แบบ (`07-order-long`, `09-predict-code`, `12-enter-value`, `13-label-parts`) **[อนุมาน]**

**วิธีอ่าน:** แต่ละ GP แยก 3 ส่วน · **[กฎ]** ต้องทำเสมอใน GP นั้น (ถ้าขัดกฎกลางใน `pattern-rule.md` กฎกลางชนะ) · **[แนวทาง]** แนวทางออกแบบ ปรับได้ตอนออกแบบจริง · **ไม่นำมาใช้** ค่าที่ขัด DS/UI เดียว/requirement (เก็บไว้ให้เห็นว่ามีในต้นฉบับ) · ทุกค่าภาพ (สี ขนาด ฟอนต์) มาจาก DS · เกณฑ์/ข้อห้ามที่ใช้กับ GP ทุกตัวอยู่ที่ `pattern-rule.md` §1.8 (หน้าที่ของแต่ละโซน, สถานะหน้าจอ, ปุ่มควบคุม)

ภาพร่าง ASCII และข้อความตัวอย่างในต้นฉบับ ย่อเป็นรายการองค์ประกอบด้านล่างแล้ว · "ตัวอย่างภารกิจ" เป็นข้อความสมมติจากต้นฉบับ ไม่ใช่เนื้อหาหลักสูตรจริง (เนื้อหาจริงอิง `curriculum-source.md`) · "Level x-y" ในต้นฉบับเป็นตัวอย่างตำแหน่งด่าน ไม่ใช่การกำหนดชั้น

### GP-01 Grid Path Navigator (นำทางบนตารางพิกัด)
- **ตัวอย่างภารกิจ:** "พาหุ่นยนต์ไปเก็บแร่" (ต้นฉบับแสดงที่ Level 1-2 · ตัวนับบล็อก 3/5)
- **Layout [แนวทาง]:** แบ่ง 50/50 ซ้าย-ขวา แนวนอน
- **Zone B (ซ้าย):** ตาราง 2 มิติ (จุดเริ่ม S, เป้า G, สิ่งกีดขวาง) · หุ่นมีลูกศรบอกทิศหน้า
- **Zone C (ขวา):** ชุดบล็อก (Toolbox) + พื้นที่โปรแกรม (Script Canvas) · ตัวอย่างบล็อก: เมื่อเริ่มทำงาน · เดินหน้า · เลี้ยวซ้าย · เลี้ยวขวา · ทำซ้ำ 3 ครั้ง
- **Zone D:** ย้อน · เล่น · ทีละก้าว · รีเซ็ต · ตัวเลื่อนความเร็ว
- **[กฎ]** หุ่นต้องมีตัวชี้ทิศทางหน้า (Heading Indicator Arrow) ชัดเจน เพื่อกันสับสนซ้าย-ขวา
- **[แนวทาง]** เส้นทางที่หุ่นเคยเดินแสดงเป็นรอยเส้นประสีอ่อน (ซ้อนกับเส้นที่ตั้งใจ ตาม 02 §4.1) · วัตถุเป้าหมายมีอนิเมชันหมุนวนเบา ๆ (idle · ต้องเคารพ reduced-motion)
- **ปรับตามชั้น [แนวทาง · เป็นค่า config]:** ป.1–ป.2 ตารางไม่เกิน 4×4 · บล็อกเป็นไอคอนลูกศรใหญ่ · ไม่มีพารามิเตอร์ตัวเลข · ป.5–ป.6 ตาราง 8×8 ถึง 10×10 · มีพิกัดแกน X, Y กำกับขอบตาราง · บล็อกรองรับตัวแปรและฟังก์ชัน

### GP-02 Sensor Reactive Trigger (ตอบสนองต่อเซนเซอร์)
- **ตัวอย่างภารกิจ:** "ตั้งระบบเบรกฉุกเฉิน" (Level 3-4)
- **Layout [แนวทาง]:** 45/55 ซ้าย = จำลองเซนเซอร์และหุ่น · ขวา = บล็อกเงื่อนไข
- **Zone B:** เกจค่าเซนเซอร์สด (ตัวอย่าง "เกจวัดระยะทาง: 15 cm" · หุ่นวิ่งเข้าหากำแพง)
- **Zone C:** บล็อกเงื่อนไข เช่น ถ้า ‹เซนเซอร์ระยะ < 20› → หยุดมอเตอร์ · มิฉะนั้น → เดินหน้าความเร็ว 50%
- **Zone D:** ตัวควบคุมสภาพแวดล้อม (เลื่อนขยับกำแพงจำลอง) · ทดสอบ · รีเซ็ต
- **[กฎ]** มีเส้น Threshold บนเกจ ให้เห็นว่าค่าปัจจุบันอยู่เหนือ/ใต้เงื่อนไข if/else
- **[แนวทาง]** เกจเซนเซอร์ได้ 3 ชนิดตามต้นฉบับ: ความสว่าง · ระยะทาง (เซนติเมตร) · ระดับเสียง (เดซิเบล) · สไลเดอร์ปรับค่าเอง (Manual Override) ให้เด็กทดสอบปฏิกิริยาก่อนรันจริง
- **DS gap:** เกจเซนเซอร์ + Threshold marker (PR-A21)

### GP-03 Breadboard & Circuit Assembler (ประกอบวงจร)
- **ตัวอย่างภารกิจ:** "ต่อไฟ LED พร้อมตัวต้านทาน" (Level 3-2)
- **Layout [แนวทาง]:** พื้นที่จำลองเต็มจอ · Zone B = พาเลตชิ้นส่วน/แหล่งจ่ายไฟด้านซ้าย · Zone C = เบรดบอร์ดใหญ่ตรงกลาง
- **ชิ้นส่วนตัวอย่าง:** LED สีแดง · ตัวต้านทาน 220Ω · สวิตช์ปุ่มกด · สายไฟ (ต้นฉบับ §4 ระบุ 4 สี: แดง/ดำ/เขียว/เหลือง · รายการส่งมอบ §7 ระบุ 6 สี → ยังไม่ตัดสินจำนวนสี)
- **Zone D:** สวิตช์จ่ายไฟ ON/OFF · มิเตอร์วัดแรงดัน (ตัวอย่าง 3.2V) · ล้างสาย
- **[กฎ]** Snap-to-Hole: เมื่อลากปลายสายเข้าใกล้รู รูที่อยู่ในแนวไฟฟ้าเดียวกัน (แถวนอนเดียวกัน) เรืองเป็นวงกลมสีเขียว (สี/สัญลักษณ์จาก DS · คู่สัญลักษณ์ ไม่ใช้สีอย่างเดียว) เพื่อสอนโครงสร้างการนำไฟฟ้า
- **[กฎ]** วงจรช็อตหรือลืมตัวต้านทาน → ไอคอนควันลอยเบา ๆ + ข้อความเป็นมิตร ตัวอย่าง "กระแสไฟฟ้าไหลแรงเกินไป ลองเพิ่มตัวต้านทานดูนะ" (ไม่ใช้แจ้งเตือนแดง · PR-A6)
- **[แนวทาง]** สีสายไฟมีความหมาย: แดง = ไฟเลี้ยง · ดำ = กราวด์ · อื่น ๆ = สัญญาณ (สร้างนิสัยจัดระเบียบวงจร) · ความเสียหายจริงใช้ตาม block-lab R5 (06)
- **DS gap:** ชิ้นส่วนเสมือนจริง (เบรดบอร์ด, LED, สวิตช์, สายไฟ, เซนเซอร์) · มาร์กเกอร์รูเบรดบอร์ด

### GP-04 Kinematic Manipulator & Sorting Arm (แขนกลและคัดแยก)
- **ตัวอย่างภารกิจ:** "คัดแยกบล็อกตามสี" (Level 4-1)
- **Layout [แนวทาง]:** 50/50 · Zone B = แขนกล + สายพาน + ถังรับ (ถัง A, ถัง B) · Zone C = ลำดับคำสั่งองศา
- **Zone C ตัวอย่าง:** วนซ้ำตลอดเวลา → ถ้า ‹ตรวจพบสี = แดง› → หมุนฐานไปที่ 45° · กริปเปอร์หนีบ · หมุนฐานไปที่ 135° · กริปเปอร์ปล่อย
- **Zone D:** สั่งเดินสายพาน · รันระบบ · ความเร็วแขนกล (ตัวอย่าง 1x) · รีเซ็ต
- **[กฎ]** ส่วนโค้งมุม (Servo Angle Arc Gizmo) ที่ข้อต่อ แสดงมุม 0–180° ให้เห็นมุมเรขาคณิตตรงกับตัวเลขในโค้ด (ช่วงมุมจริงของแขนตาม arm-lab R13 · 02 §4.4)
- **[กฎ]** ไฟสถานะมือคีบ: หนีบแน่น = เขียว · เปิดอ้า = เทา (คู่ไอคอน/ข้อความ ไม่ใช้สีอย่างเดียว)
- **[แนวทาง]** โซนวางวัตถุ (Drop Target) มีกรอบเรืองแสงตามสีที่ถูกต้อง
- **DS gap:** sprite แขน/สายพาน/ถัง

### GP-05 Data Classifier & Model Trainer (ฝึกโมเดล AI)
- **ตัวอย่างภารกิจ:** "ฝึก AI แยกภาพขยะรีไซเคิล" (Level 5-2)
- **Layout [แนวทาง]:** หน้าจอเฉพาะ แบ่ง "พื้นที่รวบรวมข้อมูล" กับ "พื้นที่ทดสอบความแม่นยำ" · Zone B = ช่องภาพสด/ทดสอบ + ผลทำนาย · Zone C = ถังตัวอย่างต่อคลาส (ตัวอย่าง: ขวดพลาสติก 15 ตัวอย่าง · กระป๋องโลหะ 14 ตัวอย่าง · ปุ่ม + เพิ่มตัวอย่าง · ปุ่มฝึกสอนโมเดล)
- **Zone D:** ทดสอบด้วยรูปใหม่ · **บันทึกโมเดลไปใช้ในโค้ดดิ้ง** · ล้างข้อมูล
- **[กฎ]** แถบสถานะการฝึก (Preparing → Training → Ready) แบบอนิเมชัน ลดความกระวนกระวายระหว่างรอ
- **[แนวทาง]** แถบความเชื่อมั่นสด (ตัวอย่าง ขวดพลาสติก 85% / กระป๋อง 15%) ขยับตามภาพที่ตรวจพบ · ถังตัวอย่างมีปุ่มกดค้างเพื่อถ่ายรัว (Hold to Record) และปุ่มลบภาพเบลอ
- **ข้อจำกัด [ยืนยัน 2026-11-09]:** ไม่ใช้กล้อง ใช้ชุดภาพ/ท่าทางที่เตรียมไว้ (PR-A14) · ส่วน "บันทึกโมเดลไปใช้ในโค้ดดิ้ง" เชื่อม AI → โปรแกรม ยังไม่มีที่รองรับใน engine (02) → ต้องตัดสินตอนออกแบบ
- **DS gap:** ถังตัวอย่าง + แถบมั่นใจ + แถบสถานะฝึก

### GP-06 State Machine & Event-Driven Simulator (เครื่องจำลองสถานะ)
- **ตัวอย่างภารกิจ:** "ระบบไฟสัญญาณจราจรอัจฉริยะ" (Level 4-3)
- **Layout [แนวทาง]:** ซ้าย = ฉากจำลองสภาพแวดล้อม (ตัวอย่าง สี่แยก · ปุ่มคนข้ามถนน) · ขวา = แผนภาพสถานะควบคู่บล็อก (ตัวอย่าง State ไฟเขียว: ตั้งเวลา 10 วินาที · เมื่อหมดเวลา → ไปยังไฟส้ม · State ไฟส้ม: 3 วินาที)
- **Zone D:** เร่งเวลาจำลอง 1x/2x/5x · ส่งเหตุการณ์จำลอง (Event) · รีเซ็ต
- **[กฎ]** สถานะที่กำลังทำงานมีกรอบแสงกะพริบ (Active State Glowing Outline · ไม่กะพริบเกิน 3 ครั้ง/วินาที · PR-A16) เพื่อให้เห็นการกระโดดข้ามสถานะ
- **[แนวทาง]** แผงปุ่มจำลองเหตุการณ์ไม่คาดคิด (Event Injection) เช่น "กดปุ่มคนข้าม", "เซนเซอร์ตรวจพบรถฉุกเฉิน" ทดสอบว่าระบบเปลี่ยนสถานะถูกตามที่เขียน
- **DS gap:** Flowchart node/edge

### GP-07 Code Detective & Diagnostic Debugger (สืบสวนและแก้บั๊ก)
- **ตัวอย่างภารกิจ:** "หาจุดผิดพลาด 1 จุดที่ทำให้รถชน" (Level 2-3)
- **Layout [แนวทาง]:** จอเปรียบเทียบข้อผิดพลาด · Zone B = จำลอง + บันทึกข้อผิดพลาด (ตัวอย่าง รถวิ่งชนกำแพงที่พิกัด X=4 · "หุ่นยนต์เดินเกินมา 1 ก้าว!") · Zone C = โค้ดที่มีบั๊ก (คลิกบล็อกที่สงสัยเพื่อแก้)
- **Zone D:** ตรวจสอบทีละบรรทัด · ทดสอบโค้ดที่แก้แล้ว · ย้อนกลับ
- **[กฎ]** บั๊กไม่ถูกเฉลยตรง ๆ แสดงไอคอนคำถาม/อาการเตือนเมื่อรันถึงจุดนั้นเท่านั้น (Visual Bug Markers)
- **[แนวทาง]** แว่นขยายลากวางเหนือบล็อกเพื่อดูค่าตัวแปรจำลองหรือคำอธิบายการทำงานของบล็อก (Inspector Magnifier) · ตัวเปรียบเทียบโค้ดเดิม (มีบั๊ก) กับโค้ดใหม่หลังแก้ (Code Difference Preview) · ปรับตาม Edit Budget (แก้ได้ไม่เกิน N จุด · 03 G7)

### GP-08 Algorithmic Sandbox & Engineering Tycoon (สนามทดลองวิศวกรรมเปิด)
- **ตัวอย่างภารกิจ:** "สร้างเมืองพลังงานสะอาด" (Capstone · งบ $450/500)
- **Layout [แนวทาง]:** แดชบอร์ดวิศวกรรมเต็มจอ · Zone B = แผนผังเมือง + แดชบอร์ด (ตัวอย่าง แผงโซลาร์ · แบตเตอรี่ · กังหันลม · โรงพยาบาล · พลังงานรวม 120/100 kW) · Zone C = แผงควบคุมระบบรวม (แท็บ: ไฟถนน · น้ำเสีย · รถ · มีบล็อกจัดสรรพลังงานอัตโนมัติ)
- **Zone D:** ปรับสภาพอากาศ (แดด/ลม/ฝน) · รันระบบ 24 ชม. · ดูกราฟ
- **[แนวทาง]** แท็บสลับระบบย่อย (ไฟฟ้า · บำบัดน้ำ · ไฟทางเดิน) · มิเตอร์งบประมาณที่ใช้และกำลังไฟคงเหลือแบบ real-time (Resource & Cost Meter) · แผงทดสอบสภาพแวดล้อม (แดดออก · ลมสงบ · ฝนตกหนัก · กลางคืน) เพื่อทดสอบเสถียรภาพของระบบที่เด็กสร้าง (Environmental Stress Testing)
- **หมายเหตุ:** เป็น capstone ยังไม่มีเกมรองรับ (`game.md` §3) · ใช้ "ปลายเปิด" มากที่สุดในชุด
