# รายการแก้ requirement ตามชุด pattern

ยังไม่แก้อะไร · เมื่อผู้ใช้ยืนยัน session หลักแก้ตามลำดับท้ายไฟล์ · ทุกข้อทำตามกฎเปลี่ยน requirement (CLAUDE.md): แก้ `requirements.md` → อัปเดตวันที่ 3 จุด → สถานะกลับเป็น `draft` → เพิ่มรายการบนสุดของ CHANGELOG → ส่ง `ruler` ตรวจ

## 5. ลำดับทำงานเมื่อผู้ใช้ยืนยัน

1. ผู้ใช้ยืนยันรายการนี้ (หรือบอกข้อที่ไม่เอา)
2. แก้ `modules/quiz/requirements.md` (Q-A ถึง Q-G) และ `modules/game-library/requirements.md` (G-A ถึง G-D)
3. อัปเดตวัน 3 จุดของทุกไฟล์ที่แก้ (ไฟล์ · `INDEX.md` ของ module · แถวและหัว `INDEX.md` ของโปรเจกต์) · สถานะ quiz → `draft` ทั้งสองที่ (หัว `INDEX.md` module + คอลัมน์สถานะใน `INDEX.md` โปรเจกต์)
4. เพิ่ม CHANGELOG · เพิ่ม OQ (Q-L, Q-M, G-F)
5. ส่ง `ruler` ตรวจ quiz R3/R4/R9/R10 + Q-I, Q-J (+ ความสัมพันธ์กับ R7 ผ่านด่าน, R8, ST-14) และ game-library R6/R10/R11 · ส่งแบบ foreground เพราะอาจต้องถามผู้ใช้
6. ผู้ใช้ยืนยันผล ruler → quiz กลับเป็น `approved`
7. ค่อยให้ `crayon` แก้ D3, D4 (ต้องถามเรื่อง canvas ก่อน และ C1 เป็น shared ต้องขออนุมัติก่อน publish) · แจ้ง DS gap ก่อน
8. ถามผู้ใช้เรื่อง DS gap ด้วย AskUserQuestion แล้วเติม DS ผ่าน session หลัก

## 6. สิ่งที่ผมไม่ได้ตรวจ

- ไม่ได้เปิดอ่าน `oq.md` (เลข OQ ถัดไป), `context.md`, `brand.md`, `CHANGELOG.md` ในรอบนี้ · ข้อความ "เดิม" ในตารางอ้างจาก `requirements.md` ที่อ่านไว้แล้วในเซสชัน (ไฟล์ quiz ฉบับ 2026-11-06 · game-library ฉบับ 2026-11-06)
- ยังไม่ได้ตรวจว่าการแก้ R3 ขัดกับ ST-13/ST-14 หรือ edge case อื่นใน feasibility เดิม (ให้ ruler ตรวจ)
